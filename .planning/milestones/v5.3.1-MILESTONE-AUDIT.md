**Notes:**

1. **KGATE-05 threshold revision** — original target ≥35% on rendered prompt revised to ≥20% on rendered + ≥35% on knowledge block during Phase 86-03 (commit `46caba53`). 2. **BPASS-02 pointer-form adaptation** — Phase 87-02 dropped the `(ver *Reglas Zero*)` pointer suffixes across discovery-tagged sections after a KGATE-05 checkpoint halt (combined deflection + elevator pushed rendered prompt over the 18,916-char threshold). 3. **QREG-01 AVAT-03 alignment** — AVAT-03 test previously asserted member-only tokens ("efectivo", "Ver membresia") in a lead-state rendered prompt. Post-gating those tokens correctly no longer reach leads. Aligned assertion now covers both KGATE-02 (lead exclusion) and KGATE-03 (non-lead inclusion). Inline anti-revert block comment anchor placed in `knowledge-gating.test.ts` (commit `ec25a6f2`). Documented in 86-02 and 88-02 SUMMARYs. Legitimate alignment, not a gap.

## Integration / Cross-Phase Wiring

The integration checker subagent was not available in this audit environment; cross-phase wiring was verified from the three VERIFICATION.md reports and the milestone-exit SUMMARY (88-02) which explicitly declares dependency provides/requires edges. Findings:

### Phase 86 → Phase 87 wiring (tagging infrastructure reuse)

Phase 87 correctly consumed Phase 86's `SectionTag` + `SECTIONS` module-level structure. Evidence:

- `SECTIONS` grew from 14 → 16 entries; `Metodo (elevator)` at index 1 tagged `["discovery"]`, `Metodo (detalle)` at index 2 tagged `[]` (full-only). Confirmed by 87-VERIFICATION truths #3 and #4.
- Boarding Pass canonical definition lives in `ZERO_RULES` (a discovery-tagged section), so it flows through the Phase 86 gate to leads unchanged — `primer mes en El Templo` appears exactly once in both full and lead outputs.
- METHOD-03 deflection rule was placed in `system-prompt.ts` universal framing (not a `SECTIONS` entry) — a deliberate design choice that prevents the rule from being accidentally gated out. Verified by Block C tests across all 5 ClientStates.

### Phase 86+87 → Phase 88 wiring (test infrastructure coverage)

Phase 88 test infrastructure correctly covers the combined 86+87 behavior. Evidence:

- `knowledge-gating.test.ts` carries per-state locks from 86-03, BP/method/deflection locks from 87-03 (Blocks A/B/C, 20 tests), and Phase 88 boundary locks (KGATE-04 null/undefined/no-arg + unknown-state fallthrough, +2 tests).
- `prompt-size.test.ts` enforces the dual KGATE-05 threshold (20% rendered, 35% knowledge block) which jointly guards Phase 86 gating effectiveness and Phase 87 content additions (elevator + deflection).
- `rendered-prompt-snapshot.test.ts` (byte-equal against a committed fixture) provides a tripwire for unintentional drift from the combined 86+87 end-state.
- Full-suite contract: 534/534 after 87, 537/537 after 88 (+3 from Phase 88 additions). Zero changes to `el-templo-bot/src/` in Phase 88 (test-only phase invariant).

### E2E flows

No E2E flows broken. The `system-prompt.ts` call site (`getBusinessKnowledge(options?.clientState)`) is a single wiring point; existing conversation-flow tests pass (AVAT-03 aligned, not broken). Lead discovery path, non-lead full-knowledge path, null/undefined backward-compat path, and unknown-state fallthrough path are all exercised by the test suite.

### Known cross-phase deviations (all documented, none blocking)

1. **KGATE-05 threshold revision** (Phase 86-03) — REQUIREMENTS.md + prompt-size.test.ts + 88-02 SUMMARY all in agreement on the 20%/35% dual threshold.
2. **BP pointer-suffix drop** (Phase 87-02) — name-preservation locks compensate; 87-03 test block adapted accordingly.
3. **AVAT-03 assertion alignment** (Phase 86-02) — documented in 86-02 SUMMARY, anchored by inline block comment in knowledge-gating.test.ts (88-02).

## Tech Debt

1. **KGATE-05 headroom <100 chars (watch-item).** Current PB1.E1A lead render is 58 chars under the 18,916 threshold. `prompt-size.test.ts` already fails loudly on breach; no hard minimum-margin assertion was added (a minimum-margin test would block justified future content additions). The next content addition to any discovery-tagged section (QUE_ES, PLANES_FLEX, ZERO_RULES, SCHEDULES, TRIAL_FLOW, SALES_TECHNIQUES, OBJECTIONS_SALES, METODO_ELEVATOR, GOLDEN_RULES) **must audit the KGATE-05 budget before merging**. Soft-warn is captured in 88-02 SUMMARY.
2. **Single-path snapshot coverage.** `rendered-prompt-snapshot.test.ts` snapshots only the PB1.E1A lead path. Per-state snapshots were deliberately deferred per 88-CONTEXT.md (churn vs. value tradeoff). Non-lead prompts are covered by behavioral string assertions only.
3. **Boarding Pass pointer-form fragility.** The `(ver *Reglas Zero*)` suffixes were dropped under Phase 87-02 budget pressure. BP name preservation is locked, but future authors editing discovery sections must remember the canonical-definition-only invariant — the rule lives in phase history (87-03 SUMMARY) and an inline Block A assertion, not a doc comment in knowledge.ts itself.
