<objective>
Add LLM-emitted profile tag detection to the PB1 discovery flow. Mica is instructed (via the
PB1 promptSection edited in plan 83-01 and reinforced here) to append a structured tag
`<profile>cero_absoluto|gym_crossover|intermedio|retorna</profile>` at the end of her reply
whenever she detects the lead's avatar from their answers. The webhook handler parses that
tag, persists the avatar into the Redis playbook session state alongside `{activePlaybook,
currentStage}`, strips the tag from the outbound text, and passes the known avatar back into
`getSystemPrompt` on subsequent turns so Mica knows not to re-detect.

Strategy decision (committed): **Hybrid LLM + structured tag** (Option C from planning brief).
Justification:

- Pure rule-based detection (Option A) cannot handle Spanish nuance like "vengo de crossfit"
  (→ gym_crossover) or "arranqué hace años pero paré" (→ retorna).
- Pure tool-call detection (Option B) requires adding a new tool to BOT_TOOLS, extending the
  existing tool loop, and burns an extra model turn — overkill for a single enum write.
- Hybrid (C) is testable end-to-end (the parser is a pure function), reuses the existing
  model turn with no extra API calls, and the Redis write is deterministic. If the model
  forgets the tag, detection is skipped silently (no false positives) and the next turn
  re-attempts. If the tag is malformed, the parser returns null (also silently skipped).

Purpose: Without a persisted profile, Mica cannot satisfy DISC-05 ("store detected profile
in the Redis session") and phase 85 AVAT-02 ("when profile is already set, skip qualifying
questions") has nothing to read. This plan lays the Redis + parser foundation; phase 85
consumes it for per-avatar tone.

Output: A new `profile-tag.ts` module with a pure parser + strip helper, an `avatar` field
on `PlaybookSessionState`, webhook handler wiring (read → extract → persist → strip → pass
forward), and a 10+ test suite covering tag detection edge cases.
</objective>

Step 1 — Create `el-templo-bot/src/playbooks/profile-tag.ts`:

Pure module (no IO, no logger, no Date). Exports:

```ts
import type { AvatarProfile } from "./types.js";

/**
 * Valid avatar values that Mica is allowed to emit inside a <profile> tag.
 * Must match AvatarProfile exactly. A test asserts parity.
 */
const VALID_AVATARS: readonly AvatarProfile[] = [
  "cero_absoluto",
  "gym_crossover",
  "intermedio",
  "retorna",
];

/**
 * Regex that matches a <profile>VALUE</profile> tag anywhere in the text.
 * Captures the value in group 1. Case-insensitive on the tag name; the
 * captured VALUE is lowercased before validation so models that emit
 * `<Profile>Intermedio</Profile>` still parse cleanly.
 */
export const PROFILE_TAG_REGEX = /<profile>\s*([a-z_]+)\s*<\/profile>/i;

/**
 * Extract the FIRST valid avatar value from a <profile>...</profile> tag
 * in the assistant text. Returns null when no tag is present, the tag is
 * malformed, or the value is not a recognized avatar.
 *
 * Pure: no IO, no side effects, idempotent.
 */
export function extractProfileTag(text: string): AvatarProfile | null {
  const match = text.match(PROFILE_TAG_REGEX);
  if (!match || !match[1]) return null;
  const candidate = match[1].toLowerCase();
  return (VALID_AVATARS as readonly string[]).includes(candidate)
    ? (candidate as AvatarProfile)
    : null;
}

/**
 * Remove ALL <profile>...</profile> tags from the text (including any
 * trailing/leading whitespace introduced by the tag on its own line).
 * Returns the cleaned text ready to send to the user.
 *
 * Pure: does not mutate inputs.
 */
export function stripProfileTag(text: string): string {
  // Global variant of the regex for removal
  const globalRegex = /<profile>\s*[a-z_]+\s*<\/profile>/gi;
  return text
    .replace(globalRegex, "")
    .replace(/[ \t]+\n/g, "\n")
    .trim();
}
```

Reasoning for two separate functions: `extractProfileTag` is read-only and returns a typed
value for the handler to persist; `stripProfileTag` mutates (returns a new) the outbound
text. Keeping them separate makes each trivially unit-testable.
