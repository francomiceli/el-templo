import { describe, it, expect } from "vitest";
import { getSystemPrompt } from "../src/ai/system-prompt.js";
import {
  advanceStageIfComplete,
  type AdvanceSignals,

Structure the file with one `describe` per DISC requirement (7 describes). Each `it` block
MUST contain an explanatory comment noting the DISC ID and what exact behavior is being
validated.

### describe("DISC-01 — first message is warm intro + first qualifying question")

1. **"PB1.E1A promptSection contains warm intro and first discovery question"**
   - Call `getSystemPrompt({clientState: "lead", activePlaybook: "PB1", currentStage: "PB1.E1A"})`
   - Assert returned string contains: `"¡Hola"` OR `"Hola"`, `"¿ya entrenaste calistenia"` or `"primera vez"`
   - Assert returned string does NOT contain: `"¿en qué puedo ayudarte"`

2. **"PB1.E1B promptSection contains alternative warm intro"**
   - currentStage="PB1.E1B"
   - Assert contains `"arrancás de cero"` or `"tenés experiencia en calistenia"`

3. **"Neither E1A nor E1B contain the generic 'en qué puedo ayudarte' opener"**
   - Both stages rendered, neither contains the blacklisted phrase.

### describe("DISC-02 — max 3 qualifying questions, woven not quiz-style")

4. **"PB1 stages contain the 2-3 adaptive question rule"**
   - Render the PB1.E1A prompt, assert contains substring `"2-3 preguntas"` (from the
     "Idealmente 2-3 preguntas" phrasing).

5. **"PB1.E3 is the LAST discovery question and advances to E4 regardless of signal richness"**
   - Call `advanceStageIfComplete({playbookId: "PB1", stageId: "PB1.E3"}, {discoveryAnswered: true})`
   - Assert result === `"PB1.E4"`
   - Reasoning: after E3, discovery always exits — the 2-3 cap is enforced.

6. **"The full E1→E2→E3 sequence is at most 3 advancement calls"**
   - Simulate: E1A → E2A → E3 → E4 using `advanceStageIfComplete` three times.
   - Assert each step returns the expected next stage.
   - Assert you cannot advance PAST E4 into a fourth discovery question (there is no E4'
     discovery stage).

### describe("DISC-03 — direct question interrupt is handled on same turn")

7. **"PB1.E1A promptSection documents the defer rule"**
   - Render E1A, assert contains `"Si el lead te hace una pregunta directa"` or similar
     phrase from plan 83-01's required content (grep for `"pregunta directa"`).

8. **"advance.ts holds the stage when directQuestionAsked is true"**
   - Call with signals `{discoveryAnswered: true, directQuestionAsked: true}` at PB1.E1A.
   - Assert result === `null` (no advance — the defer kept the stage).

9. **"advance.ts normal path still works when directQuestionAsked is false"**
   - Same stage, signals `{discoveryAnswered: true, directQuestionAsked: false}`.
   - Assert result === `"PB1.E2A"` (default when no avatar detected).

### describe("DISC-04 — one targeted recommendation, not a menu")

10. **"PB1.E4 promptSection forbids plan recommendations and prices"**
    - Render `getSystemPrompt({..., currentStage: "PB1.E4"})`.
    - Assert contains `"NO recomend"` or `"REGLA FUERTE"` (exact substring from plan 83-01's required content).
    - Assert contains `"clase de prueba"` and `"gratis"`.

11. **"PB1.E4 promptSection does NOT list multiple plans as options"**
    - Render E4 prompt, assert does NOT contain any of: `"Foundation"`, `"Performance"`, `"Flex"`, `"$"`.

### describe("DISC-05 — profile detected and stored in Redis session")

12. **"Profile tag parser recognizes all 4 avatars"**
    - `extractProfileTag("<profile>cero_absoluto</profile>")` === `"cero_absoluto"`
    - Same for the other 3 avatars.

13. **"System prompt instructs Mica to emit <profile> tag only during PB1 + no-prior-avatar"**
    - Render with `{activePlaybook: "PB1", currentStage: "PB1.E1A", currentAvatar: null}`.
    - Assert contains `"<profile>"` instruction string (from the "Detección de perfil"
      section added in plan 83-02).
    - Render same options but with `currentAvatar: "intermedio"`.
    - Assert does NOT contain the `"Detección de perfil"` instruction section
      (Mica should NOT re-detect an already-known avatar).

14. **"Profile-aware branching: intermedio at E1A advances to E2B"**
    - `advanceStageIfComplete({playbookId: "PB1", stageId: "PB1.E1A"}, {discoveryAnswered: true, detectedAvatar: "intermedio"})`
    - Assert result === `"PB1.E2B"`.

### describe("DISC-06 — soft trial offer close")

15. **"PB1.E4 closes with free trial CTA, not hard sell"**
    - Render E4 prompt, assert contains `"clase de prueba"` or `"probar"` or `"gratis"`.
    - Assert does NOT contain `"urgencia"`, `"promoción"` (except inside the TEAM-CORR
      corrections wording — be lenient here by grepping for `"precio"` and asserting it's
      either absent OR accompanied by the "Te paso los detalles después de la clase" re-anchor).

16. **"PB1.E5 continues the agenda tone (no hard sell)"**
    - Render E5 prompt, assert contains `"agendo"` or `"ropa cómoda"`.
    - Assert does NOT contain `"pagar"`, `"precio"`, `"plan"` words (E5 is scheduling, not
      selling — the next turn inside PB2 handles selling).

### describe("DISC-07 — insistence on direct answers defers profiling gracefully")

17. **"PB1 stages document the insistence-defer rule"**
    - Render E1A prompt, assert contains a phrase like `"insist"` or `"NO empujes otra pregunta"`.

18. **"advance.ts holds stage when userInsistedDirect is true"**
    - Call with signals `{discoveryAnswered: true, userInsistedDirect: true}` at PB1.E1A.
    - Assert result === `null`.

19. **"advance.ts normal flow resumes when userInsistedDirect is false on a later turn"**
    - Call with `{discoveryAnswered: true, userInsistedDirect: false}` at PB1.E1A (simulating the lead answering normally on the next turn).
    - Assert result === `"PB1.E2A"` (or `"PB1.E2B"` if avatar set).
