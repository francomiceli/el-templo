**Recipe shape: SQL round-trip (CONTEXT.md D-12 Option 2 — recommended).**

Rationale: same source of truth as production; eliminates JS↔MySQL day-of-week numbering mismatch risk; no new test helper needed. Uses MySQL `DATE_ADD(CURDATE(), INTERVAL (<dayOfWeek> - DAYOFWEEK(CURDATE()) + 8) % 7 DAY)` mirroring `tools.ts:329` verbatim.

**Apply at 2 test bodies** (after D-13 patch lands the `booking_status` column rename at these same INSERT statements):

1. **`:153-175`** test `check_schedule > accounts for bookings in spots remaining` — currently seeds `today = new Date().toISOString().slice(0, 10)` at the top of the loop and inserts 18 bookings with `booking_date = today`. Replace `today` with `nextOccurrence`, derived via a one-shot pool query immediately before the `for` loop:

   `const [dateRows] = await pool.execute(\`SELECT DATE_ADD(CURDATE(), INTERVAL (? - DAYOFWEEK(CURDATE()) + 8) % 7 DAY) AS d\`, [1])`where the parameter`1`is the test's`dayOfWeek: 1`(Monday). Cast`dateRows[0].d`to ISO string with`.toISOString().slice(0, 10)`(MySQL returns a Date object). Bind the result as the`booking_date` placeholder in the existing INSERT.

2. **`:178-200`** test `check_schedule > shows 'lleno' when at capacity` — same shape, 20 bookings instead of 18, asserts `result.toContain("lleno")`. Same `nextOccurrence` derivation, same `dayOfWeek: 1` parameter.

**Pattern reuse:** both tests get the same 3-line block (declare `dateRows`, derive `nextOccurrence`, pass to INSERT). No new helper. Inline derivation keeps the test self-contained and pins the source-of-truth to the exact same SQL expression production uses.

**Why NOT a new `nextOccurrenceISO()` helper (D-12 Option 1 — rejected):** JS↔MySQL day-of-week numbering differs (MySQL `DAYOFWEEK` is 1-Sun..7-Sat; JS `getDay()` is 0-Sun..6-Sat); a JS helper would need careful manual conversion that drifts if the production formula changes. SQL round-trip stays byte-equivalent to prod.

**Interaction with D-13 patch:** The patch already renames the column at these INSERT statements (`status` → `booking_status`). The D-12 edit only changes the `booking_date` value passed to those INSERTs — the column-rename hunks from the patch stay intact.
