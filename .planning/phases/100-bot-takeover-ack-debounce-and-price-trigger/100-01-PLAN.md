<objective>
Implement DBNC-01 — replace the fixed 3-second `setTimeout(DEBOUNCE_DELAY_MS)` at `handler.ts:465` with a trailing-debounce poll-and-extend loop that aggregates multi-message bursts while keeping single-message latency low. Add two env-overridable constants (`DEBOUNCE_QUIET_WINDOW_MS=7000` default, `DEBOUNCE_HARD_CAP_MS=30000` default), record an inbound timestamp per phone in Redis, and run the loop INSIDE the existing Phase 93 SETNX-acquired token (no parallel handler path). Cover the deterministic loop control with unit tests and the end-to-end timing with an integration test.

Purpose: Live-test finding — fixed 3s window punishes single-message senders (full 3s wait for nothing) and is too aggressive for multi-message senders (3s isn't enough for a slow typer). Trailing debounce solves both with one mechanism, bounded by a cap so a non-stop typer cannot stall the bot forever.

Output: Modified `handler.ts` + `session.ts` + `.env.example` with the new loop; one unit test file under `el-templo-bot/test/`; one integration test file under `el-templo-api/test/whatsapp/`.
</objective>
