    **1. Create subscription-plans.ts schema** (follow aura-transactions.ts pattern for enums):
    - Table `subscription_plans` with fields: id (int PK auto), name (varchar 150 notNull), description (text nullable), planTier (mysqlEnum 'plan_tier' ['flex','foundation','performance','other'] notNull), bookingMode (mysqlEnum 'booking_mode' ['fixed','flexible'] notNull), priceRegular (int notNull, whole pesos), priceZero (int notNull, boarding pass / first month price), priceCreditCard (int nullable, for Phase 49), durationDays (int notNull), classesPerWeek (int nullable, null = unlimited), multiBranch (boolean default false notNull), isTrial (boolean default false notNull), isGroup (boolean default false notNull), groupMaxMembers (int nullable), isActive (boolean default true notNull), createdAt (timestamp defaultNow notNull), updatedAt (timestamp defaultNow onUpdateNow notNull).
    - Export table as `subscriptionPlans` and relations.
    - Use separate mysqlEnum instances (same pattern as AURA — separate enum per table to avoid MySQL name collisions).

    **2. Create subscriptions.ts schema**:
    - Table `subscriptions` with fields: id (int PK auto), userId (int notNull FK->users.id), planId (int notNull FK->subscription_plans.id), branchId (int notNull FK->branches.id), status (mysqlEnum 'subscription_status' ['active','paused','cancelled','expired'] notNull default 'active'), startDate (date mode 'string' notNull), endDate (date mode 'string' nullable), pricePaid (int notNull), priceTypeApplied (mysqlEnum 'price_type_applied' ['regular','zero','credit_card'] notNull), auraDiscount (int nullable, AURA amount spent for discount), auraDiscountPercent (int nullable, discount percentage applied), boardingPassUsed (boolean default false notNull), priceOverrideAmount (int nullable), priceOverrideReason (text nullable), pausedAt (timestamp nullable), resumedAt (timestamp nullable), cancelledAt (timestamp nullable), notes (text nullable), createdAt (timestamp defaultNow notNull), updatedAt (timestamp defaultNow onUpdateNow notNull).
    - Add unique partial index concept: enforce one active/paused subscription per user. Since MySQL doesn't support partial unique indexes, add a comment noting this is enforced at the service layer. Do NOT add a unique constraint on userId alone (a member can have many historical subscriptions).
    - Export table as `subscriptions` and relations (belongs to user, plan, branch).

    **3. Modify users.ts**: Add `boardingPassUsed` (boolean default false notNull) column to the users table.

    **4. Update schema/index.ts**: Add barrel exports for subscription-plans and subscriptions.

    **5. Write migration 0032_subscriptions.sql** manually (same pattern as 0030 and 0031 — Drizzle interactive prompts are unreliable):
    - CREATE TABLE subscription_plans with all columns and enums
    - CREATE TABLE subscriptions with all columns, enums, and foreign keys (userId->users.id, planId->subscription_plans.id, branchId->branches.id)
    - Add index on subscriptions.user_id for fast member lookup
    - Add index on subscriptions.plan_id for plan usage lookup
    - ALTER TABLE users ADD COLUMN boarding_pass_used BOOLEAN NOT NULL DEFAULT FALSE

    **6. Create types.ts** in modules/subscriptions/:
    - Plan types: PlanListItem, PlanDetail, CreatePlanInput, UpdatePlanInput
    - Subscription types: SubscriptionDetail (includes plan name, branch name, status, dates, pricing breakdown), SubscriptionHistoryItem, AssignPlanInput (planId, branchId, startDate, priceTypeApplied, auraSpend optional, priceOverrideAmount optional, priceOverrideReason optional, boardingPass boolean, notes optional)
    - Pricing types: PricingPreview (basePrice, discountType, discountAmount, finalPrice, auraToSpend, auraBalance)
    - AURA discount tiers constant: AURA_DISCOUNT_TIERS = [{spend: 500, percent: 5}, {spend: 1000, percent: 10}, {spend: 2000, percent: 20}, {spend: 5000, percent: 30}]
    - Export SubscriptionStatus, PlanTier, BookingMode, PriceType as TypeScript union types matching the MySQL enums.

    **7. Create schemas.ts** with Fastify JSON validation schemas for all routes (follow members/schemas.ts pattern).

    **8. Create service.ts** — SubscriptionService class with constructor DI (db, log, auraService):
    - **Plans CRUD**: listPlans (with optional isActive filter), getPlanById, createPlan, updatePlan, deactivatePlan (set isActive=false). Simple Drizzle queries.
    - **Subscription queries**: getMemberSubscription (get active/paused sub for userId, auto-expire if endDate < today), getMemberSubscriptionHistory (all subs for userId, most recent first), getSubscriptionById.
    - **Auto-expire logic**: In getMemberSubscription and getMemberSubscriptionHistory, check if any active subscription has endDate < today. If so, UPDATE status='expired' before returning. This is the "expire on read" pattern per user decision.
    - **Assign plan**: assignPlan(input: AssignPlanInput, adminId: number) — validates: member exists, plan exists and isActive, no existing active/paused sub for member (throw ConflictError). Calculates endDate = startDate + plan.durationDays. If boardingPass: check user.boardingPassUsed is false (throw if already used), use priceZero, mark user.boardingPassUsed=true. If auraSpend: validate against AURA_DISCOUNT_TIERS, call auraService.spend() with sourceType 'subscription_discount', referenceType 'subscription'. If priceOverride: use override amount, require reason. Otherwise use plan's price for the selected priceType. Insert subscription row. Return SubscriptionDetail.
    - **Pause**: pauseSubscription(subscriptionId) — validate status is 'active', set status='paused', pausedAt=now. Return updated sub.
    - **Resume**: resumeSubscription(subscriptionId) — validate status is 'paused', calculate paused duration (now - pausedAt), extend endDate by that duration, set status='active', resumedAt=now, clear pausedAt. Return updated sub.
    - **Cancel**: cancelSubscription(subscriptionId, notes?) — validate status is 'active' or 'paused', set status='cancelled', cancelledAt=now, add notes. Return updated sub.
    - **Pricing preview**: getPricingPreview(planId, userId, priceType, auraSpendTier?) — returns PricingPreview showing what the member would pay. Checks boarding pass eligibility. Shows AURA balance and discount tier options. Does NOT modify data.

    **9. Create routes.ts** — subscriptionRoutes Fastify plugin with admin role guard (same pattern as memberRoutes):
    - Plans endpoints (prefix /plans):
      - GET /plans — list plans (optional ?isActive filter)
      - GET /plans/:planId — get plan detail
      - POST /plans — create plan
      - PUT /plans/:planId — update plan
      - PATCH /plans/:planId/deactivate — deactivate plan
    - Subscription endpoints:
      - GET /members/:userId/subscription — get current active/paused subscription (auto-expire)
      - GET /members/:userId/subscription/history — get subscription history
      - POST /members/:userId/subscription/assign — assign plan to member
      - POST /members/:userId/subscription/pause — pause subscription
      - POST /members/:userId/subscription/resume — resume subscription
      - POST /members/:userId/subscription/cancel — cancel subscription
      - GET /members/:userId/subscription/pricing-preview — get pricing preview for plan assignment
    - All routes behind admin role guard (onRequest hook, same as members).

    **10. Create index.ts** barrel export: `export { subscriptionRoutes } from './routes'`

    **11. Register in app.ts**: Import subscriptionRoutes, register at prefix `/api/admin/subscriptions`.
