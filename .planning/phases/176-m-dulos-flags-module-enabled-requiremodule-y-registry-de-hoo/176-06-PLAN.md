`src/modules/shared/hooks.ts` debe exportar exactamente estos símbolos y estas formas:

- `interface HookCallCtx { tenantId: number; db: DbInstance; log: FastifyBaseLogger }`
  (`DbInstance = MySql2Database<typeof schema>`, igual que en `settings/service.ts`).

- `interface AppliedBenefit { module: ModuleName; benefit: string }`

- `type PricingCallSite = "assign" | "change-now" | "change-after-current" | "preview"`

- `interface PricingSupports { exclusiveBenefits: boolean; discounts: boolean }`
  `exclusiveBenefits`: el call site soporta un beneficio que reemplaza el precio y corta la cadena
  (boarding pass). `discounts`: el call site soporta descuentos porcentuales sobre el precio (AURA).
  Es así de granular porque los 4 call sites reales NO son simétricos: `changePlanNow` tiene boarding
  pass pero NO AURA, y `getPricingPreview` calcula AURA pero no tiene rama de precio de boarding pass.

- `interface PricingAdjustCtx {`
  `  callSite: PricingCallSite; userId: number; planId: number; planCategory: string;`
  `  priceType: PriceType;      // MUTABLE — el handler puede pisarlo (p.ej. a "zero")`
  `  basePrice: number;         // MUTABLE`
  `  price: number;             // MUTABLE — cada filter lo ajusta`
  `  priceLocked: "prorate" | "override" | null;  // el core ya fijó el precio por una regla core`
  `  commit: boolean;           // false = preview: calcular sin gastar ni marcar`
  `  supports: PricingSupports;`
  `  moduleInput: Record<string, unknown>;   // opaco: el core NO lo tipa ni le hace \`as\``
` moduleOutput: Record<string, unknown>; // el handler deja acá lo que el response necesita`
` applied: AppliedBenefit[]; // trazabilidad de qué benefit tocó el precio`
` exclusive: boolean; // true ⇒ la cadena corta`
` resolvePriceType: (t: PriceType) => Promise<PriceType>; // callback provisto por el core`
` basePriceFor: (t: PriceType) => number; // callback provisto por el core`
`}`
`PriceType`se importa con`import type`desde`../subscriptions/types` (import de tipo: no crea ciclo en runtime).

- `interface StreakMilestoneEvent { userId: number; milestone: number; streakDays: number }`

- `interface FilterMap { "pricing.adjust": (ctx: PricingAdjustCtx, hook: HookCallCtx) => Promise<void> }`
- `interface EventMap { "streak.milestone": (evt: StreakMilestoneEvent, hook: HookCallCtx) => Promise<void> }`

- `class HookRegistry` con:
  `setFilter<K extends keyof FilterMap>(module: ModuleName, key: K, handler: FilterMap[K]): void`
  `setEvent<K extends keyof EventMap>(module: ModuleName, key: K, handler: EventMap[K]): void`
  `runFilter<K extends keyof FilterMap>(key: K, hook: HookCallCtx, ctx: PricingAdjustCtx): Promise<void>`
  `emit<K extends keyof EventMap>(key: K, hook: HookCallCtx, evt: StreakMilestoneEvent): Promise<void>`
  `clear(): void` (solo para tests)
  `modulesFor<K>(key: K): ModuleName[]` (introspección: qué módulos tienen handler para ese hook)

- `export const hookRegistry = new HookRegistry();` — instancia de proceso.

<decisions_locked>

- **Almacenamiento idempotente:** `Map<hookKey, Map<ModuleName, handler>>`. Registrar dos veces el mismo
  par (módulo, hook) REEMPLAZA. Es deliberado: `createTestApp()` construye un app por archivo de test en el
  mismo proceso y un almacenamiento por array acumularía handlers y ejecutaría el `spend` de AURA dos veces.
- **Filtrado por módulo habilitado DENTRO de `runFilter`/`emit`** (no en el call site del core): el core no
  debe saber a qué módulo pertenece un handler. Se consulta `isModuleEnabled(hook.tenantId, module, hook.db)`
  con el MISMO resolver que usa el guard.
- **Semántica de errores (doc 04 §4.1), no negociable:**
  - `runFilter`: los errores **PROPAGAN**. Hoy `subscriptions/service.ts:1825` deja salir
    `InsufficientBalanceError` sin `catch` y el alta aborta. Un `try/catch` acá sería un bug de cobro
    (precio con descuento sin descontar el saldo).

    literalmente `streaks/service.ts:296-302`, incluido el `catch (err: unknown)`.
- **Orden de ejecución = orden de registro** en el composition root (doc 04 §4.4). Con un solo módulo por

- **Singleton de proceso:** `hookRegistry` se exporta desde `hooks.ts` y lo consumen `pricing.ts` y
  `StreakService` por import directo. Esto evita tocar los 17 call sites de `new SubscriptionService(...)`.
  El almacenamiento idempotente es lo que hace segura esa decisión.
