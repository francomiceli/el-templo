<objective>
Extend the member tree contract (`GET /api/tree-progress/me`) so each node carries a server-computed `state` (the 4 videogame-style states of D-01..D-04) and a `band` (kairos→spartan derived from dificultadLineal, D-08). All derivation happens server-side inside `buildMemberTree` — the client computes nothing (D-05 fase 127 pattern). The `reached` flag and the % ring formula DO NOT change (D-05): states are a separate layer.

Purpose: this is the contract source for the member-app refresh (R6). Plan 02 renders these fields verbatim. The states must be evidence-based (D-01) so "dominado" means something falsable.
Output: extended `TreeNode` interface + `treeNodeSchema` + integration tests proving the 4 states.
</objective>
