  <action>
    **Module scaffolding** — Follow training/progression module pattern:

    `journey/index.ts`:
    - Export manifest: `{ name: 'journey', label: 'Journey', icon: 'explore', basePath: '/journey', routes }`.
    - Export `registerModule(router: Router)` that adds routes under 'layout' parent.

    `journey/routes.ts`:
    - `/journey` → JourneySelection.vue (default: journey picker or redirect to duration if journey already active)
    - `/journey/overview/:type` → JourneyOverview.vue
    - `/journey/duration` → DurationPicker.vue
    - `/journey/session` → JourneySession.vue (placeholder for Plan 05)

    `journey/types.ts`:
    - Mirror the API types: JourneyType, JourneyDuration, JourneyProgress, ArchivedJourney, JourneyMetadata.
    - JourneySessionResponse type (session with blocks, similar to existing Session type).

    **Pinia store** (`journeyStore.ts`):
    - Composition API pattern (`defineStore('journey', () => { ... })`).
    - State: `activeJourney: ref<JourneyProgress | null>`, `selectedDuration: ref<JourneyDuration | null>`, `journeyMetadata: ref<JourneyMetadata[]>`, `currentSession: ref<JourneySessionResponse | null>`.
    - Actions: `fetchMetadata()`, `fetchActiveJourney()`, `selectJourney(type)`, `setDuration(duration)`, `fetchSession(week, day)`, `clearSession()`.
    - Computed: `hasActiveJourney`, `activeJourneyName`, `activeJourneyTier`.
    - Store receives data from API composable, does not make API calls directly (per established pattern).

    **API composable** (`useJourneyApi.ts`):
    - `getMetadata(): Promise<JourneyMetadata[]>` — GET /api/journeys/metadata
    - `getActiveJourney(): Promise<JourneyProgress | null>` — GET /api/journeys/active
    - `selectJourney(type: JourneyType): Promise<JourneyProgress>` — POST /api/journeys/select
    - `getArchivedJourneys(): Promise<ArchivedJourney[]>` — GET /api/journeys/archived
    - `getSession(week, day, duration): Promise<JourneySessionResponse | null>` — GET /api/journeys/session
    - `completeSession(data): Promise<{ success: boolean; progress: JourneyProgress }>` — POST /api/journeys/complete
    - Uses existing axios API instance from boot/axios.ts.
    - Returns `cleanup()` method per composable convention.

    **Register in modules.ts:**
    - Import `manifest as journeyManifest, registerModule as registerJourney` from journey module.
    - Add `journeyManifest` to modules array.
    - Call `registerJourney(router)` in boot function.

    Use `createLogger()` from `src/utils/logger.ts` per CLAUDE.md. No console.log.

  <action>
    **JourneySelection.vue** — The journey picker screen:
    - Loads journey metadata from store on mount.
    - If member has active journey, show "Tu Journey Actual" banner at top with journey name and option to change or continue to duration picker.
    - Groups 6 journeys in 3 rows by tier with tier label headers: "Principiante", "Intermedio", "Avanzado".
    - Each journey displayed as a visual card following `.docs/new-brand-visual/visual-brand.txt` brand guidelines:
      - Background: surface-sand (#E6E2D6) card on cream (#F5F2EB) page background.
      - Title in Cinzel serif font (existing @fontsource/cinzel).
      - Body text in Montserrat/system sans-serif.
      - Accent-terracotta (#C27A5D) for tier badges and CTA elements.
      - Accent-sage (#8A9A8A) for zone badges.
      - Minimal border-radius per brand guidelines (sharp corners feel premium).
      - Generous whitespace/padding.
    - Each card shows: journey name, zone badges, brief description snippet.
    - Tapping a card navigates to `/journey/overview/:type`.
    - No restrictions on picking advanced journeys (per CONTEXT.md — informational only).

    **JourneyOverview.vue** — Journey details before confirming:
    - Receives journey type from route params (`:type`).
    - Loads metadata for this journey from store.
    - Shows: journey name (large Cinzel heading), tier badge, full description, targeted body zones list, idealFor text, difficulty level indicator.
    - Two buttons at bottom:
      - "Elegir este Journey" (terracotta CTA) → calls store.selectJourney(type) → navigates to `/journey/duration`.
      - "Volver" (text button) → goes back to selection.
    - If member already has this journey active, CTA says "Continuar" instead and skips selectJourney call.

    **DurationPicker.vue** — Session duration selector:
    - Must have active journey (if not, redirect to /journey).
    - Shows journey name at top as context.
    - Three duration cards: 20 min, 40 min, 60 min.
      - 20 min card: "Sesion Rapida" — "Initium + Nucleus" — Shows encouraging message: "Si estas cansado o con poco tiempo, es mejor hacer una sesion mas corta" (per CONTEXT.md).
      - 40 min card: "Sesion Completa" — "Initium + Nucleus + Deuteros".
      - 60 min card: "Sesion Extendida" — "Initium + Nucleus + Deuteros + Athlos/Epikos".
    - Duration always neutral (no pre-selection, per CONTEXT.md).
    - Selecting a duration: stores in journeyStore → navigates to `/journey/session`.
    - Visual style consistent with brand: cream background, sand cards, terracotta accents.

    All pages use `createLogger()` per CLAUDE.md.
    UI text in Spanish per project convention.
