    Create `journey-pipeline.ts` — a modified pipeline orchestrator for journey sessions:

    1. **Journey Route Resolution (replaces Stage 1):**
       - Import JOURNEY_ROUTE_MAP from journeys/constants.
       - Select route deterministically: use a hash of (week, day, blockRole) modulo allowedRoutes.length. Use a simple string hash function (e.g., sum of char codes) for determinism.
       - This ensures route variety across days and blocks while remaining reproducible.
       - Add JOURNEY_ROUTE_SELECTED trace event.

    2. **SPOM Rule Fallback (modifies Stage 2):**
       - After selecting route, attempt normal `resolveSpom(ctx, spomService)`.
       - If SPOM rule is missing for the journey route at current week, implement fallback:
         a. Try other weeks for the same route (nearest week first).
         b. If no SPOM rule exists for this route at any week, use a default intensity (50%) and default pattern.
       - Add JOURNEY_SPOM_FALLBACK trace event when fallback is used.

    3. **Stages 3-5 (unchanged):** Call deriveBudget, deriveContraction, selectFormat as normal.

    4. **Stage 6 — Disable cross-route for journey sessions:**
       - Modify `selectExercises` to accept an optional `disableCrossRoute` parameter (or a `journeyRoutes` parameter).
       - When `disableCrossRoute` is true, skip `queryCrossRouteExercises` and select all exercises from the journey's route pool.
       - This ensures 100% zone bias per CONTEXT.md locked decision.
       - If modifying selectExercises would be too invasive, create a wrapper in journey-pipeline.ts that calls selectExercises with modified context (set pattern2 to the block route itself, which effectively makes cross-route select from same zone).

    5. **Stage 7 (unchanged):** Call generatePrescriptions as normal.

    6. **Journey Initium:**
       - Modify `runInitiumPipeline` to accept an optional `journeyRoutes: string[]` parameter.
       - When provided, filter Initium exercises to only include mobility exercises related to the journey's routes (use ROUTE_TO_MOBILITY_ROUTES to find relevant mobility areas).
       - This ensures zone-specific warm-up per CONTEXT.md locked decision.
       - If no zone-specific mobility exercises exist, fall back to generic Initium selection.

    The function signature:
    ```typescript
    export async function runJourneyBlockPipeline(
      initialContext: BlockContext,
      spomService: SpomService,
      db: MySql2Database<typeof schema>,
      journeyType: JourneyType,
      options?: BlockPipelineOptions,
    ): Promise<BlockPlan>
    ```

    IMPORTANT: Do NOT duplicate pipeline stages. Import and reuse resolveSpom, deriveBudget, deriveContraction, selectFormat, selectExercises, generatePrescriptions directly. Only replace Stage 1 and add guard logic for Stages 2 and 6.
