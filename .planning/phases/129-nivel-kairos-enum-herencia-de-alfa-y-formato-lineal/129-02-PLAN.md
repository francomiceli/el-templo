<objective>
Make a session generated for `memberLevel='kairos'` inherit Alfa (effectiveLevel='alfa', Alfa exercises at the lowest difficulty rung), force a linear sets-by-reps format on every block, and limit every block — INITIUM included — to exactly 2 exercises. All of this is gated strictly behind `memberLevel === 'kairos'` so existing alfa/delta/sigma/omega/spartan generation is byte-for-byte unchanged.

Purpose: KAIROS-02 (inherit Alfa difficulty=1) and KAIROS-03 (linear + 2/block) are the behavioral payload of the phase. The brownfield invariant D-07 is load-bearing: a regression test must prove non-kairos generation did not move.

Output: A small `isKairos` gate helper, three pipeline injection points (budget/format/exercise stages) plus the INITIUM pipeline, and an integration test file proving both the kairos behavior and the non-kairos regression.
</objective>

INJECTION POINT A — block size 2 incl INITIUM (D-05):

- Non-INITIUM blocks: stage-3-budget.ts getExerciseCountBounds(role, ruleMin, ruleMax). Today INITIUM_EXERCISE_COUNT=4 (this constant only caps non-INITIUM's `role==='INITIUM'` branch which never runs here — non-INITIUM blocks go through the standard pipeline; INITIUM has its OWN pipeline). For non-INITIUM kairos blocks, force min=max=2.
- INITIUM block: initium-pipeline.ts uses its OWN constant `INITIUM_EXERCISE_COUNT = 4` and selectWithVariety(pool, INITIUM_EXERCISE_COUNT, offset). For kairos, force the INITIUM selection count to 2.
  NOTE: stage-3 getExerciseCountBounds does NOT currently receive memberLevel — pass ctx.memberLevel into it (or read ctx in deriveBudget) to gate.

INJECTION POINT B — linear format only (D-04):

- stage-5-format.ts selectFormat(ctx, db, excludeFormatNames). Today it calls selectFormatWithFallback over the compatibility matrix. For kairos, BEFORE the ladder, look up the canonical linear format by name from the `formats` table and return it directly (skip the matrix). This applies to non-INITIUM blocks.
- INITIUM format: initium-pipeline.ts selectInitiumFormat picks an interval-style warmup format. For kairos, also force the linear format by name (so the INITIUM block is sets-by-reps too).
  LINEAR FORMAT NAME: the `formats` table (seeded from "[Planificaciones] - Base de Datos - Formatos.csv") contains "Singlet" and "For Quality" (both render as sets-by-reps via getDefaultFormatParams handlers `singlet` / `for_quality`). "Straight Sets" is referenced in DEFAULT_FORMATS but is NOT in the seed CSV — do NOT assume it exists. Use "Singlet" as the forced linear format (purest sets-by-reps, no time domain); query it by name and assert it exists, falling back to "For Quality" if "Singlet" is absent. Centralize the chosen name in utils/kairos.ts.

INJECTION POINT C — Alfa exercises at difficulty=1 (D-03):

- stage-6-exercises.ts selectExercises(ctx, db). Today it computes allowedLevels = getAllowedLevels(ctx.levelGroup) -> ['alfa','delta'] for alfa_delta, and min/maxDificultadLineal from getLinearDifficultyTarget(memberLevel, intensity, bucket).
- For kairos: override allowedLevels = ['alfa'] (Alfa only) and force minDificultadLineal = maxDificultadLineal = 1 (the lowest linear rung = "el escalon mas facil"), targetLevel='alfa'. This bypasses the Nivel Superior / high-intensity shift logic for kairos.
  DISCRETION (D-03): "Alfa difficulty=1" maps to dificultadLineal=1 here because the candidate query (exercise-fallback.ts queryExercises) filters on `dificultad_lineal`, not the separate `difficulty` (1-3 bucket) column. If the curated Alfa set has no dificultadLineal=1 rows for a route, the existing fallback ladder will widen gracefully — that is acceptable (content gaps are a profe/future concern, not this phase). Document the dificultadLineal=1 choice in a comment.
