# Phase 142 — UI Design Contract

> Visual and interaction contract for the **"Configuración de Caja"** admin page (MIG-01, D-06).
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Scope note:** This is a deliberately MINIMAL surface — today exactly ONE field
> (the pending-overdue threshold in days). The spec is kept proportionate: it does NOT
> invent extra fields, sections, or controls. It is "la casa" (the house) for future
> module knobs, but it ships as a single-field form. shadcn is **not applicable** —
> this is a Quasar + Vue 3 admin app, so the contract is expressed against the existing
> Quasar design system and warm brand palette.

## Layout & Interaction Contract

### Route & Nav placement

| Item                | Value                                                                                                                                   |
| ------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |

| Page component      | `pages/ConfiguracionCajaPage.vue`                                                                                                       |
| `meta.allowedRoles` | `['admin', 'owner']` (owner/admin gated — coach/gestion excluded; config is admin+, D-06 + permissions.ts)                              |

| Nav label           | "Configuración de Caja"                                                                                                                 |
| Nav icon            | `settings` (Material)                                                                                                                   |

> **Assumption A1 (Claude's discretion, D-06):** placed under the existing **Administracion**
> drawer section rather than next to Caja, because that section already groups owner/admin-only

> may instead place it directly below "Caja" gated by `isAdminRole` if Franco prefers proximity —

### Single-field form layout

```
q-page (q-pa-md, cream bg)
├── div.row.items-center.q-mb-md
│     └── div.text-h5  "Configuración de Caja"
└── q-card (flat bordered, max-width ~480px)
      └── q-card-section
            └── q-form (@submit.prevent="onSave")
                  ├── q-input
                  │     v-model.number="thresholdDays"
                  │     type="number"  min="1"
                  │     label="Umbral de pendientes (días)"
                  │     outlined  dense
                  │     :loading="loading"        ← while reading current value
                  │     :rules="[required, min1, integer]"
                  │     hint="Días sin validar tras los que un pendiente
                  │           dispara la alerta de la bandeja de Caja."
                  └── div.q-mt-md
                        └── q-btn  type="submit"  label="Guardar"
                              color="primary"  :loading="saving"  :disable="loading"
```

Field is the only control. No reset button, no extra rows. Card is width-capped (~480px) so the
lone input doesn't stretch across a wide admin viewport.

### States

| State                     | Trigger                                           | UI behaviour                                                                                                      |
| ------------------------- | ------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| **Loading current value** | On mount, fetching `finance.pending_overdue_days` | Input shows `:loading` spinner (or a `q-skeleton` over the input); Guardar disabled                               |
| **Idle / loaded**         | Current value fetched                             | Input populated with current int (e.g. `3`); Guardar enabled                                                      |
| **Validation error**      | Value `< 1`, empty, or non-integer                | Quasar `:rules` shows inline error under input ("Debe ser un número entero ≥ 1"); submit blocked, no request sent |
| **Saving**                | Guardar pressed, valid                            | Guardar shows `:loading`; input read-only during request                                                          |
| **Saved (success)**       | PUT/POST resolves                                 | `$q.notify({ type: 'positive', message: 'Configuración guardada' })`; input reflects saved value                  |
| **Save error**            | Request rejects (network / 4xx / 5xx)             | `$q.notify({ type: 'negative', message: 'No se pudo guardar. Reintentá.' })`; value stays editable, nothing lost  |

There is no empty state (the setting always resolves to a value via the backend default-fallback,
mirror of `getStreakMilestoneConfig`; if the row is missing the UI still receives `3`).

### Validation rule (locked)

- **Integer, minimum 1.** A threshold of 0 or negative is meaningless (a pendiente cannot be
  "overdue before it exists"). Upper bound is not enforced in the UI (any sane large int is allowed);
  the backend may clamp but the form does not invent a max.

### State management

- A composable `useCajaConfigApi()` (or `useFinanceConfigApi`) exposing `getThreshold()` / `setThreshold(days)`,
  `loading`, `saving`, and a `cleanup()` method — **per CLAUDE.md composable pattern (no `onUnmounted`
  inside the composable; expose `cleanup()` and call it from the page's `onUnmounted`).**
- Use `createLogger('ConfiguracionCajaPage')` for any error logging — never `console.*`.
- No `any` types — define a `CajaConfig`/threshold response interface.

## Accessibility

- Numeric input has a visible `label` (Quasar associates it as the field label) — no placeholder-only
  labelling.
- Hint text is persistent (`hint` prop), not tooltip-only, so the threshold's meaning is always visible.
- Validation errors render as text below the input (Quasar `:rules`), not color-only — meets non-color
  error signalling.
- Save is a real `type="submit"` inside `q-form`, so Enter-to-submit works for keyboard users.
- Focus ring uses the terracotta `$primary` which meets WCAG AA contrast on the cream surface
  (4.75:1, per palette comments).
- Success/error feedback uses Quasar `notify` (announced) plus warm semantic colors that pass AA.
