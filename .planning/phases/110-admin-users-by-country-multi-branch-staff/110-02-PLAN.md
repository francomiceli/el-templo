Run the project's custom migration runner from the API package:

```bash
cd el-templo-api && pnpm db:migrate
```

This invokes `src/db/run-migrations.ts` which:

1. Reads pending migrations from `el-templo-api/src/db/migrations/` (alphabetical order).
2. Skips any whose filename is already in the `_migrations` table.
3. Splits each pending file on `;`, executes statements sequentially.
4. INSERTs the filename into `_migrations` on success.

Expected output: `Applied 0107_admin_users_by_country.sql` (or similar — match the runner's actual stdout). If the runner errors, capture the failing statement and STOP — do not run partial cleanup. Phase 105 P01 precedent: "CREATE×3 then DROP×2 protects against partial-failure data loss"; here we have ALTER + CREATE + UPDATE + INSERT, so a partial failure leaves the schema half-applied. Roll forward by fixing the SQL or re-running, never roll back without operator review.

Forbidden: do NOT use `drizzle-kit migrate` (CLAUDE.md). Do NOT use `drizzle-kit push` either — bypasses the `_migrations` tracker.
</action>
