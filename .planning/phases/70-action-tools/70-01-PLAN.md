Create bot-internal API routes at `/api/bot/scheduling` in a new `bot-routes.ts` file. These are NOT admin or member routes -- they're service-to-service endpoints called only by el-templo-bot via localhost.

**Auth guard:** Use a simple API key check via `x-bot-api-key` header matched against `BOT_API_KEY` env var. Add the env var to `.env.example`. This is localhost-only traffic so a shared secret is sufficient.

**POST /book-class** — Book a class for an identified member:

- Body: `{ memberId: number, scheduleId: number, date: string }` (same as the existing BookingService.reserve args)
- Delegates to `BookingService.reserve(memberId, scheduleId, date)`
- Returns 201 with BookingRecord on success
- Returns 400/404/409 with error message on validation failures (class full, already booked, past class, etc.)
- The bot will have already resolved memberId from the phone->user lookup and scheduleId from the schedule query

**POST /register-trial** — Create a trial user and optionally book them into a class:

- Body: `{ phone: string, name: string, scheduleId?: number, date?: string }`
- Delegates to a new `BotSchedulingService.registerTrial()` method
- Create `bot-service.ts` with `BotSchedulingService` class:
  1. Check if user already exists by phone. If exists and already had a trial subscription, return error "Ya tuviste una clase de prueba"
  2. If user doesn't exist: INSERT into users table with `{ firstName: name, phone, role: 'member', branchId: 1 (default), isActive: true }`. Use drizzle insert.
  3. Find the trial subscription plan: `SELECT id FROM subscription_plans WHERE is_trial = true AND is_active = true LIMIT 1`
  4. Create a trial subscription: INSERT into subscriptions `{ userId, planId: trialPlan.id, status: 'active', startDate: today, endDate: today + plan.durationDays }`
  5. If scheduleId + date provided: call `BookingService.reserve(newUserId, scheduleId, date)` to book the class
  6. Return `{ userId, bookingId?, message }`
- Returns 201 on success, 400 on validation error, 409 if trial already used

**Register the routes** in `app.ts`:

```typescript
import { schedulingBotRoutes } from "./modules/scheduling/bot-routes";
// ... in buildApp():
await app.register(schedulingBotRoutes, { prefix: "/api/bot/scheduling" });
```

Register BEFORE the admin/member auth hooks so the bot routes use their own API key guard, not JWT auth.

Add `BOT_API_KEY` to el-templo-api `.env.example` with a comment explaining it's for bot-to-API communication.

Add interactive message support to the WhatsApp client per Meta Cloud API interactive message format.

**In types.ts**, add:

```typescript
/** WhatsApp interactive button for confirmation/selection */
export interface InteractiveButton {
  id: string; // e.g. "confirm_booking", "cancel_booking"
  title: string; // e.g. "Confirmar", "Cancelar" (max 20 chars)
}

/** WhatsApp interactive list row for class selection */
export interface InteractiveListRow {
  id: string; // e.g. "schedule_42"
  title: string; // e.g. "Yoga 18:00" (max 24 chars)
  description?: string; // e.g. "Sede Alem - 3 lugares" (max 72 chars)
}
```

Also add interactive reply types to MetaWebhookMessage:

```typescript
interactive?: {
  type: 'button_reply' | 'list_reply';
  button_reply?: { id: string; title: string };
  list_reply?: { id: string; title: string; description?: string };
};
```

**In client.ts**, add `sendInteractiveMessage` function:

```typescript
export async function sendInteractiveMessage(
  phone: string,
  bodyText: string,
  buttons: InteractiveButton[],
): Promise<string>;
```

Implementation:

- Same auth token / phoneId / URL pattern as sendTextMessage
- Body format per Meta API:

```json
{
  "messaging_product": "whatsapp",
  "to": phone,
  "type": "interactive",
  "interactive": {
    "type": "button",
    "body": { "text": bodyText },
    "action": {
      "buttons": buttons.map(b => ({
        "type": "reply",
        "reply": { "id": b.id, "title": b.title }
      }))
    }
  }
}
```

- Max 3 buttons per message (WhatsApp API limit). If more than 3, log a warning and truncate.
- Returns wamid like sendTextMessage.

**Update parseWebhookPayload** in client.ts to also handle interactive replies:

- Currently only accepts `message.type === 'text'`. Add handling for `message.type === 'interactive'`:
  - Extract button_reply.id and button_reply.title (or list_reply equivalents)
  - Set `text` field to `button_reply.title` (so the AI sees the button label as user text)
  - Set `messageType` to `'text'` (treat it as text for downstream processing)
  - Add `interactiveReplyId` to ParsedInboundMessage interface (optional string) so tools can check the exact button ID
- This way interactive replies flow through the same handler pipeline.

Also add `BOT_API_KEY` to el-templo-bot `.env.example` with comment.
