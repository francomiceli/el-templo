**1. `device_tokens` table (per D-25, D-26, D-27):**

- `id`: int, primaryKey, autoincrement
- `userId`: int, references users.id, notNull
- `token`: varchar(500), notNull — FCM registration token
- `platform`: mysqlEnum('platform', ['android', 'ios']), notNull

- `id`: int, primaryKey, autoincrement
- `templateKey`: varchar(100), notNull, unique — e.g. 'segment_transition_en_riesgo', 'weekly_summary', 'morning_energy', 'post_session_soreness', 'program_enrollment', 'program_week_unlock', 'program_renewal_warning', 'segment_transition_ghost', 'segment_transition_recovery', 'segment_transition_espartano', 'ghost_monthly_reattempt'

- `title`: varchar(200), notNull — notification title in Spanish
- `body`: text, notNull — notification body text in Spanish
- `route`: varchar(200), default '/mi-templo' — deep link route (per D-28)
- `isEnabled`: boolean, default true, notNull — admin toggle (per D-13)
- `sentCount`: int, default 0, notNull — delivery tracking counter (per D-31)
- `openedCount`: int, default 0, notNull — open tracking counter (per D-31)
- `createdAt`: timestamp, defaultNow, notNull
- `updatedAt`: timestamp, defaultNow, onUpdateNow, notNull

**3. `notification_preferences` table (per D-18, D-19, D-20):**

- `id`: int, primaryKey, autoincrement
- `userId`: int, references users.id, notNull
- `category`: mysqlEnum('notification_category', ...) reuse the same enum, notNull
- `enabled`: boolean, default true, notNull
- `createdAt`: timestamp, defaultNow, notNull
- `updatedAt`: timestamp, defaultNow, onUpdateNow, notNull

- `userId`: int, references users.id, notNull
- `templateId`: int, references notification_templates.id (nullable for ad-hoc admin sends)

- `scheduledAt`: timestamp, notNull — when to send (now for immediate, future for delayed per D-10)
- `sentAt`: timestamp, nullable
- `errorMessage`: varchar(500), nullable — failure reason
- `createdAt`: timestamp, defaultNow, notNull
- Index on (status, scheduledAt) for queue polling (idx_pending_notifications_queue)
- Index on userId (idx_pending_notifications_user_id)

**NotificationService class:**

Constructor: `(db: DbInstance, log: FastifyBaseLogger, dryRun?: boolean)`

- `dryRun` defaults to `process.env.DRY_RUN === 'true'` (per D-39)

**Core methods:**

1. `initFirebase()`: Initialize firebase-admin app using FIREBASE_SERVICE_ACCOUNT_BASE64 env var. Decode base64 -> JSON.parse -> admin.initializeApp({ credential: admin.credential.cert(serviceAccount) }). If DRY_RUN or no env var, skip init and log warning. Store the initialized messaging instance as private field. Call this once at service construction or lazily on first send.

2. `queueNotification(input: QueueNotificationInput): Promise<number>` — Look up template by templateKey from notification_templates table. If template not found or not enabled, log warning and return -1. Check user's notification_preferences for that template's category — if disabled, skip (return -1). Insert into pending_notifications with status='pending', scheduledAt (default now), title from template (or titleOverride), body from template (or bodyOverride), route from template (or routeOverride). Return the pending notification ID.

3. `queueAdHocNotification(input: QueueAdHocInput): Promise<number>` — For admin segment sends. Check user's notification_preferences for 'anuncios' category. Insert into pending_notifications with templateId=null, provided title/body/route, status='pending'. Return pending notification ID.

4. `processQueue(): Promise<{ sent: number; failed: number }>` — Called by cron every 15 min (per D-10). Select all pending_notifications where status='pending' AND scheduledAt <= NOW(), ordered by scheduledAt ASC, limit 100 (batch processing). For each notification:
   a. Get all device_tokens for that userId
   b. If no tokens, mark as 'failed' with errorMessage 'No device tokens registered'
   c. For each token, call sendToDevice(token, title, body, route, notificationId)
   d. On success: update status='sent', sentAt=now. If templateId exists, increment sentCount on notification_templates.
   e. On failure: single retry (per D-38). If retry fails, mark status='failed', errorMessage from FCM error.
   f. Return counts.

5. `sendToDevice(token: string, title: string, body: string, route: string, notificationId: number): Promise<boolean>` — If dryRun, log the notification details and return true. Otherwise, use firebase-admin messaging().send({ token, notification: { title, body }, data: { route, notificationId: String(notificationId) } }). On 'messaging/registration-token-not-valid' or 'messaging/invalid-registration-token' error, delete the token from device_tokens (per D-27). Return success boolean.

6. `registerToken(userId: number, token: string, platform: 'android' | 'ios'): Promise<void>` — Upsert: if token exists (unique constraint), update userId and updatedAt. If new token, insert. This handles the D-26 on-every-launch token registration.

7. `removeToken(token: string): Promise<void>` — Delete token from device_tokens.

8. `getUserPreferences(userId: number): Promise<Record<NotificationCategory, boolean>>` — Query notification_preferences for userId. Default all categories to true (per D-19) if no row exists.

9. `updatePreference(userId: number, category: NotificationCategory, enabled: boolean): Promise<void>` — Upsert notification_preferences row.

10. `recordOpened(notificationId: number): Promise<void>` — Increment openedCount on the notification_templates table for the template associated with this pending_notification ID (per D-31, D-32). Look up the pending_notification to get templateId, then increment.

11. `purgeOldNotifications(): Promise<number>` — Delete from pending_notifications where status in ('sent', 'failed') AND createdAt < NOW() - 24 hours (per D-11). Return deleted count.

12. `seedTemplates(): Promise<void>` — Import TEMPLATE_SEEDS from types.ts. For each seed, INSERT IGNORE (skip if templateKey already exists) into notification_templates. Used during migration/startup.
