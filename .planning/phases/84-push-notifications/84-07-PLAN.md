**Test setup:**

- Create test app
- Get auth tokens: one member token, one admin/owner token
- Seed notification templates before tests: POST /api/notifications/admin/seed-templates with admin token

**Test groups:**

**1. Token Registration:**

- `POST /api/notifications/token` with valid token and platform='android' returns 200
- `POST /api/notifications/token` with same token again returns 200 (upsert)
- `POST /api/notifications/token` without auth returns 401
- `POST /api/notifications/token` with missing token field returns 400
- `POST /api/notifications/token` with invalid platform returns 400

**2. Notification Preferences:**

- `GET /api/notifications/preferences` returns 200 with 4 categories all true (defaults per D-19)
- `PUT /api/notifications/preferences` with { category: 'entrenamiento', enabled: false } returns 200
- `GET /api/notifications/preferences` after update shows entrenamiento: false, others: true
- `PUT /api/notifications/preferences` with invalid category returns 400
- `PUT /api/notifications/preferences` without auth returns 401

**3. Opened Tracking:**

- First queue a notification via service (direct service call or admin endpoint), then:
- `POST /api/notifications/:id/opened` with valid ID returns 200
- `POST /api/notifications/999999/opened` with non-existent ID returns 200 (graceful)
- `POST /api/notifications/:id/opened` without auth returns 401

**4. Admin Template Management:**

- `GET /api/notifications/admin/templates` with admin token returns 200 with template array
- Templates include seeded entries with sentCount=0, openedCount=0, openRate=0
- `PUT /api/notifications/admin/templates/:id` with { title: 'Updated' } updates title
- `PUT /api/notifications/admin/templates/:id` with { isEnabled: false } disables template
- `GET /api/notifications/admin/templates` with member token returns 401/403
- `POST /api/notifications/admin/seed-templates` with admin token returns 200

**5. Send to Segment:**

- `POST /api/notifications/admin/send-segment` with { title: 'Test', body: 'Test body', segmentIds: ['espartano'] } returns 200 with queued count
- The queued count should match members with 'espartano' segment in member_profiles
- `POST /api/notifications/admin/send-segment` with member token returns 401/403
- `POST /api/notifications/admin/send-segment` with empty segmentIds returns 200 with queued: 0

**6. Queue Processing (service-level test via direct service call):**

- Create NotificationService with db and test logger, dryRun=true
- Queue a notification via service.queueNotification()
- Call service.processQueue()
- Verify the notification status changed to 'sent' in DB
- Verify sentCount incremented on the template
- Call service.purgeOldNotifications() — verify sent rows older than 24h deleted (may need to manually backdate for test)

**Cleanup:**

- After all tests, delete test data from device_tokens, pending_notifications, notification_preferences tables (add to cleanTestData in helpers.ts if the pattern allows, or do inline cleanup)

Use `beforeAll` for app creation and template seeding, `afterAll` for cleanup and app.close().

**Update `.github/workflows/build-android-production.yml`:**

Add a step to decode google-services.json from GitHub Secret, right AFTER the "Decode keystore" step (around line 70) and BEFORE the "Build signed AAB and APK" step.

Per D-35, google-services.json is stored as base64 in GitHub Secrets (same pattern as keystore from Phase 75):

```yaml
- name: Decode google-services.json
  working-directory: el-templo-app/src-capacitor/android/app
  run: printf '%s' "${{ secrets.GOOGLE_SERVICES_JSON_BASE64 }}" | base64 --decode > google-services.json
```

This places the file at `el-templo-app/src-capacitor/android/app/google-services.json` which is exactly where the existing build.gradle `try { def servicesJSON = file('google-services.json') }` block expects it.

**Update `.github/workflows/deploy.yml`:**
