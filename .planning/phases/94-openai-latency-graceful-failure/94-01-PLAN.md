<objective>
Close BUG-02 (the ~3-minute response latency observed 2026-04-16 22:23-22:26) by enforcing a known OpenAI timeout boundary and providing user-visible UX on slow / failing upstream calls.

Three coupled deliverables, single atomic GREEN commit:

- **LAT-01** — Inject an explicit `timeout` option into the `OpenAI` SDK client at `el-templo-bot/src/ai/openai.ts:29`, defaulting to `45_000` ms and overridable via `OPENAI_TIMEOUT_MS`. Without this the SDK silently uses its 600s default.
- **LAT-02** — Wrap the two `provider.chat(...)` await sites in `el-templo-bot/src/webhook/handler.ts` (`:600` outside the tool loop; `:657` inside the tool loop) so that an `OpenAI.APIError` (which covers `APIConnectionTimeoutError` thrown when the SDK `timeout` is exceeded) triggers a single interim UX message — **"Dame un segundo 🙌"** — sent via the existing `sendTextMessage` path.
- **LAT-03** — Extend the outer `try/catch` at `el-templo-bot/src/webhook/handler.ts:334-350` (currently log-only) to send a graceful fallback — **"Tuve un problemita técnico, ¿me lo escribís de nuevo?"** — before returning cleanly. No re-throw, no infinite loop, no process exit. The `human_takeover` early-return at `:325-331` is unaffected.

Purpose: Eliminate silent multi-minute stalls; close the BUG-02 v5.3.3 release blocker; preserve the Cross-Phase Invariant locked in by Phase 93's `DEBOUNCE_TTL_SECONDS=600`.

Output: One TDD RED commit (failing tests against current main), one GREEN commit (LAT-01+02+03 + env example + invariant script).

**Plan-time decisions (Claude's Discretion, declared per CONTEXT.md lines 109-115):**

1. **Wrapper shape for LAT-02:** Inline `try/catch` around each of the two `provider.chat` await sites inside `processWithAi`, both delegating to the same `sendInterimMessage(phone)` helper. The interim message must fire when the SDK throws at the await — putting the catch at the outer `try/catch` (line 334) would also work, but separating "send interim" (LAT-02) from "send graceful fallback" (LAT-03) makes the two SC#2 vs SC#3 test surfaces independently observable. Both catches re-throw so the outer catch handles LAT-03 fallback dispatch.
2. **Retry policy:** Option (a) — NO manual handler-level retry. The SDK already retries 2× internally within the 45s timeout boundary; once it throws, the upstream is durably slow within the bound. Manual retry adds another 45s of wait with no measured benefit. Interim message is a UX signal, not a retry obligation.
3. **`OpenAI.APIError` shape preservation:** Option (b) — re-throw the raw `OpenAI.APIError` from `openai.ts:88-97` (currently re-thrown as `new Error(...)`). The change is ≤ 5 lines (keep the `logger.error`, replace `throw new Error(...)` with `throw err`). LAT-02's catch then uses `err instanceof OpenAI.APIError` for clean discrimination instead of brittle message-text matching. The `instanceof Error` fallback in the outer catch still works because `OpenAI.APIError extends Error`.
