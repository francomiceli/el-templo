    **1. DB Schema** (`el-templo-api/src/db/schema/attendance.ts`):
    - Create `attendance` table with columns:
      - `id` int PK autoincrement
      - `memberId` int FK -> users.id, notNull
      - `branchId` int FK -> branches.id, notNull
      - `checkedInAt` timestamp, notNull, defaultNow
      - `confirmedAt` timestamp, nullable (set when coach confirms)
      - `attendance_status` mysqlEnum("attendance_status", ["registrado", "confirmado"]), notNull, default "registrado"
      - `attendance_source` mysqlEnum("attendance_source", ["qr", "manual"]), notNull, default "qr"
      - `createdAt` timestamp defaultNow notNull
    - IMPORTANT: mysqlEnum name becomes SQL column name (Phase 48 lesson). Use "attendance_status" and "attendance_source" as enum names.
    - Add relations: member -> users, branch -> branches
    - Add index on (memberId, checkedInAt) for per-member queries
    - Add unique index on (memberId, DATE(checkedInAt)) for one-per-day constraint — implement at service layer since MySQL can't do functional unique indexes, but add compound index on (memberId, checkedInAt) for query performance.

    **2. Migration** (`el-templo-api/src/db/migrations/0034_attendance.sql`):

    - FKs to users(id) and branches(id)

    **5. Schemas** (`el-templo-api/src/modules/attendance/schemas.ts`):
    - Fastify JSON schemas for: memberCheckIn (POST body with qrToken), batchConfirm (POST body with attendanceIds array), manualCheckIn (POST body with memberId), generateQr (GET params with branchId), listAttendance (GET querystring with filters/pagination), memberAttendanceHistory (GET params with userId)

    **6. Service** (`el-templo-api/src/modules/attendance/service.ts`):
    - Constructor DI: `constructor(db, log)` — same pattern as AuraService/PaymentService/SubscriptionService
    - Create internal instances: `new PaymentService(db, log)`, `new SubscriptionService(db, log)`, `new AuraService(db, log)`

    **QR Token methods:**
    - `generateQrToken(branchId: number): string` — HMAC-SHA256 sign `{branchId, type: "checkin"}` with `process.env.JWT_SECRET` (reuse existing env var). Return base64url encoded `payload.signature`.
    - `validateQrToken(token: string): QrPayload | null` — Decode, verify HMAC, return payload or null.

    **Check-in method** (`checkIn(memberId, qrToken)`):
    - Validate QR token -> extract branchId
    - Check subscription: call `subscriptionService.getMemberSubscription(memberId)`. If null -> throw BadRequestError "No tenés una suscripción activa"
    - Check overdue: call `paymentService.getMemberBalance(memberId)`. If isOverdue -> throw BadRequestError "Tu suscripción tiene un pago pendiente. Acercate a recepción."
    - Check branch enforcement: Get the member's subscription plan (need to query subscription_plans.multiBranch via the subscription's planId). If !multiBranch and the QR branchId !== member's branchId (from users table) -> throw BadRequestError "Tu plan solo permite asistir a tu sede asignada"
    - Check one-per-day: Query attendance for this memberId where DATE(checkedInAt) = CURDATE(). If exists -> throw BadRequestError "Ya registraste asistencia hoy"
    - Insert attendance record with status "registrado", source "qr"
    - Return the created record

    **Manual check-in** (`manualCheckIn(memberId, branchId, coachId)`):
    - Same subscription/overdue/one-per-day checks as checkIn (but NO branch enforcement — coach overrides)
    - Insert attendance record with status "confirmado", source "manual", confirmedAt = NOW()
    - Award AURA immediately: `auraService.award({ userId: memberId, sourceType: "attendance", referenceType: "attendance", referenceId: record.id })`
    - Return the created record

    **Batch confirm** (`batchConfirm(attendanceIds: number[])`):
    - Update all records in attendanceIds to status "confirmado", confirmedAt = NOW() WHERE status = "registrado"
    - For each confirmed record, award AURA: `auraService.award(...)` with sourceType "attendance"
    - Return count of confirmed records
    - Handle duplicate AURA awards gracefully (AuraService throws on duplicate — catch and skip)

    **Query methods:**
    - `listAttendance(params: AttendanceListParams)`: Join with users and branches for names. Filter by branchId, date (single day or range), status. Paginated. Order by checkedInAt DESC.
    - `getMemberAttendance(memberId, page, limit)`: Shortcut for listAttendance with memberId filter.
    - `getTodayByBranch(branchId)`: Get all attendance records for today at a branch (for batch confirm page). No pagination — returns all.

    **7. Routes** (`el-templo-api/src/modules/attendance/routes.ts`):

    Create TWO route plugins:

    `attendanceAdminRoutes` (registered at /api/admin/attendance):
    - Plugin-level onRequest hook for admin/coach/superadmin role guard (same pattern as members/payments)
    - `GET /qr/:branchId` — Generate QR token for branch. Return `{ token, branchId, branchName }`. Validate branch exists and is not virtual.
    - `GET /today?branchId=X` — Get today's attendance for batch confirm. branchId required.
    - `POST /confirm` — Batch confirm. Body: `{ attendanceIds: number[] }`.
    - `POST /manual` — Manual check-in. Body: `{ memberId: number, branchId: number }`.
    - `GET /` — List attendance with filters (branchId, date, dateFrom, dateTo, status, page, limit).
    - `GET /member/:userId` — Member's attendance history (paginated).

    `attendanceMemberRoutes` (registered at /api/members/attendance):
    - Auth-only guard (any authenticated user), no admin role required
    - `POST /check-in` — Member check-in. Body: `{ qrToken: string }`. Uses request.user.userId.
    - `GET /history` — Member's own attendance history (paginated). Uses request.user.userId.
