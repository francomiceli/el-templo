## Spacing Scale

Quasar's `q-pa-*` / `q-gutter-*` / `q-mb-*` utilities map to a 4px base. Declared values (all multiples of 4):

| Token | Value | Quasar util | Usage                                                         |
| ----- | ----- | ----------- | ------------------------------------------------------------- |
| xs    | 4px   | `xs`        | Icon-to-text gaps, inline padding, badge groups               |
| sm    | 8px   | `sm`        | Compact field gutter inside a card (`q-gutter-sm`)            |
| md    | 16px  | `md`        | Default element/section spacing, page padding (`q-pa-md`)     |
| lg    | 24px  | `lg`        | Gap between the step body and the summary panel; card-to-card |
| xl    | 32px  | `xl`        | Column gap desktop (active step ↔ summary), page-level breaks |
| 2xl   | 48px  | —           | Empty-state vertical padding                                  |
| 3xl   | 64px  | —           | Not used this phase                                           |

Exceptions:

- List item touch targets stay at `q-py-md` (≈44px min height) for the socio typeahead options, plan grid rows, and payment-method buttons — accessible tap size.
- Sticky action bar offset `[0, 16]` (16px above safe area), unchanged from current page.
- Content column max-width: **560px** for the active-step body (mobile stays single column, full width minus `q-pa-md`). Right summary panel fixed at **320px** on desktop.

## Color

60/30/10 split on the warm palette:

| Role            | Value                                  | Usage                                                                                                                                     |
| --------------- | -------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| Dominant (60%)  | `#f2ede5` Marble Cream                 | Page background, form surfaces, cards (bordered-flat on cream, current pattern)                                                           |
| Secondary (30%) | `#e9e2d6` deeper cream (subtle raised) | Right summary panel background, progress-header band, mobile compact summary header, selected/active list surfaces where not using accent |
| Accent (10%)    | `#96593a` Terracotta (`--q-primary`)   | See reserved list below                                                                                                                   |
| Destructive     | `#b34a4a` Warm red (`negative`)        | Abandon-flow confirmation button only (no delete actions in this phase)                                                                   |

Accent reserved for:

- Portada primary CTA **"Registrar cobro"**.
- Step **"Continuar"** button and final **"Confirmar · $monto"** button.
- Active step indicator in the progress header (current step number + connector fill).
- Selected state of a plan row (`active-class="bg-primary text-white"`, current pattern) and the selected payment-method button.
- Links / text buttons ("+ Nueva cuenta", "Asignarle un plan").

Never apply accent to: static list rows, the summary panel body, badges that carry their own semantic color, or every button on screen.

Semantic (feedback) colors — carried from `quasar.variables.scss`, not counted in the 10% accent:

- `warning` `#7d6520` (`bg-warning text-dark`): **debt notice banner (POS-01)** in step 1, partial-payment warning in step 3, "Pendiente de validación" hint, "sin cuentas" profe notice.
- `positive` `#3b7249`: Zero-price toggle, success `$q.notify`, "Activa" status badge in socio search.
- `negative` `#b34a4a`: error `$q.notify`, validation error text.

## Flow Layout & Interaction Contract (phase-specific)

### Route & entry (D-09, D-11)

- Route renamed `/pagos` → `/cobros`, with a redirect `/pagos → /cobros`. Role landing (149 D-14) points to `/cobros`.
- Portada `/cobros`: **CTA `Registrar cobro` (accent, size `lg`, full-width up to 560px) at the top**, historical listado below (COBRO-03).
- Tapping the CTA enters the 4-step flow (state held in the page component, single route — D-02). No child routes, no store, no refresh-loss.
- Design the flow entry to accept an optional pre-selected socio (prop/query) for future phase 154 reuse — do not build the caller now, just don't hard-block it.

### Progress header (locked from Claude's discretion)

- **Numbered steps with labels**: `1 Socio · 2 ¿Qué se cobra? · 3 ¿Cómo se paga? · 4 Resumen`, linear connector; current step number filled accent, completed steps show a check, future steps muted (`text-grey-6`). Header sits on the secondary band (`#e9e2d6`).
- **Mobile**: collapse to `Paso {n} de 4` + a thin `q-linear-progress` (accent, `size="4px"`) + the current step label. Back arrow at left.
- Back button (`arrow_back`) always at the header's left edge; advances via the `Continuar`/`Confirmar` action at the bottom of the step body (sticky on mobile, inline-bottom on desktop).

### Step transitions (locked)

- Horizontal slide: forward = new step slides in from the right; back = slides in from the left. Duration 200ms, ease-out. Use a Vue `<transition>`/`<transition-group>` wrapper.
- Respect `prefers-reduced-motion: reduce` → fall back to a plain fade (or no transition). No layout shift of the progress header during transition.

### Two-column layout (D-04, locked)

- **Desktop (`$q.screen.gt.sm`)**: two columns with `xl` (32px) gap. Left = active step body (max 560px). Right = **accumulated summary panel** (320px, sticky below header, secondary surface `#e9e2d6`, `lg` padding) listing what's chosen so far: `Socio`, `Qué se cobra`, `Cómo se paga`, and a bold `Total` (Heading 20/600). Empty rows show a muted placeholder (`—`).
- **Mobile**: the summary collapses to a **compact sticky header** under the progress bar showing socio name + running total; tappable to expand the full summary in a `q-expansion` / bottom sheet.
- **Step 4 (Resumen) and the desktop right panel share one component** (`CobroResumen.vue` or equivalent) — single source of truth for the accumulated summary.

### Per-step content contract

- **Step 1 — Socio**: socio typeahead (`Buscar socio (nombre o DNI)`) + `Nuevo alumno` path (mini-form Nombre/Apellido/DNI + DNI dedup on-blur + Sede select, reused from phase 148 behavior). **Debt notice (POS-01) renders here**, below the selected/created socio, as a `warning` banner; it also surfaces as a small warning chip in the summary panel. `Continuar` enabled once a socio is selected or a valid new-student mini-form is filled.
- **Step 2 — ¿Qué se cobra?**: three associations surfaced as one question (D-01, no mode toggle) — (a) renovar plan vigente (readonly plan name + amount), (b) asignar plan nuevo (plan grid by tier + Zero toggle + `FixedSchedulePicker` for fixed plans), (c) cobro suelto (concepto + `Motivo` select, obligatorio). If the socio has no renewable plan, offer `Asignarle un plan` inline. The flow chooses which of the 3 endpoints to call at confirm.
- **Step 3 — ¿Cómo se paga?**: payment-method buttons (`Efectivo` / `Transferencia` / `Tarjeta`) + amount (`Monto`, currency suffix). **Bank-account selector (COBRO-04)** appears only for `Transferencia`/`Tarjeta`: a `q-select` filtered to **active bank-type accounts of the charge currency** (150 invariants). Cash never shows it (and server rejects a raw `cashRegisterId` for cash). See account states below.
- **Step 4 — Resumen y Confirmar**: renders the shared summary component read-only + final `Confirmar · {monto}` action. Idempotency key generated lazily on first tap of Confirmar, reused across retries, regenerated only after acknowledged success (140 D-09 semantics preserved exactly).

### Bank-account selector states (COBRO-04, D-08 — locked)

- **Accounts exist (any role)**: `q-select` of active bank accounts of the charge currency. `+ Nueva cuenta` is shown **even when accounts exist** (convenience), as a trailing action inside the dropdown AND an inline text button below the selector — but only rendered for **admin/owner** (150 D-12). Selecting `+ Nueva cuenta` opens `CuentaBancariaFormDialog` (150 D-11) with the charge currency preselected.
- **No accounts of the charge currency, admin/owner**: treat as empty state — show `No hay cuentas de esta moneda. Creá una para continuar.` + `Crear cuenta` button opening the dialog with currency preselected.
- **No accounts, profe/recepción**: show the warning notice (copy above), disable finishing by transfer/card; **Efectivo stays available**. The real security gate lives in the API (149 D-04); the UI only hides the create button.
- Prefill is corregible downstream: the chosen account is a suggested imputation, visible and editable by the validator in `BandejaPendientesTab` (D-05) — no UI change needed in this phase's page beyond sending the field.

### Listado (COBRO-03, D-10 — locked)

- Title `Cobros` (was "Mis cargas de hoy", which lied — endpoint returns last 50 historical, not today).
- **Grouped by day** with sticky day-group labels (`Hoy` / `Ayer` / `{ddd d MMM}`); each row shows **time `HH:mm`** + socio + concept + method badge + `Pendiente` badge + amount. Endpoint unchanged (`GET /coach-load/mis-cargas`); this is a frontend-only label+format fix.
