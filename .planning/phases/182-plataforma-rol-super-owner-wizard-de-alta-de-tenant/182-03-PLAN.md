(`deploy.yml`, `RUNBOOK.md`), así que un contador en memoria es coherente y no necesita Redis. Con

**Si la Task 1 resolvió `opcion-b`:** crear `el-templo-api/src/modules/platform/rate-limit.ts` con
un limitador propio, sin dependencias:
- `const MAX_INTENTOS = 10`, `const VENTANA_MS = 5 * 60 * 1000`.
- `const intentos = new Map<string, { n: number; resetAt: number }>()`.
- `export function claveDeCliente(request: FastifyRequest): string` — usa el primer valor de
  `x-forwarded-for` si existe (nginx lo setea), si no `request.ip`.
- `export function consumirIntento(clave: string, ahora = Date.now()): { permitido: boolean;
  restantes: number; resetAt: number }` — ventana fija: si `ahora > resetAt` resetea el contador.
- `export function limpiarVencidos(ahora = Date.now()): void` — borra entradas con `resetAt <
  ahora`; llamarla al inicio de `consumirIntento` cada N llamadas o cuando el `Map` supere 1000
  entradas, para que no crezca sin techo.
- `export const platformLoginRateLimit: preHandlerHookHandler` — si `permitido === false`, responde
  `reply.code(429).header("Retry-After", segundosHastaReset).send({ error: "Demasiados intentos",
  message: "Demasiados intentos de inicio de sesion. Intenta de nuevo mas tarde." })` y re-lanza
  para abortar el handler, igual que hace `requirePlatformAuth`.
- `export function resetPlatformRateLimit(): void` — limpia el `Map`; **solo para tests**
  (documentarlo así en el docblock).
- Docblock honesto: es el mínimo consciente que reemplaza a `@fastify/rate-limit` porque el usuario
  eligió no sumar dependencia; es válido mientras la API corra en pm2 fork de **una** instancia
  (con cluster mode el contador deja de ser global y hay que migrar al paquete oficial).
En `auth-routes.ts`, agregar `preHandler: platformLoginRateLimit` a la opción de ruta de
`POST /login`.

En AMBOS casos: el limitador aplica **solo** a `POST /api/platform/auth/login`; ninguna otra ruta
de la API cambia de comportamiento. Anotar en el SUMMARY qué opción se ejecutó y por qué.
