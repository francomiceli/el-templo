<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| internet → nginx del EC2 | El vhost wildcard amplía el conjunto de hosts aceptados en un servidor que ya sirve producción |
| operador → producción (SSH) | Cambios con root fuera del pipeline, sin revisión automática |
| certbot → API del proveedor de DNS | Credenciales de larga vida almacenadas en el servidor |
| staging ↔ producción | Comparten host MySQL |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-182-22b | Spoofing | `Host` arbitrario contra el EC2 | mitigate | `server_name` explícito por vhost **más** un `default_server` que rechaza lo no matcheado; verificación con `curl` de un `Host` inventado dentro del gate |
| T-182-23b | Information Disclosure | Credenciales de la API del DNS | mitigate | Archivo de credenciales con permisos `600`, fuera del repo; ruta anotada en la Bitácora sin el contenido |
| T-182-31 | Elevation of Privilege | `PLATFORM_JWT_SECRET` compartido entre entornos | mitigate | Un secreto por entorno, generado en el servidor con `openssl rand`, distinto entre staging y prod y distinto de `JWT_SECRET`; nunca sale del servidor |
| T-182-24b | Tampering | Alta del demo en la base equivocada | mitigate | `SELECT DATABASE()` obligatorio antes de cada alta; slugs distintos si la base es compartida; el alta se hace por el wizard, nunca por SQL |
| T-182-32 | Denial of Service | Regresión de El Templo en producción | mitigate | Staging-first estricto + UAT de no-regresión aprobado antes de tocar prod + rollback de una sola variable (`PLATFORM_DOMAIN` vacío) documentado y probado |
| T-182-20b | Information Disclosure | Contraseñas del super-owner y del owner del demo | mitigate | Ingresadas por stdin o mostradas una única vez en la UI; prohibido escribirlas en el repo, en el SUMMARY o en un log |
</threat_model>
