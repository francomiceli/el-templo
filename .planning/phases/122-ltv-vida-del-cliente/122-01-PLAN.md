  <behavior>
    Input: one observation per customer, `{ durationMonths: number; event: boolean }` where `event=true` = life closed (churned), `event=false` = censored (still active / in-grace).
    Algorithm: stepwise survival S(t) = Π (1 − d_i / n_i) over distinct event times in ascending order, where d_i = events at time t_i and n_i = at-risk count (observations with duration >= t_i). Return the FIRST event time t where S(t) <= 0.5 (the median survival). Curve is NOT returned (deferred, D-122-05).
    Test cases (D-122-06 — ALL required):
    - Test 1 (events, no censoring): all-closed cohort with durations [1,2,3,4] -> median = the first month where survival <= 0.5 (assert exact value, e.g. 3).
    - Test 2 (censoring matters): a cohort mixing closed + censored where the at-risk denominator changes because censored observations leave the risk set without being events -> assert the median differs from a naive median-of-closed.
    - Test 3 (ties): multiple events at the same durationMonths collapse into one survival step (d_i > 1) -> assert correct single-step drop.
    - Test 4 (empty cohort): `[]` -> returns `null`.
    - Test 5 (single customer): one observation -> returns `null` (cannot establish a median, mirror `median` empty/insufficient guard).
    - Test 6 (never crosses 0.5): an all-censored / heavily-censored cohort where S(t) stays above 0.5 at every event time -> returns `null`.
  </behavior>
  <action>
    Create `kaplan-meier.ts` exporting a pure function `kaplanMeierMedian(observations: KaplanMeierObservation[]): number | null` and the `KaplanMeierObservation` interface (`durationMonths: number; event: boolean`). Export a named constant for the survival threshold (e.g. `SURVIVAL_MEDIAN_THRESHOLD = 0.5`). Implement the stepwise product-limit estimator per <behavior>: sort distinct event times ascending, fold the survival product over them, walk the steps and return the first event time whose running S(t) is `<= SURVIVAL_MEDIAN_THRESHOLD`; return `null` when the cohort is empty, has a single observation, or survival never reaches the threshold. Use `unknown`/typed inputs, no `any`. Write the test file FIRST (RED) covering all six cases in <behavior>, confirm it fails against an unimplemented helper, then implement to GREEN.
