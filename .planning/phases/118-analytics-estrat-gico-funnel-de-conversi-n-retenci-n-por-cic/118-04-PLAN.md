<objective>
Implementar la PROPUESTA #1: funnel de conversión `freemium → prueba → activo` con tiempos por
etapa. DEPENDE de los hooks de user_status_history del Plan 01 (sin ellos la etapa `prueba` no se
registra ni hacia adelante).

Decisiones LOCKED:

- D-01: funnel completo + caveat visual. Aproximar la etapa `activo` histórica con
  `MIN(subscriptions.created_at)` por usuario; las transiciones `prueba`/`inactivo` precisas solo
  existen forward-only desde 2026-05-26. Data histórica = aproximada; data confiable = forward-only.
  El backend devuelve la data; el frontend (Plan 06) muestra el caveat de ramp-up.
- D-03: cohorte del funnel = mes de alta (`users.created_at`). Por cohorte: % a prueba, % a activo,
  mediana de días freemium→prueba y prueba→activo. Corte por sede y país (applyScope).
- D-11: endpoint SENSIBLE → ADMIN_ROLES con requireAdminAnalytics.
- D-12: test de integración obligatorio contra MySQL real.

Domain service NUEVO. NO tocar el monolito analytics/service.ts (v4.9).

Purpose: ver dónde se cae el embudo (marketing / clase de prueba / onboarding).
Output: FunnelService + endpoint + tipos/schema + test.
</objective>
