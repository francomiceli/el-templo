**Program CRUD methods:**

1. `async createProgram(input: CreateProgramInput): Promise<number>` — Inserts into micro_programs, then bulk-inserts content blocks. Returns program id. Use a transaction.

2. `async listPrograms(): Promise<MicroProgram[]>` — SELECT all programs (both active and inactive) ordered by createdAt DESC. Admin sees all.

3. `async getProgramDetail(programId: number): Promise<MicroProgramDetail | null>` — SELECT program + LEFT JOIN content_blocks (ordered by weekNumber ASC, sortOrder ASC) + COUNT active enrollments. For exercise-type blocks, LEFT JOIN exercises table to get exerciseName (exercises.exercise column) and exerciseVideoUrl (construct via assembleVideoUrl helper or just return the exercise ID for the client to resolve — use the simpler approach of just returning exerciseId and the joined exercise name from exercises.exercise).

4. `async updateProgram(programId: number, input: UpdateProgramInput): Promise<void>` — UPDATE micro_programs fields. Per D-41: if name/description/price/auraWeeklyBonus/auraCompletionBonus are provided, update them. durationWeeks is NOT in UpdateProgramInput by design.

5. `async addContentBlocks(programId: number, blocks: ContentBlockInput[]): Promise<void>` — Bulk insert new content blocks for a program (per D-41: admin can add content to future weeks).

6. `async deactivateProgram(programId: number): Promise<void>` — SET isActive=false. Per D-43: existing active enrollments run to completion.

**Enrollment methods:**

7. `async enrollMember(input: EnrollMemberInput): Promise<number>` — Per D-06: check no existing active enrollment for this user (SELECT WHERE userId=input.userId AND status='active'). If found, throw error "Member already has an active program enrollment". Insert into program_enrollments with status='active', currentWeek=1, sessionsCompletedThisWeek=0. Returns enrollment id.

8. `async cancelEnrollment(enrollmentId: number): Promise<void>` — Per D-29: set status='cancelled', cancelledAt=now(). Only if current status is 'active'.

9. `async advanceWeek(enrollmentId: number): Promise<void>` — Per D-42: manual admin override. Load enrollment, increment currentWeek by 1, reset sessionsCompletedThisWeek to 0, set weekUnlockedAt=now(). If new currentWeek > program.durationWeeks, set status='completed', completedAt=now().

10. `async getEnrollmentsByUser(userId: number): Promise<ProgramEnrollment[]>` — SELECT enrollments joined with micro_programs for programName, durationWeeks, sessionsPerWeekToAdvance. Order by: active first, then by enrolledAt DESC.

11. `async getActiveEnrollment(userId: number): Promise<ProgramEnrollment | null>` — SELECT single enrollment WHERE userId AND status='active', joined with program.

**Member-facing methods:**

12. `async getCatalog(): Promise<MemberProgramCatalogItem[]>` — SELECT active programs only (isActive=true). For hasContent: subquery checking if any content blocks exist for that program. Per D-46: programs with no content show "Proximamente".

13. `async getMemberProgress(userId: number): Promise<MemberEnrollmentProgress | null>` — Get active enrollment + joined program fields + content blocks for current week only. Calculate isWeekComplete (sessionsCompletedThisWeek >= sessionsPerWeekToAdvance). Calculate daysUntilExpiry: enrolledAt + (durationWeeks \* 7 days) - now. Include content blocks filtered to currentWeek, ordered by sortOrder ASC.

**Analytics method:**

14. `async getAnalytics(): Promise<ProgramAnalytics>` — Per D-40: COUNT total enrollments, COUNT WHERE status='active', COUNT WHERE status='completed'.

All methods use Drizzle ORM query builder (not raw SQL unless needed for complex joins). Use `this.log?.info(...)` / `this.log?.warn(...)` for logging (never console.log).

**Create `el-templo-api/src/modules/programs/routes.ts`:**

Follow the established route module pattern (see subscriptions/routes.ts, onboarding/routes.ts). Export a `programRoutes` Fastify plugin function.

Inside the plugin:

- Instantiate `ProgramsService` with `fastify.db` and `fastify.log`
- Define Fastify JSON schemas for request validation

**Admin routes** (all require `fastify.authenticate` + role check against `ADMIN_ROLES` from shared/permissions.ts, EXCEPT enrollment management which uses `COACH_ROLES` per D-35):

1. `POST /admin/programs` — Create program. Body: CreateProgramInput shape. Returns `{ id: number }`. Role: ADMIN_ROLES.

2. `GET /admin/programs` — List all programs. Returns `{ programs: MicroProgram[] }`. Role: ADMIN_ROLES.

3. `GET /admin/programs/:programId` — Program detail with content blocks. Returns MicroProgramDetail. Role: ADMIN_ROLES.

4. `PUT /admin/programs/:programId` — Update program. Body: UpdateProgramInput. Returns `{ success: true }`. Role: ADMIN_ROLES.

5. `POST /admin/programs/:programId/content` — Add content blocks to program. Body: `{ blocks: ContentBlockInput[] }`. Returns `{ success: true }`. Role: ADMIN_ROLES.

6. `POST /admin/programs/:programId/deactivate` — Deactivate program. Returns `{ success: true }`. Role: ADMIN_ROLES.

7. `POST /admin/programs/enroll` — Enroll member. Body: EnrollMemberInput. Returns `{ enrollmentId: number }`. Role: COACH_ROLES (per D-35: coaches can enroll members they coach).

8. `POST /admin/programs/enrollments/:enrollmentId/cancel` — Cancel enrollment. Returns `{ success: true }`. Role: COACH_ROLES.

9. `POST /admin/programs/enrollments/:enrollmentId/advance` — Advance week. Returns `{ success: true }`. Role: COACH_ROLES.

10. `GET /admin/programs/enrollments/user/:userId` — Get enrollments for a user. Returns `{ enrollments: ProgramEnrollment[] }`. Role: COACH_ROLES.

11. `GET /admin/programs/analytics` — Program analytics. Returns ProgramAnalytics. Role: ADMIN_ROLES.

**Member routes** (require `fastify.authenticate`, member role):

12. `GET /members/programs/catalog` — Active program catalog. Returns `{ programs: MemberProgramCatalogItem[] }`.

13. `GET /members/programs/my-progress` — Active enrollment progress. Returns MemberEnrollmentProgress or 204 No Content if no active enrollment (follow the onboarding/routes.ts 204 pattern).

**Role checking pattern** — Use the same pattern as other admin routes:

```typescript
const { role } = request.user;
if (!(ADMIN_ROLES as readonly string[]).includes(role)) {
  return reply.status(403).send({ error: "Forbidden" });
}
```

Wrap all route handlers in try/catch with `handleServiceError(request, reply, err)` from shared/error-handler.ts.
