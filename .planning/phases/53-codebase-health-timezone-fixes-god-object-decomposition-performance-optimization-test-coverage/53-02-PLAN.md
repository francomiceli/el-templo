  <name>Task 1: Fix N+1 query in getWeeklyGrid</name>
  <files>el-templo-api/src/modules/scheduling/service.ts</files>
  <action>
    In `getWeeklyGrid()` method (starts around line 215), there is a loop at lines ~294-310 that fires a separate COUNT query for each schedule row:

    ```typescript
    for (const row of scheduleRows) {
      const slotDate = this.addDays(weekStartDate, row.dayOfWeek - 1);
      const [countResult] = await this.db
        .select({ count: sql`COUNT(*)` })
        .from(schema.bookings)
        .where(and(
          eq(schema.bookings.scheduleId, row.id),
          eq(schema.bookings.bookingDate, slotDate),
          eq(schema.bookings.status, "confirmed"),
        ));
      const bookedCount = Number(countResult?.count ?? 0);
      // ... push to slots
    }
    ```

    Replace this N+1 pattern with a single GROUP BY query BEFORE the loop:

    1. Collect all schedule IDs from `scheduleRows`: `const scheduleIds = scheduleRows.map(r => r.id);`

    2. If scheduleIds is empty, skip the query (empty week).

    3. Run a single query using `GROUP BY scheduleId, bookingDate`:
       ```typescript
       const bookingCounts = await this.db
         .select({
           scheduleId: schema.bookings.scheduleId,
           bookingDate: schema.bookings.bookingDate,
           count: sql<number>`COUNT(*)`,
         })
         .from(schema.bookings)
         .where(
           and(
             inArray(schema.bookings.scheduleId, scheduleIds),
             eq(schema.bookings.status, "confirmed"),
           ),
         )
         .groupBy(schema.bookings.scheduleId, schema.bookings.bookingDate);
       ```

    4. Build a lookup Map: `Map<string, number>` keyed by `"${scheduleId}-${bookingDate}"`.

    5. In the loop, replace the per-row query with a Map lookup:
       ```typescript
       const slotDate = addDays(weekStartDate, row.dayOfWeek - 1);
       const bookedCount = bookingCountMap.get(`${row.id}-${slotDate}`) ?? 0;
       ```

    NOTE: `addDays` may still be `this.addDays` if Plan 01 hasn't run yet (they're Wave 1 parallel). If so, use the existing private method. The Plan 01 executor will replace it. Both plans touch different methods in the same file — Plan 01 touches date utility methods + isWithinBookingWindow/isWithinCancelWindow; Plan 02 touches getWeeklyGrid. No conflict.

    Also add `inArray` to the import from `drizzle-orm` if not already imported (check line ~10).

  </action>
