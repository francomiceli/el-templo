# Phase 158 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Scope note:** this phase is the VISIBILITY layer of the referral program (v5.5). It only READS and COMMUNICATES what Phase 157 shipped (`referrals` / `referral_credits`, `users.referralCode` / `referredBy`, `ReferralService.compute…`, config 10% / cap 40%). It must NOT touch attribution, qualification or discount math. Three new surfaces: (S1) member-app `MisReferidosPage`, (S2) the `ProfilePage` entry point that reaches it, (S3) an admin "Referidos" section in the student ficha; plus (S4) one push-notification copy contract. Everything reuses existing Quasar components and brand tokens verbatim — no new visual pattern is introduced. All decisions here are pre-populated from `158-CONTEXT.md` (D-26..D-37) and inherited from `157-UI-SPEC.md`.

## Typography

### S1/S2 — App (dark surface)

| Role                              | Size            | Weight | Line Height | Notes                                                                                         |
| --------------------------------- | --------------- | ------ | ----------- | --------------------------------------------------------------------------------------------- |
| Discount headline ("X% menos")    | 1.5rem (24px)   | 700    | 1.2         | Montserrat — display size, shared with the code value                                         |
| Code value                        | 1.5rem (24px)   | 700    | 1.2         | Montserrat, `letter-spacing: 0.1em` — SAME display size as the headline (single display step) |
| Section title ("Trajiste a" etc.) | 1rem (16px)     | 600    | 1.2         | Montserrat — reuse `.section-title` from `ProfilePage.vue` verbatim                           |
| Body / vínculo names / breakdown  | 0.875rem (14px) | 400    | 1.5         | Geologica (`$body-font-size: 14px`, `$body-line-height: 1.5`)                                 |
| Caption ("se reactiva si vuelve") | 0.75rem (12px)  | 400    | 1.4         | Geologica, muted (`text-grey-6` on dark → `rgba($cream,0.6)`), reuse `q-item-label caption`   |

**Sizes in play (typography budget — 4 sizes):** 12 (caption) / 14 (body) / 16 (section title) / 24 (display — discount headline AND code value share this single step). Do NOT introduce a fifth size.

**Weights in play (typography budget — 2 weights):** 400 (regular — body/names/breakdown/captions) + 700 (bold — discount headline + code). **Inherited exception — EXEMPT from budget:** the 600 weight on `.section-title` is reused verbatim from the already-shipped `ProfilePage.vue` style; this phase does not introduce it and its scope forbids editing that rule, so it does not count as a new typographic decision.

## Interaction Contracts

### S1 — MisReferidosPage (top-to-bottom, per D-27)

**Route:** new `/mis-referidos`, member-authenticated. Data source: `GET /members/referrals` (D-30) → `{ referralCode, discount: { percent, activeCount, perLinkPercent, capPercent }, broughtByMe: [...], broughtMeIn?: {...} }` (exact shape owned by planning). All numbers (per-link %, cap) come from config — NEVER hardcode.

**Block 1 — Code + Share (always visible, even with zero vínculos — this screen IS the diffusion tool):**

- Card (secondary surface) with `card_giftcard` icon (terracotta), eyebrow "TU CÓDIGO", the code value prominent (700 / 24px display size / `letter-spacing 0.1em`), and a primary `q-btn` "Compartir mi código".
- Share = native Capacitor share, dynamic-imported exactly like `bar-challenge/Resultado.vue:217-219`: `Share.share({ title, text, url })` where `url` = public registration URL + `?ref={referralCode}` (URL base owned by planning). Fallback on share rejection: copy the link to clipboard + `$q.notify` warning (mirror the Resultado fallback pattern).

**Block 2 — Current discount (pedagogical, D-27.2 + Specifics):**

- Card with headline "Estás pagando {percent}% menos" (terracotta number, 700/24px) when `percent > 0`.
- Below it, an explicit breakdown line reading the config values: "{activeCount} vínculos activos × {perLinkPercent}% = {percent}% (tope {capPercent}%)". The member must understand WHY they pay what they pay.
- When `percent === 0`: headline reads "Todavía no tenés descuento activo" and the breakdown line is replaced by the empty-state guidance copy (see Copywriting).

**Block 3 — Vínculos list (symmetric, D-29):**

- Two sections, each with a `.section-title`: "Trajiste a" (links where I am referrer) and "Te trajo" (the single link where I am referred, if any). Show a section only if it has ≥1 vínculo.
- Each row: member full name (14px/400) + a right-aligned `q-chip` with the derived state (Pendiente / Activo / Suspendido). Suspendido rows show a 12px caption "se reactiva si vuelve".

**States:**
| State | Behavior |
|-------|----------|
| Loading | `TemploLoader` centered (reuse existing loader), no skeleton needed |
| Loaded, has vínculos | Blocks 1-3 as above |
| Loaded, zero vínculos | Block 1 (code + share) stays prominent; Block 2 shows the 0% headline; Block 3 replaced by the empty state (see copy) |
| Load error | Full-page retry: `$q.notify` negative + inline "Reintentar" button that re-fetches |

**Hard rule:** the code + Share button render even before/without any vínculo — this is the marketing surface; it must never be hidden behind an empty state.

### S2 — ProfilePage entry

- Add one `settings-card__item settings-card__item--clickable` (clone of the "Cambiar contraseña" item `:73-78`) inside the existing "Ajustes" settings card: icon `card_giftcard` (terracotta), label "Mis referidos", trailing `chevron_right`, `@click="$router.push('/mis-referidos')"`.
- No new visual pattern — reuse the divider + item markup already in the card.

### S3 — Admin MemberReferralsTab

- New `q-tab name="referidos" label="Referidos"` after "Perfil" in `AlumnoDetailPage.vue:340`, with a `q-tab-panel name="referidos"` rendering `MemberReferralsTab.vue`. (Planner may instead fold this into a card at the bottom of the "Perfil" tab if it prefers fewer tabs — the visual contract below applies either way.)
- Two subsections mirroring the app's symmetry: "Lo trajo" (single referrer, if any — full name as a terracotta link routing to that member's ficha) and "Trajo a" (list — each name links to its ficha). Each row carries the same derived-state chip (Pendiente / Activo / Suspendido) as S1.
- Derived state comes from the SAME `deriveCoveredUntil` criterion the discount uses — never `users.status` (D-28).

**States:**
| State | Behavior |
|-------|----------|
| Loading | Quasar spinner (`color="primary"`) centered in the panel |
| Has data | Two subsections as above; only render a subsection with ≥1 vínculo |
| No referrals at all | Single muted `text-caption` line: "Este alumno no tiene referidos." |
| Load error | Existing negative toast via `extractError` (module pattern), no new inline error UI |

### S4 — Push notification "vínculo activado" (VIS-02 / D-31, D-32, D-33)

- New category `referidos` in `notificationCategoryEnum` (enum migration, verify next free number at plan time; CONTEXT tentatively said 0177+) + template in `seedTemplates()` + granular opt-out preference like every other category.
- Fired to the REFERRER only, at the flip to `qualified` inside `ReferralService.qualifyFirstPayment`, via the existing `queueNotification`. Best-effort: a notification failure NEVER breaks the charge (same criterion as the rest of the queue). The referred member gets NO push (they already see the discount on their first charge).
