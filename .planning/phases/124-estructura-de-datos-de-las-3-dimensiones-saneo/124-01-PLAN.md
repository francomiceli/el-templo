<objective>
Crear la ESTRUCTURA de datos de las 3 dimensiones de dificultad (gesto/sub-familia, palanca/posición, contracción) sobre el catálogo de ejercicios, separándolas del campo `position` sucio, y preparar los punteros/marcadores que el saneo (Plan 02) y las fases siguientes (125 bootstrap, 126 grafo, 129 Kairos) van a usar.

Esta es la fase 0 / bedrock del milestone v5.1. Cubre **TREE-01** (las 3 dimensiones como datos estructurados). Backend-first, NO frontend.

Purpose: Sin columnas/relaciones propias para las dimensiones, el bootstrap LLM (125) no tiene dónde escribir y el grafo (126) no tiene nodos que leer. `position` mezcla palanca + implemento + orientación y no sirve como dato estructurado.

Output:

- Tabla catálogo `exercise_subfamilies` (D-01).
- Columnas nuevas en `exercises`: `subfamily_id` (FK nullable a la sub-familia), `leverage` (varchar nullable, NO enum global — D-03/D-05), `canonical_exercise_id` (self-FK nullable para soft-merge — D-07), y un marcador `route_pending` para la detección de "sin ruta" (D-08).
- Migración hand-written `0137` aditiva, idempotente y reversible (D-11/D-12).

NO incluye: poblar las dimensiones (125), construir el grafo (126), tocar `position`/`effort`/`level`/`dificultadLineal`, ni el editor (128). La población del saneo (escritura de punteros canónicos + marcado de ruta) es el Plan 02.
