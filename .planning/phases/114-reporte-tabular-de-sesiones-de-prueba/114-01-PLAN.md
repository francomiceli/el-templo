    **Step B — Hand-write fallback** (likely needed because drizzle-kit journal is at 0059 vs DB at 0120):
    Create `el-templo-api/src/db/migrations/0121_users_lead_fields.sql` with this exact content (note: every `--` comment line has NO `;`):

    ```sql
    -- Phase 114 Plan 01 (D-15, D-16, D-17, D-18)
    -- Adds lead lifecycle fields to users
    --   lead_status   ENUM nullable, no default; explicit at insert time
    --   lead_notes    TEXT nullable
    --   created_by    INT nullable, FK -> users.id ON DELETE SET NULL
    -- Plus two indexes for filter performance
    --
    -- Idempotent via IF NOT EXISTS guards on columns and indexes
    -- (MySQL 8 supports IF NOT EXISTS on ADD COLUMN/INDEX in recent versions
    -- runner is single-statement-per-execution, splits on semicolons)

    ALTER TABLE users
      ADD COLUMN lead_status ENUM('en_seguimiento','cerrado','perdido') NULL DEFAULT NULL AFTER converted_at;

    ALTER TABLE users
      ADD COLUMN lead_notes TEXT NULL DEFAULT NULL AFTER lead_status;

    ALTER TABLE users
      ADD COLUMN created_by INT NULL DEFAULT NULL AFTER lead_notes;

    -- FK constraint: name matches Drizzle's auto-generated convention
    -- (users_created_by_users_id_fk) so pnpm db:generate output and this
    -- hand-written SQL converge. If Drizzle's convention differs in this
    -- project version, rename here to match what drizzle-kit would emit.
    ALTER TABLE users
      ADD CONSTRAINT users_created_by_users_id_fk
      FOREIGN KEY (created_by) REFERENCES users(id) ON DELETE SET NULL;

    CREATE INDEX idx_users_lead_status ON users(lead_status);

    CREATE INDEX idx_users_created_by ON users(created_by);
    ```

    Notes:
    - DO NOT use `IF NOT EXISTS` on ADD COLUMN / CREATE INDEX inline — MySQL support is version-flaky AND the project pattern (see 0108/0111) is to rely on the `_migrations` row to guarantee single execution. Idempotency at the runner level, not statement level.
    - DO NOT put `;` inside any `-- ...` comment line (project runner split bug — user memory `feedback_no_semicolon_in_sql_comments`).
    - Every statement terminates with a single `;` on its own (no trailing whitespace tricks).

    **Step C — Apply locally:**
    From `el-templo-api/`, run `pnpm db:migrate` against the local dev DB. Verify the runner exits 0 and reports `0121_users_lead_fields.sql applied`.

    **Step D — Local DB sanity:**
    Run `mysql ${DATABASE_URL_LOCAL} -e "SHOW COLUMNS FROM users LIKE 'lead_%'; SHOW COLUMNS FROM users LIKE 'created_by'; SHOW INDEX FROM users WHERE Key_name IN ('idx_users_lead_status','idx_users_created_by');"` (or equivalent connect-string call) and confirm the 3 columns + 2 indexes exist.

    **Step E — Commit:**
    Stage `users.ts` + `0121_users_lead_fields.sql` together. DO NOT push.
