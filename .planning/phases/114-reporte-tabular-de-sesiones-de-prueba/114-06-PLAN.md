  <name>[BLOCKING] Decide how to populate the "Gestiona" SELECT for non-owner admins (D-36)</name>
  <decision>
    The CONTEXT D-36 contract is: "Gestiona filter must be a SELECT populated with admins/gestion/owner". The existing `useUsersApi.fetchStaff` calls `GET /admin/users` which is OWNER-ONLY (`el-templo-api/src/modules/users/routes.ts:24-28`). This report is gated on CAJA_ROLES (D-25 — owner + admin + gestion). For admin/gestion users, calling fetchStaff returns 403 and the SELECT cannot be populated.

    The executor MUST pause here and surface this conflict to the user BEFORE writing the UI. A fallback to a numeric input violates D-36 and is explicitly prohibited (per the revision feedback).

  </decision>
  <context>
    D-36 (CONTEXT.md locked): "select poblada con admins/gestion/owner". A numeric input is NOT a valid degradation — it does not surface the names of staff and is not what receptionists/admins expect from a "Gestiona" filter.

  <options>
    <option id="option-a">
      <name>Widen GET /admin/users to CAJA_ROLES (read-only)</name>
      <pros>Minimal API surface; reuses existing endpoint; existing fetchStaff in useUsersApi works unchanged.</pros>

      <name>Add a new minimal-projection endpoint GET /api/admin/users/staff-options for CAJA_ROLES</name>
      <pros>Tightly scoped: returns only { userId, name } for users with role in (admin, gestion, owner). No PII beyond name. Clean separation of concerns.</pros>
      <cons>Adds a new endpoint (must include schema + tests + route registration). Slightly larger plan diff. Add as a NEW task in Plan 06 OR push to Plan 04 (leads-routes is the natural home).</cons>
    </option>
    <option id="option-c">
      <name>Owner-only Gestiona filter (hide the SELECT for non-owners)</name>
      <pros>Zero new API work. Keeps D-36 satisfied for the user role most likely to use cross-branch reporting (owner).</pros>
      <cons>Violates D-36 letter for admin/gestion. Non-owners get no Gestiona filter at all (cannot filter by which admin created which lead). Reduces utility of the report for the day-to-day operator persona.</cons>
    </option>
  </options>

    ```ts
    async function fetchTrialSessions(
      filters: TrialSessionsFiltersClient,
    ): Promise<{ rows: TrialSessionsRowClient[]; total: number; page: number; limit: number }> {
      const params = buildTrialSessionsParams(filters); // strips undefined
      const { data } = await api.get("/api/admin/reports/trial-sessions", { params });
      return data;
    }

    function exportTrialSessionsUrl(filters: TrialSessionsFiltersClient): string {
      const usp = new URLSearchParams();
      // serialize: skip undefined, leadStatus as repeated keys
      for (const [k, v] of Object.entries(filters)) {
        if (v === undefined || v === null || v === "") continue;
        if (Array.isArray(v)) v.forEach((vv) => usp.append(k, String(vv)));
        else usp.append(k, String(v));
      }
      return `/api/admin/reports/trial-sessions/export?${usp.toString()}`;
    }
    ```
