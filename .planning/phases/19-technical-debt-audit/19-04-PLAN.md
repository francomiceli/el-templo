<objective>
Harden the CI pipeline with lint gates (errors block, warnings pass), API integration tests with MySQL service container, and security audit checks. Harden the deploy pipeline with pre-deploy backup, post-deploy smoke test, and automatic rollback on health check failure.

Purpose: Currently CI has `continue-on-error: true` on linting (meaning lint errors are ignored), no tests run in CI, and deployment is one-way with no rollback capability. A bad deploy destroys the previous build via rsync --delete. These changes make the pipeline catch real problems before they reach production, and recover automatically when they do.
Output: Updated ci.yml with test + lint + audit gates. Updated deploy.yml with backup + smoke test + auto-rollback.
</objective>

  <action>
    Modify `.github/workflows/deploy.yml` to add deploy safety:

    1. **Make deploy depend on CI passing.** The deploy workflow currently runs on push to master. It should either:
       - Add the same build/test jobs inline, OR
       - Reference the CI workflow using `workflow_run` trigger, OR
       - Simply add test execution to the existing build jobs.
       Simplest approach: add `pnpm test` step to the build-api job (after build, before upload artifact). This ensures tests pass before deploy artifact is created.

    2. **Add backup step** before deployment in the `deploy` job. Insert BEFORE the rsync deploy steps:
       ```yaml
       - name: Backup current deployment
         run: |
           ssh ${{ secrets.SSH_USER }}@${{ secrets.SERVER_HOST }} << 'ENDSSH'
             # Backup API
             if [ -d "${{ secrets.API_DEPLOY_PATH }}" ]; then
               rm -rf ${{ secrets.API_DEPLOY_PATH }}.previous
               cp -r ${{ secrets.API_DEPLOY_PATH }} ${{ secrets.API_DEPLOY_PATH }}.previous
             fi
             # Backup App
             if [ -d "${{ secrets.APP_DEPLOY_PATH }}" ]; then
               rm -rf ${{ secrets.APP_DEPLOY_PATH }}.previous
               cp -r ${{ secrets.APP_DEPLOY_PATH }} ${{ secrets.APP_DEPLOY_PATH }}.previous
             fi
             # Backup Admin
             if [ -d "${{ secrets.ADMIN_DEPLOY_PATH }}" ]; then
               rm -rf ${{ secrets.ADMIN_DEPLOY_PATH }}.previous
               cp -r ${{ secrets.ADMIN_DEPLOY_PATH }} ${{ secrets.ADMIN_DEPLOY_PATH }}.previous
             fi
           ENDSSH
       ```

    3. **Enhance the existing health check** (currently at end of deploy job, "Verify deployment" step). Replace the current soft check with a hard check + rollback:
       ```yaml
       - name: Post-deploy smoke test
         run: |
           sleep 10
           API_BASE=$(echo "${{ secrets.VITE_API_URL }}" | sed 's|/api$||')
           HTTP_CODE=$(curl -s -o /dev/null -w "%{http_code}" ${API_BASE}/health || echo "000")
           if [ "$HTTP_CODE" != "200" ]; then
             echo "::error::Health check FAILED (HTTP $HTTP_CODE). Rolling back..."
             ssh ${{ secrets.SSH_USER }}@${{ secrets.SERVER_HOST }} << 'ENDSSH'
               # Restore previous API
               if [ -d "${{ secrets.API_DEPLOY_PATH }}.previous" ]; then
                 rm -rf ${{ secrets.API_DEPLOY_PATH }}
                 mv ${{ secrets.API_DEPLOY_PATH }}.previous ${{ secrets.API_DEPLOY_PATH }}
               fi
               # Restore previous App
               if [ -d "${{ secrets.APP_DEPLOY_PATH }}.previous" ]; then
                 rm -rf ${{ secrets.APP_DEPLOY_PATH }}
                 mv ${{ secrets.APP_DEPLOY_PATH }}.previous ${{ secrets.APP_DEPLOY_PATH }}
               fi
               # Restore previous Admin
               if [ -d "${{ secrets.ADMIN_DEPLOY_PATH }}.previous" ]; then
                 rm -rf ${{ secrets.ADMIN_DEPLOY_PATH }}
                 mv ${{ secrets.ADMIN_DEPLOY_PATH }}.previous ${{ secrets.ADMIN_DEPLOY_PATH }}
               fi
               cd ${{ secrets.API_DEPLOY_PATH }}
               pnpm install --prod --frozen-lockfile
               pm2 restart eltemplo-api --update-env
             ENDSSH
             exit 1
           fi
           echo "Health check PASSED (HTTP $HTTP_CODE)"
       ```

    4. **Add test step to build-api job** -- after the Build step and before Upload artifact:

    Note on rollback and migrations: Per RESEARCH.md Pitfall 5, database migrations should be backward-compatible (additive only). The rollback restores previous code, which should still work with the new schema. Document this constraint in the runbook (Plan 09).
  </action>
