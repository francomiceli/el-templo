    Create two shell scripts in the deploy/ directory:

    **deploy/backup.sh** -- Automated backup with rotation and cloud archival:
    ```bash
    #!/bin/bash
    # El Templo - Automated MySQL Backup
    # Usage: ./backup.sh
    # Cron: 0 6 * * * /path/to/deploy/backup.sh >> /var/log/eltemplo-backup.log 2>&1
    # (06:00 UTC = 03:00 Argentina time)
    set -euo pipefail

    # Configuration (override via environment)
    DB_NAME="${DB_NAME:-eltemplo}"
    DB_USER="${DB_USER:-root}"
    DB_PASSWORD="${DB_PASSWORD:?DB_PASSWORD must be set}"
    BACKUP_DIR="${BACKUP_DIR:-/var/backups/mysql}"
    RETENTION_DAYS="${RETENTION_DAYS:-7}"
    BUCKET="${BACKUP_BUCKET:-s3://eltemplo-backups}"
    TIMESTAMP=$(date +%Y%m%d_%H%M%S)
    BACKUP_FILE="${BACKUP_DIR}/${DB_NAME}_${TIMESTAMP}.sql.gz"

    # Ensure backup directory exists
    mkdir -p "$BACKUP_DIR"

    echo "[$(date)] Starting backup of database: $DB_NAME"

    # Create compressed backup
    # --single-transaction: consistent snapshot without locking (InnoDB)
    # --quick: retrieve rows one at a time (reduces memory)
    # --lock-tables=false: don't lock tables (use single-transaction instead)
    mysqldump -u "$DB_USER" -p"$DB_PASSWORD" "$DB_NAME" \
      --single-transaction --quick --lock-tables=false | gzip > "$BACKUP_FILE"

    BACKUP_SIZE=$(du -h "$BACKUP_FILE" | cut -f1)
    echo "[$(date)] Backup created: $BACKUP_FILE ($BACKUP_SIZE)"

    # Delete local backups older than retention period
    DELETED=$(find "$BACKUP_DIR" -name "${DB_NAME}_*.sql.gz" -mtime +${RETENTION_DAYS} -delete -print | wc -l)
    echo "[$(date)] Deleted $DELETED old backups (older than $RETENTION_DAYS days)"

    # Upload to cloud storage (AWS S3)
    if command -v aws &> /dev/null && aws sts get-caller-identity &> /dev/null; then
      aws s3 cp "$BACKUP_FILE" "${BUCKET}/" --quiet
      echo "[$(date)] Uploaded to S3: ${BUCKET}/$(basename "$BACKUP_FILE")"
    else
      echo "[$(date)] Cloud upload skipped (aws CLI or AWS credentials not configured)"
    fi

    echo "[$(date)] Backup complete"
    ```

    **deploy/restore.sh** -- Restore from backup:
    ```bash
    #!/bin/bash
    # El Templo - Database Restore from Backup
    # Usage: ./restore.sh /var/backups/mysql/eltemplo_20260214_060000.sql.gz
    set -euo pipefail

    if [ $# -eq 0 ]; then
      echo "Usage: $0 <backup-file.sql.gz>"
      echo ""
      echo "Available backups:"
      ls -la ${BACKUP_DIR:-/var/backups/mysql}/eltemplo_*.sql.gz 2>/dev/null || echo "No backups found"
      exit 1
    fi

    BACKUP_FILE="$1"
    DB_NAME="${DB_NAME:-eltemplo}"
    DB_USER="${DB_USER:-root}"
    DB_PASSWORD="${DB_PASSWORD:?DB_PASSWORD must be set}"

    if [ ! -f "$BACKUP_FILE" ]; then
      echo "Error: Backup file not found: $BACKUP_FILE"
      exit 1
    fi

    echo "WARNING: This will REPLACE the current '$DB_NAME' database with the backup."
    echo "Backup file: $BACKUP_FILE"
    echo "Press Ctrl+C to cancel, or wait 5 seconds to continue..."
    sleep 5

    echo "[$(date)] Restoring database from: $BACKUP_FILE"

    # Restore: decompress and pipe to mysql
    gunzip -c "$BACKUP_FILE" | mysql -u "$DB_USER" -p"$DB_PASSWORD" "$DB_NAME"

    echo "[$(date)] Restore complete. Restart the API to pick up any changes."
    echo "Run: pm2 restart eltemplo-api"
    ```

    Make both scripts executable: `chmod +x deploy/backup.sh deploy/restore.sh`

    AWS S3 for cloud storage (user already on AWS). The backup script uses aws CLI with standard S3 commands. Cloud upload is optional -- gracefully skips if aws CLI or AWS credentials are not configured.

  <action>
    Create `deploy/RUNBOOK.md` documenting common production incident scenarios with step-by-step resolution. The runbook is for the solo developer (Franco) to reference under pressure when something breaks.

    **Sections:**

    **1. Quick Reference**
    - SSH access: `ssh user@server`
    - API path on server: reference to GitHub secrets
    - PM2 commands: `pm2 status`, `pm2 restart eltemplo-api`, `pm2 logs eltemplo-api`
    - Nginx: `sudo systemctl status nginx`, `sudo nginx -t`, `sudo systemctl reload nginx`
    - MySQL: `sudo systemctl status mysql`, `mysql -u root -p`

    **2. API Down (HTTP 502/503)**
    - Check PM2: `pm2 status` -- is eltemplo-api running?
    - Check logs: `pm2 logs eltemplo-api --lines 50`
    - Restart: `pm2 restart eltemplo-api --update-env`
    - If still down: check if port is in use, check Node.js errors in logs
    - Nuclear option: `pm2 delete eltemplo-api && cd /path/to/api && NODE_ENV=production pm2 start dist/index.js --name eltemplo-api`

    **3. Database Connection Lost**
    - Check MySQL: `sudo systemctl status mysql`
    - Restart MySQL: `sudo systemctl restart mysql`
    - Check API can connect: `pm2 restart eltemplo-api` (reconnects on restart)
    - Check disk space: `df -h` (MySQL crashes when disk is full)
    - Check MySQL logs: `sudo tail -50 /var/log/mysql/error.log`

    **4. App Not Loading (Frontend)**
    - Check Nginx: `sudo nginx -t && sudo systemctl status nginx`
    - Check if files exist: `ls /path/to/app/dist/`
    - Check Nginx error log: `sudo tail -50 /var/log/nginx/error.log`
    - Hard refresh: tell users to clear cache (Ctrl+F5)
    - If corrupted deploy: rollback (see section 6)

    **5. Failed Deploy**
    - CI will auto-rollback if health check fails (Plan 04)
    - Manual rollback: restore .previous directories
    - Investigate: check GitHub Actions logs for the failed deploy

    **6. Database Corruption / Data Loss**
    - Stop API: `pm2 stop eltemplo-api`
    - Find latest backup: `ls -la /var/backups/mysql/eltemplo_*.sql.gz`
    - Restore: `./deploy/restore.sh /var/backups/mysql/eltemplo_LATEST.sql.gz`
    - Restart: `pm2 restart eltemplo-api`
    - If no local backup: download from AWS S3

    **7. SSL Certificate Expired**
    - Check cert: `sudo certbot certificates`
    - Renew: `sudo certbot renew`
    - Reload Nginx: `sudo systemctl reload nginx`

    **8. High Memory / CPU Usage**
    - Check: `htop` or `top`
    - PM2 memory: `pm2 monit`
    - If API leaking: restart PM2, investigate logs

    **9. Secret Rotation Procedure**
    - JWT Secret: Update in GitHub secrets + server .env, deploy, users re-authenticate
    - DB Password: Update MySQL password first, then .env, then restart API
    - Never rotate during peak hours

    **10. Backup Verification**
    - Monthly: restore a backup to eltemplo_test database and verify data integrity
    - Check cron: `crontab -l | grep backup`

    **Important note on rollback and migrations:** Database migrations should be backward-compatible (additive only). Rolling back API code works because the old code can handle new columns/tables. Never do destructive migrations.
