Algoritmo, TODO dentro de un único `db.transaction` (protocolo paso 4, carga transaccional):

1. Primera pasada por entrada: buscar la fila global existente con `and(eq(gymExercises.tenantScopeKey, 0), eq(normalizedSql(gymExercises.nombreCanonico), normalizeSearchText(entry.nombreCanonico)))`. Si existe: UPDATE de todos los campos de ficha SIN tocar `status` (D-13: preserva el estado de revisión de los ya publicados) y sin tocar `tenant_id`. Si no existe: INSERT con `tenantId: null` literal —nunca `tenantValues`, que es para escrituras de tenant—, `status: "borrador"` (D-01) y `createdByUserId: null` (docblock del schema: NULL para el catálogo global sembrado por el equipo). En esta pasada `easierVariantExerciseId`/`harderVariantExerciseId` van NULL: las referencias pueden apuntar hacia adelante.
2. Construir el mapa nombre canónico normalizado → id con TODAS las filas globales tocadas.
3. Segunda pasada: resolver `easierVariant`/`harderVariant` contra el mapa y hacer el UPDATE de esas dos columnas; borrar e insertar en bloque los alias (usando `aliasRowsFor`, con `tenantId: null`) y las alternativas (`tenantId: null`, `alternativeExerciseId` resuelto por el mapa). Reemplazo en bloque, mismo criterio que `updateExercise`.
4. Si algún nombre referenciado no resuelve, acumularlo en `nombresNoResueltos` y abortar la transacción con un error que los liste (el validador del plan 01 ya debería haberlo frenado antes; esto es la red de seguridad).
5. Con `dryRun`, hacer todo el trabajo y abortar la transacción con un error centinela propio que el caller distingue y reporta como "dry-run OK, sin cambios".

CLI (`if (require.main === module)`): cargar env con dotenv igual que `run-migrations.ts`; aplicar el GUARD DE ENTORNO antes de conectar — abortar con exit 2 y mensaje explícito si `process.env.NODE_ENV === "production"` o si `DB_HOST` no es `localhost`/`127.0.0.1` (staging y prod comparten host MySQL remoto y la base de prod se llama `eltemplo` igual que la local: el nombre solo no alcanza como guard); obtener la `connection` con `createSingleConnection()` y construir el handle con `drizzle(connection, { schema, mode: "default" })` para que el tipo sea el mismo que consume el test; leer el dataset con `loadGymCatalogDataset()`; correr `validateGymCatalogDataset` y ABORTAR con exit 1 si el reporte no está `ok` (nunca cargar un dataset inválido); ejecutar `loadCatalogIntoDb`; imprimir el reporte con conteos; cerrar la conexión en `finally`. Exit codes: 0 OK, 1 dataset inválido o carga fallida, 2 entorno/uso inválido.

Agregar a `package.json`: `"db:load-gym-catalog": "tsx src/db/scripts/load-gym-catalog-dataset.ts"`. Sin `console.log` fuera del wrapper CLI, sin `any`, `catch (err: unknown)` con `instanceof Error`.
