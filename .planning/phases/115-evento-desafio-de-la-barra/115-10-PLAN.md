<!-- Estado del pipeline iOS. -->

iOS build proceso típico para apps Capacitor:

1. `pnpm build` (web)
2. `pnpm exec cap sync ios`
3. Abrir Xcode workspace: `el-templo-app/src-capacitor/ios/App/App.xcworkspace`
4. Seleccionar target App, scheme App, destination "Any iOS Device (arm64)"
5. Product → Archive
6. Xcode Organizer → Distribute App → App Store Connect → Upload (auto-managed signing si está habilitado, sino manual)
7. Esperar processing (~15-30 min) → aparece en TestFlight
8. Smoke test desde TestFlight en device físico
9. App Store Connect → My Apps → El Templo → iOS App → Add for Review → Submit

**Pre-requisitos verificados en Plan 08:**

- MARKETING_VERSION = 1.5.0
- CURRENT_PROJECT_VERSION incrementado (build number)
- Plugins instalados, NSCameraUsageDescription en Info.plist

**Operador tiene que confirmar:**

- Cuenta Apple Developer activa, pagada al día.
- Certificate + Provisioning Profile válidos para "El Templo" bundle id.
- Acceso a Mac con Xcode (last stable).
- Acceso a App Store Connect.

**Si CI/CD tiene iOS pipeline:** verificar Phase 74-77 SUMMARYs (Play Store Setup) — STATE.md menciona Phase 76 está en progreso solo para Play Store. iOS build puede ser 100% manual desde Xcode local.

<task type="checkpoint:human-action" gate="blocking-human">
  <name>Task 3: BLOCKING — Operador hace Archive + Upload + TestFlight smoke + Submit for Review en Xcode/ASC</name>
  <what-built>Proyecto Xcode listo con web bundle sincronizado.</what-built>
  <how-to-verify>
    Operador hace:
    1. **Archive en Xcode:**
       - Abrir `el-templo-app/src-capacitor/ios/App/App.xcworkspace` (workspace, no project).
       - Seleccionar scheme "App", destination "Any iOS Device (arm64)".
       - Product → Archive.
       - Esperar archive (5-10 min).
    2. **Upload to App Store Connect:**
       - Xcode Organizer abre automáticamente con el archive.
       - Distribute App → App Store Connect → Upload.
       - Aceptar managed signing o seleccionar profile manual.
       - Click Upload, esperar (5-15 min).
       - Verificar success notification.
    3. **TestFlight processing:**
       - App Store Connect → TestFlight → iOS → ver el build subido (status "Processing" → "Ready to Test", ~15-30min).
       - Si aparece "Missing Compliance" (encryption), responder "No" (la app no usa crypto custom).
       - Agregar al Internal Testing group existente (o crear uno).
    4. **Smoke test en device iOS:**
       - Instalar TestFlight en device, aceptar invite.
       - Mismo smoke test que Plan 09 Task 3 (mi-templo + ?bar-challenge-force=1 → BarChallengeCard → explicacion → timer → cámara → resultado → share).
       - Validar especialmente:
         - Cámara abre correctamente (NSCameraUsageDescription se muestra al primer uso).
         - Share sheet de iOS muestra apps disponibles (Instagram Stories, WhatsApp).
         - KeepAwake mantiene pantalla activa durante el timer.
    5. **Submit for App Review:**
       - App Store Connect → My Apps → El Templo → iOS App → versión 1.5.0 → editar.
       - Adjuntar el build a la versión.
       - Release notes en español:
         "Nueva: Desafío de la Barra — evento 24/05. Aguantá 1:30 colgado y ganá tu premio en el local."
       - Privacy: verificar que data safety está sin cambios significativos (no nuevo PII collection — la foto vive en device).
       - Crypto export compliance: No (sin custom crypto).
       - Save + Submit for Review.
       - Considerar pedir Expedited Review si el deadline es muy ajustado (botón en ASC, justificar como "marketing event with hard external deadline").
    6. Documentar timestamps y URLs.
  </how-to-verify>
  <resume-signal>Operador responde "ios-submitted-for-review" con: (a) URL del build en TestFlight, (b) URL de la versión 1.5.0 en App Store Connect, (c) timestamp del submit, (d) confirmación del smoke test verde, (e) si pidió Expedited Review.</resume-signal>
</task>
