**Axios boot fix (el-templo-app/src/boot/axios.ts):**

The boot file is created via `boot(({ app }) => { ... })`. The Quasar boot function receives `{ app, router, store }` as arguments. However, the interceptors are set up OUTSIDE the boot function (at module level), so they don't have access to the router instance.

Fix approach: Move the interceptor setup inside the boot function where `router` is available, or export the router reference from the router module and import it.

The cleanest approach for Quasar: Import the router instance from `src/router/index.ts`. Check how the router is exported — Quasar typically exports the Router instance from the route file.

Read `el-templo-app/src/router/index.ts` to find how Router is exported, then:

1. Import the router (or the route function result) at the top of axios.ts
2. Replace `window.location.pathname !== '/login'` with a check against `router.currentRoute.value.path !== '/login'`
3. Replace `window.location.href = '/login'` with `router.push('/login')`

If router is not directly importable (Quasar creates it inside the boot), alternative: Move the response interceptor setup inside the `boot()` callback where `router` is available as a parameter. This is actually the cleanest Quasar pattern.

The boot function signature is `boot(({ app, router, store, ssrContext, urlPath, publicPath, redirect }) => { ... })`. Move the response interceptor setup inside this callback and use the `router` parameter.

Keep the `api` axios instance creation and request interceptor at module level (they don't need router).
