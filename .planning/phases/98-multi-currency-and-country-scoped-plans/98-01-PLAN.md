**Step B — Write the manual SQL migration file** at `el-templo-api/src/db/migrations/0091_multi_currency_and_country_scope.sql`. The file MUST contain THREE sections in order, with header comment block documenting them:

**Section 1 — Header + ALTER TABLE statements (6 columns total):**

```sql
-- Phase 98: Multi-currency and country-scoped plans
-- 1. Adds `country` to subscription_plans, promo_plans, gladius_products
-- 2. Adds `currency` to subscription_plans, subscriptions, payments
-- 3. Defensively backfills AR/ARS on any pre-existing row (NOT NULL DEFAULT
--    already backfills on ALTER; these UPDATEs are belt-and-suspenders)
-- 4. Seeds 12 ES plans with exact EUR prices per SPEC Requirement 4
--
-- Idempotency: column adds use IF NOT EXISTS-style guard via the _migrations
-- tracker (this file runs once per successful apply). ES plan INSERTs use
-- INSERT IGNORE keyed on (name, country) so partial re-applies are safe.
-- Atomicity is provided by run-migrations.ts: a file that fails mid-apply
-- is NOT recorded as applied, so the next run replays every statement.

ALTER TABLE subscription_plans ADD COLUMN country VARCHAR(2) NOT NULL DEFAULT 'AR';
ALTER TABLE subscription_plans ADD COLUMN currency VARCHAR(3) NOT NULL DEFAULT 'ARS';
ALTER TABLE subscriptions     ADD COLUMN currency VARCHAR(3) NOT NULL DEFAULT 'ARS';
ALTER TABLE payments          ADD COLUMN currency VARCHAR(3) NOT NULL DEFAULT 'ARS';
ALTER TABLE promo_plans       ADD COLUMN country  VARCHAR(2) NOT NULL DEFAULT 'AR';
ALTER TABLE gladius_products  ADD COLUMN country  VARCHAR(2) NOT NULL DEFAULT 'AR';
```

**Section 2 — Defensive backfill (no-op on fresh ALTER but safe for re-run):**

```sql
UPDATE subscription_plans SET country  = 'AR'  WHERE country  IS NULL OR country  = '';
UPDATE subscription_plans SET currency = 'ARS' WHERE currency IS NULL OR currency = '';
UPDATE subscriptions      SET currency = 'ARS' WHERE currency IS NULL OR currency = '';
UPDATE payments           SET currency = 'ARS' WHERE currency IS NULL OR currency = '';
UPDATE promo_plans        SET country  = 'AR'  WHERE country  IS NULL OR country  = '';
UPDATE gladius_products   SET country  = 'AR'  WHERE country  IS NULL OR country  = '';
```

**Section 3 — Seed 12 ES plans.** Each INSERT must mirror the field shape of the AR plan with the same (or closest) name. BEFORE hand-writing INSERTs, the executor MUST run a SELECT against the local dev DB to capture each AR analog's `plan_tier`, `booking_mode`, `plan_category`, `duration_days`, `classes_per_week`, `multi_branch`, `is_trial`, `is_group` values. Example lookup:

```sql
SELECT name, plan_tier, booking_mode, plan_category, duration_days, classes_per_week, multi_branch, is_trial, is_group, is_active, is_archived
FROM subscription_plans
WHERE country = 'AR' AND name IN (
  'Flex','Flex+','Foundation','Foundation+','Performance','Sesión de Prueba',
  '30 Días Online','Cero a Atleta','Foundation Online','Piernas y Glúteos',
  'Promo Gratuito 30 Días','Tu Primer Front Lever'
);
```

(Runnable via `mysql -uroot eltemplo -e "..."` or through a node/drizzle script — DO NOT invent values.)

For names that do NOT have an exact AR analog, pick the closest match:

- **Presenciales** (Flex, Flex+, Foundation, Foundation+, Performance, Sesión de Prueba): booking_mode likely `flexible` or `fixed`; plan_category likely `presencial` (check existing AR rows to confirm exact enum value).
- **Online** (30 Días Online, Cero a Atleta, Foundation Online, Piernas y Glúteos, Promo Gratuito 30 Días, Tu Primer Front Lever): plan_category likely `online`; booking_mode likely `online` or similar.

Write 12 `INSERT IGNORE INTO subscription_plans (...) VALUES (...)` statements, one per plan, with the exact prices IN CENTS:

```
| Plan                     | Category    | EUR | Cents |
|--------------------------|-------------|-----|-------|
| Flex                     | Presenciales| €70 | 7000  |
```

Each INSERT sets: `country = 'ES'`, `currency = 'EUR'`, `price_regular = <cents>`, `price_zero = <cents>` (set equal to `price_regular` UNLESS the AR analog has a different `price_zero`, in which case mirror proportionally — if unclear, set equal to `price_regular` and flag in the commit message), `is_active = 1`, `is_archived = 0`, and copy the AR analog's `plan_tier`, `booking_mode`, `plan_category`, `duration_days`, `classes_per_week`, `multi_branch`, `is_trial`, `is_group`. Include `created_at = NOW()`, `updated_at = NOW()`.

INSERT IGNORE uses MySQL's behavior of skipping on duplicate key — to make this work, the executor must either (a) rely on an existing unique key on (`name`, `country`) if present, or (b) simply trust that re-running a successful migration never happens because `_migrations` tracks applied files. Option (b) is the project convention; `INSERT IGNORE` is defensive only.
