**Analytics service (`analytics/service.ts`):**

For every aggregation method:

1. Add optional `country?: "AR" | "ES"` to its filter type.
2. Add `eq(schema.branches.country, filters.country)` to the WHERE chain when present.
3. Ensure the query joins `branches`. If it aggregates from `payments`, chain: `payments → subscriptions → users → branches` (or `payments → users → branches` depending on your schema — confirm via reading the existing queries).
4. For revenue-type aggregations that sum `amount` or `price_paid`, GROUP BY currency (or include currency in the returned row shape so the UI can segment):

```typescript
const revenueByMethod = await this.db
  .select({
    paymentMethod: schema.payments.paymentMethod,
    currency: schema.payments.currency,
    total: sql<number>`SUM(${schema.payments.amount})`,
  })
  .from(schema.payments)
  .innerJoin(schema.subscriptions, eq(schema.subscriptions.id, schema.payments.subscriptionId))
  .innerJoin(schema.users, eq(schema.users.id, schema.subscriptions.userId))
  .innerJoin(schema.branches, eq(schema.branches.id, schema.users.branchId))
  .where(
    and(
      /* existing conditions */,
      filters.country ? eq(schema.branches.country, filters.country) : undefined,
    )
  )
  .groupBy(schema.payments.paymentMethod, schema.payments.currency);
```

Since views are single-country per D-10, the currency GROUP BY will typically yield a single group per call — but including it in the output keeps the shape compatible with owner toggling without re-querying.
