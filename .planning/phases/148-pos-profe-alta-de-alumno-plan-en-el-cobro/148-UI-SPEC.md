# Phase 148 — UI Design Contract

> Visual and interaction contract for the **"Alta + plan" mode** added to the coach "Cargar pago" PoS screen. Mobile-web surface in `el-templo-admin` (Quasar/Vue 3). Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **This phase EXTENDS an existing, shipped screen** (`CargarPagoPage.vue`, Fase 140). It does NOT start from scratch. Every visual/interaction decision below inherits from the established PoS language: warm palette (no blue), single column ≤480px, big ≥56px touch targets, sticky Confirmar bar, "pendiente de validación" framing. New surface area is only what the alta flow genuinely needs.
>
> All product/flow decisions are **locked in `148-CONTEXT.md`** (crear-en-vivo, dedup DNI, sucursal default editable, precio según medio de pago + toggle Zero, turnos estructurados solo fixed, alumno mínimo nombre+DNI). This spec materializes those into a visual contract. Items genuinely left to discretion by CONTEXT are tagged `[ASSUMPTION]` and are overridable by the planner without breaking a locked decision.

**Sucursal chip** (`[ASSUMPTION]` shape): a compact `q-select` (`dense`, `outlined`) or a `q-chip` + small "editar" affordance at the top of the Alta panel, pre-filled with the profe's sede (`branchId` default). Editable to any sede the profe has access to via `requireBranchAccess({ from: 'body.branchId' })`. Only renders in **Alta + plan** mode (renew/misc keep using the member's existing branch). It drives which schedules the `FixedSchedulePicker` loads (`:branch-id`).

**Step order within the panel (top→bottom, no q-stepper):** alumno → plan (+ Zero) → turnos (conditional) → medio de pago + monto. A flat scroll panel (not a wizard) keeps it fast; the conditional Turnos section appears/collapses based on the selected plan's `bookingMode`. `[ASSUMPTION]` — CONTEXT "panel"; AssignPlanDialog uses a stepper because it has more branches (change/proration), which this PoS flow does not.

## Interaction Flows

### Flow — Alta + plan (the new mode)

1. Coach taps the **Alta + plan** tab. The **Sucursal chip** appears pre-filled with the profe's sede.
2. (Optional) Coach edits **Sucursal** if loading for another sede.
3. **Alumno — two paths:**
   - **Existing:** types name/DNI in the socio typeahead → selects a result. (Dedup is implicit — they picked a real member.)
   - **New:** types something with no match → taps **"+ Nuevo alumno"** → inline mini-form reveals **Nombre / Apellido / DNI**. On DNI blur (≥7 digits) the UI calls `check-duplicates`:
     - **Match found** → gold dedup banner: _"Ya existe un alumno con ese DNI: {nombre}. Se cargará sobre ese alumno."_ + a **"Usar ese alumno"** action that collapses the mini-form and selects the existing member. (Locked: never duplicate by DNI.)
     - **No match** → the new-student data is kept; the alta will create the member on Confirmar.
4. **Plan:** the plan grid (grouped by tier, filtered to the chosen sucursal's catalog) renders. Coach taps a plan row → it highlights `$primary`. **Precio Zero** toggle appears under the grid.
5. **Turnos (conditional):** if the selected plan is `bookingMode === 'fixed'`, the **Turnos fijos** section + `FixedSchedulePicker` appears, required count = `classesPerWeek`. If `flexible`, **no picker** renders (locked) — show a one-line caption: _"Este plan reserva semana a semana — no se eligen turnos ahora."_
6. **Medio de pago + Monto:** coach taps a payment button. **Monto autocalculates**: `card` → `priceCreditCard`; `cash`/`transfer` → `priceZero` if Zero on else `priceRegular`. Monto stays **editable**; if coach enters less than the price → gold deuda banner.
7. **Confirmar** (sticky): shows the amount. On tap → `:loading`/`:disable` → atomic backend call (resolve/create member + assignPlan + pendiente txn). Success → notify, form resets, ticket prepends to "Mis cargas" with a **Pendiente** badge (+ "Nuevo" chip if a member was created).

**Confirmar enabled only when:** (existing member selected OR new-student Nombre+DNI present) AND sucursal set AND a plan selected AND payment method selected AND monto > 0 AND (if plan is `fixed`: schedule count === `classesPerWeek`).

### Mode-switch behavior

Switching INTO Alta + plan from another mode clears renew/misc-specific fields but keeps the selected socio if one was chosen (so a misclassified tap is cheap to recover). Switching OUT clears the new-student mini-form. `[ASSUMPTION]` — mirrors the existing `resetChargeFields` philosophy in `CargarPagoPage.vue`.

## States

| State                                   | Trigger                           | UI                                                                                                                                                                                            |
| --------------------------------------- | --------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Initial (Alta mode)**                 | Tab selected                      | Sucursal pre-filled (profe sede), empty alumno/plan, Confirmar disabled                                                                                                                       |
| **Typeahead searching**                 | Typing socio                      | `q-select :loading`; `#no-option` shows "Escribí para buscar" / "Sin resultados" + **"+ Nuevo alumno"**                                                                                       |
| **New-student form open**               | "+ Nuevo alumno" tapped           | Mini-form (Nombre/Apellido/DNI) reveals; typeahead value cleared                                                                                                                              |
| **DNI checking**                        | DNI blur (≥7 digits)              | Inline spinner / disabled Confirmar while `check-duplicates` in flight                                                                                                                        |
| **DNI dedup match**                     | check-duplicates returns a member | Gold banner "Ya existe un alumno con ese DNI: {nombre}" + "Usar ese alumno" action                                                                                                            |
| **Plan list loading**                   | Sucursal set / mode entered       | `q-skeleton` rows in the plan grid (pattern from `AssignPlanDialog` spinner)                                                                                                                  |
| **Plan list empty**                     | No active plans for sede          | `text-grey-5 text-italic`: "No hay planes activos para esta sede."                                                                                                                            |
| **Plan selected — fixed**               | Tap a fixed plan                  | Turnos section appears; picker badge shows `seleccionadas/required`; Confirmar blocked until exact count                                                                                      |
| **Plan selected — flexible**            | Tap a flexible plan               | No picker; caption "reserva semana a semana"; Confirmar not blocked on turnos                                                                                                                 |
| **Monto autocalculated**                | Plan + method chosen              | Monto field pre-fills from price column; caption "Por defecto se cobra el total. Editá si es parcial."                                                                                        |
| **Partial / deuda**                     | Monto < precio                    | Gold banner "El alumno quedará deudor por $X"                                                                                                                                                 |
| **Submitting**                          | Confirmar tapped                  | Confirmar `:loading` + `:disable` for the whole request (double-submit guard)                                                                                                                 |
| **Success**                             | 2xx                               | `$q.notify positive` "Alumno y plan cargados — pendiente de validación"; form resets; ticket prepends (Pendiente + Nuevo chip)                                                                |
| **Duplicate submit (idempotent no-op)** | Same idempotency key resent       | Server returns the existing ticket; treat as success, de-dupe the list prepend by id; **no error, no duplicate member**                                                                       |
| **Validation error (client)**           | Confirmar with missing field      | Confirmar stays disabled; offending field shows `:error`; no network call                                                                                                                     |
| **Network / server error**              | non-2xx                           | `$q.notify negative` "No se pudo cargar. Reintentá."; Confirmar re-enables; **retry reuses the same idempotency key** (atomic + idempotent backend — safe no-op if it had actually succeeded) |

### Idempotency lifecycle (locked: atomic + idempotent endpoint)

- Generate **one** `crypto.randomUUID()` per confirmation attempt (first tap for the current form state); reuse on retry; regenerate only after an acknowledged success (form reset). Identical to the existing `currentIdempotencyKey` lifecycle in `CargarPagoPage.vue`. The disabled-button guard handles double-taps; the idempotency key is the network-retry backstop. A replay must **not** create a second member or payment.

**Destructive confirmation (ALTA-06 — void cascade):**
The coach screen has **no** destructive action (coach cannot void; void is done by gestión in the Pendientes bandeja, Fase 141). However this phase's locked cascade behavior demands an **enhanced confirmation copy in the bandeja** when voiding a charge that _created a new member_:

> **Anular esta carga** · "Esta carga creó al alumno **{nombre}**. Al anular, también se desactivará su membresía y el alumno quedará **inactivo** (no se elimina). ¿Anular de todos modos?" — confirm via the existing void dialog, red `$negative` confirm button.

For voids of **pre-existing** members the copy is unchanged (current behavior — only that payment/membership is annulled). The bandeja must distinguish the two cases (e.g. a "creó alumno nuevo" flag on the transaction) to pick the right copy.

## Accessibility

- **Touch targets:** all interactive elements ≥44px; payment buttons, plan rows, and Confirmar ≥56px (Spacing exceptions).
- **Single column, no horizontal scroll** at 320px (the Turnos grid has its own internal `overflow-x:auto`, isolated — it does not break the page).
- **Numeric inputs:** `inputmode="numeric"` on DNI and Monto so phones surface the number pad.
- **Contrast:** all palette tokens WCAG-AA verified on cream `#f2ede5` (documented in `quasar.variables.scss`: primary 4.75:1, warning 4.79:1, positive 4.88:1, negative 4.51:1).
- **Color never the sole signal:** Pendiente badge carries text; selected plan shows highlight + check, not color alone; dedup notice has an icon + text; deuda banner has icon + text.
- **Sticky Confirmar** clears the iOS/Android bottom bar via `q-pb-xl` safe-area padding.
- **Loading feedback** on every async step (typeahead, DNI check, plan list, submit) — no silent waits.
- **Focus / reading order** top-to-bottom matches the visual panel order: sede → alumno → plan → turnos → medio de pago → Confirmar.
