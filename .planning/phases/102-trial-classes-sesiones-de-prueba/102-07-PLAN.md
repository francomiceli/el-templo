<objective>
Trial conversion analytics. Track when a lead becomes an alumno and surface
the funnel in a new "Conversión" tab in Reportes.

Decisions (confirmed 2026-04-24):

- converted_at semantics: set on first subscription creation IF user has
  any is_trial=1 booking (any status, including cancelled) — captures the
  full funnel, not just "clean" conversions.
- No backfill: trials are a new concept (phase 102 just shipped), so no
  historical is_trial=1 rows exist. Forward-only.
- No coach attribution: schedules have no coach_id. Out of scope here,
  revisit with a dedicated coach-per-class design.
  </objective>

<scope>

**Schema**

- New column `users.converted_at TIMESTAMP NULL`.
- Index: `idx_users_converted_at` (only populated for converts, cheap).
- Migration adds the column; no UPDATE backfill.

**Hook**

- `SubscriptionService.assignSubscription` (or equivalent): after the
  INSERT succeeds, if user has `converted_at IS NULL` AND exists a
  booking with `is_trial=1` for that user, set `converted_at = NOW()`.
- Fires once per user (subsequent subs are no-ops).
- Implemented in the same transaction as the sub creation so partial
  failures don't leak.

**Endpoint**

- `GET /api/admin/reportes/trial-conversion?from=YYYY-MM-DD&to=YYYY-MM-DD`
- Country-scoped via `attachCountryScope`.
- Response:
  ```
  {
    totals: {
      trialsCount: number,           // total leads in window (distinct users)
      convertedCount: number,        // those with converted_at set in window
      conversionRatePct: number,     // convertedCount / trialsCount * 100
      medianDaysToConvert: number|null,
      revenueFromConverted: number,  // sum of payments from converted users
      revenuePerTrial: number,       // revenueFromConverted / trialsCount
    },
    byBranch:   [{ branchId, branchName, trialsCount, convertedCount, conversionRatePct }],
    byHourSlot: [{ hour: "HH:00", trialsCount, convertedCount, conversionRatePct }],
    byShift:    [{ shift: "TM"|"TT", trialsCount, convertedCount, conversionRatePct }],
    pendingLeads: [                    // un-converted leads, oldest trial first
      { userId, firstName, lastName, phone, branchId, trialDate, daysSinceTrial }
    ]
  }
  ```

**Frontend**

- New tab "Conversión" in `ReportesPage.vue`, icon `trending_up`.
- Date range picker (defaults: last 30 days).
- KPI cards: Conversion rate %, Total trials, Convertidos, Mediana días a
  conversión, Revenue por trial.
- Tables: Por sede, Por horario (hora + TM/TT), Leads pendientes (ordenables
  por días desde trial, con link a `/alumnos/:id`).

**Tests**

- Migration schema check.
- Hook: assigning first sub to a user with a trial sets `converted_at`;
  assigning sub to a user without trial leaves it NULL; assigning second
  sub to an already-converted user is a no-op.
- Endpoint: fixture with 3 trials, 2 conversions, assert rate = 66.67,
  branches aggregate correctly, pending list excludes converted users.

</scope>

<out_of_scope>

- Coach attribution — needs coach-per-class data model (separate phase).

- Auto-outreach to pending leads — just surface them, no nudge automation.
- Conversion attribution beyond first sub (upgrades, re-activations).
- Charts / visualization beyond tables + KPI cards (can iterate later).
  </out_of_scope>
