<threat_model>

## Trust Boundaries

| Boundary                             | Description                                                                      |
| ------------------------------------ | -------------------------------------------------------------------------------- |
| formulario de alta → `insert(users)` | el staff carga `branchId`, DNI y email; hoy nada verifica el gimnasio de la sede |
| `userId` de params → update/delete   | el id llega por la URL y hoy matchea en cualquier gimnasio                       |
| SELECT de unicidad → 409             | un 409 por DNI repetido en otro gimnasio delata que ese socio existe             |
| `DEFAULT 1` de `tenant_id`           | un insert sin `tenantValues` nace en el gimnasio 1 sin que nadie lo decida       |

## STRIDE Threat Register

| Threat ID   | Category               | Component                            | Disposition | Mitigation Plan                                                                                                    |
| ----------- | ---------------------- | ------------------------------------ | ----------- | ------------------------------------------------------------------------------------------------------------------ |
| T-173-18-01 | Tampering              | `insert(users)` de las 3 altas       | mitigate    | `tenantValues` con el tenant estampado después del spread (anti mass-assignment) en todas las tablas del alta      |
| T-173-18-02 | Tampering              | `input.branchId` → `users.branch_id` | mitigate    | `assertBranchDelGimnasio` dentro de la transacción; se escribe el `id` de la fila resuelta, no el del payload      |
| T-173-18-03 | Elevation of Privilege | `resetMemberPassword`                | mitigate    | `tenantWhere` en el update: sin él, se puede tomar control de una cuenta de otro gimnasio                          |
| T-173-18-04 | Information Disclosure | 409 de DNI/email repetido            | mitigate    | `tenantWhere` en los SELECT de unicidad: el conflicto solo puede venir del propio gimnasio (trampa (a) del piloto) |
| T-173-18-05 | Tampering              | `softDeleteMember` / `updatePhoto`   | mitigate    | `tenantWhere` en cada update; un `userId` ajeno deja de matchear                                                   |
| T-173-18-06 | Tampering              | notas colgando de un socio ajeno     | mitigate    | verificación de pertenencia del socio antes de escribir, más `tenantValues` en `member_notes`                      |

</threat_model>
