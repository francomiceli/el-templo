<interfaces>
Contratos que este plan CREA (consumidos por el plan 06 — composable/types del admin los espejan 1:1):

- `GET /admin/tree-editor/milestone-review?route=CODE` → `{ rows: MilestoneReviewRow[] }` con MilestoneReviewRow = { exerciseId, name, dl (dificultad_lineal), effort, movementToken: string|null, stepRank: number|null, proposedMilestoneExerciseId: number|null, status: 'pending'|'accepted'|'rejected', confidence: number|null }. Solo pending por defecto. El agrupamiento visual por (movementToken, stepRank) lo hace el frontend.
- `GET /admin/tree-editor/milestone/:exerciseId/variants` → `{ variants: [{ id, name, dl }] }` — ejercicios con milestone_exercise_id = :exerciseId (truth aceptado, no propuestas).
- `POST /admin/tree-editor/milestone-review/accept` body { exerciseId: number, role: 'hito'|'variante', milestoneExerciseId?: number (requerido si role='variante'), dimensionOverrides?: { step?: number|null, habilidad?: string|null } } → MutationResult. En UNA db.transaction: (a) si existe propuesta de dimensión pending para el ejercicio → aceptarla vía acceptInTransaction con los overrides; (b) escribir exercises.milestone_exercise_id (NULL si hito, milestoneExerciseId si variante); (c) si role='variante' → poda acotada de aristas (ver Task 1); (d) flipear la propuesta de hito a 'accepted' si existe (si no existe, proceder igual — clasificación ad-hoc desde el panel).
- `POST /admin/tree-editor/milestone-review/reject` body { exerciseId } → flipea la propuesta de hito a 'rejected'; 404 si no hay pending; NUNCA toca exercises.
- `POST /admin/tree-editor/milestone/promote` body { exerciseId } (debe ser variante) → swap transaccional (ver Task 2).

Validaciones (TreeEditorError 400/404, nunca 500): milestoneExerciseId debe existir, ser de la MISMA partición (route × effort) que el ejercicio, ser él mismo hito (milestone_exercise_id IS NULL) y distinto del ejercicio; degradar un ejercicio que tiene variantes apuntándole → 400 con mensaje "tiene variantes asignadas — promové otra variante a hito primero".
</interfaces>
