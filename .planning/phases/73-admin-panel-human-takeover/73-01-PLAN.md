<task type="auto">
  <name>Task 1: Implement takeover, resumeBot, and sendMessage service methods</name>
  <files>el-templo-api/src/modules/whatsapp/service.ts</files>
  <action>
    Implement the three stub methods in WhatsAppService:

    **takeover(conversationId, adminId):**
    1. Fetch conversation by id. If not found, throw NotFoundError.
    2. If already human_takeover, throw BadRequestError("Conversacion ya esta en modo humano").
    3. Update conversation: set status='human_takeover', assignedAdminId=adminId, updatedAt=NOW().
    4. Return the updated ConversationRecord via a re-fetch using the existing getConversation query pattern (or a simpler single-row query + mapConversationRow).

    **resumeBot(conversationId):**
    1. Fetch conversation by id. If not found, throw NotFoundError.
    2. If not human_takeover, throw BadRequestError("Conversacion no esta en modo humano").
    3. Update conversation: set status='active', assignedAdminId=null, updatedAt=NOW().
    4. Return the updated ConversationRecord.

    **sendMessage(conversationId, adminId, input):**
    1. Fetch conversation by id. If not found, throw NotFoundError.
    2. Insert a new row in whatsapp_messages with direction='outbound_human', content=input.content, messageType=input.messageType ?? 'text', conversationId.
    3. Update conversation: set lastMessageAt=NOW(), updatedAt=NOW().
    4. Call WhatsApp Cloud API to deliver the message. Use native fetch (Node 22 built-in, same pattern as el-templo-bot/src/whatsapp/client.ts). Read WHATSAPP_TOKEN and WHATSAPP_PHONE_ID from process.env. POST to `https://graph.facebook.com/v21.0/{phoneId}/messages` with messaging_product=whatsapp, to={conversation.phone}, type=text, text={body: input.content}.
    5. Update the inserted message row with the whatsappMessageId returned from the API response.
    6. Return the MessageRecord.

    For the WhatsApp API call, create a private helper method `sendWhatsAppMessage(phone: string, text: string): Promise<string>` that returns the wamid. Keep it simple -- if the API call fails, log the error but still return the saved message (the message is recorded in DB even if delivery fails). Use try/catch around the fetch, log error with this.log.error, and set whatsappMessageId to null on failure.

    Do NOT duplicate the bot's client.ts -- this is a minimal inline implementation in the service. The API service only needs to send text messages (not interactive or template).

    Use drizzle ORM methods (this.db.update, this.db.insert) not raw SQL, following the existing patterns in the service file.
