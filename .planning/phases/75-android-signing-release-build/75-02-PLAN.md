Create `.github/workflows/build-android-production.yml` by cloning the staging workflow structure and making these specific changes:

**Workflow metadata:**

- `name: Build Android Production Release`
- Trigger: `workflow_dispatch` only (same as staging)

**Job setup (same as staging):**

- `runs-on: ubuntu-latest`
- `defaults.run.working-directory: el-templo-app`
- Same pnpm, Node.js, Java setup steps (pnpm v10, Node 22, Java 21 Zulu)

**Build web assets step -- use PRODUCTION env vars (not staging):**

```yaml
- name: Build web assets for production
  run: pnpm run build
  env:
    VITE_API_URL: ${{ secrets.VITE_API_URL }}
    VITE_APP_NAME: "El Templo"
    VITE_SENTRY_DSN: ${{ secrets.VITE_SENTRY_DSN }}
```

Note: Uses `VITE_API_URL` (not `STAGING_VITE_API_URL`) and `VITE_SENTRY_DSN` (not `STAGING_VITE_SENTRY_DSN`). App name is "El Templo" (not "El Templo (Staging)").

**Capacitor sync step -- NO STAGING env var:**

```yaml
- name: Install Capacitor dependencies
  working-directory: el-templo-app/src-capacitor
  run: pnpm install --frozen-lockfile

- name: Sync web assets and native plugins
  working-directory: el-templo-app/src-capacitor
  run: |
    mkdir -p www
    cp -r ../dist/spa/* www/
    npx cap sync android
```

Note: No `STAGING: 'true'` env var -- this is a production build. The `production` flavor is the default (no env var needed).

**NEW: Decode keystore step (before Gradle build):**

```yaml
- name: Decode keystore
  working-directory: el-templo-app/src-capacitor/android/app
  run: echo "${{ secrets.ANDROID_KEYSTORE_BASE64 }}" | base64 --decode > keystore.jks
```

Working directory MUST be `el-templo-app/src-capacitor/android/app` so `keystore.jks` lands where `build.gradle` expects it via `file("keystore.jks")`.

**NEW: Extract version name step (for artifact naming):**

```yaml
- name: Extract version name
  id: version
  working-directory: el-templo-app/src-capacitor/android/app
  run: |
    VERSION_NAME=$(grep 'versionName' build.gradle | head -1 | sed 's/.*"\(.*\)".*/\1/')
    SHORT_SHA=$(echo "${{ github.sha }}" | cut -c1-7)
    echo "name=v${VERSION_NAME}-${SHORT_SHA}" >> $GITHUB_OUTPUT
```

**Gradle build step -- run BOTH bundle and assemble:**

```yaml
- name: Build signed AAB and APK
  working-directory: el-templo-app/src-capacitor/android
  env:
    VERSION_CODE: ${{ github.run_number }}
    ANDROID_KEYSTORE_PASSWORD: ${{ secrets.ANDROID_KEYSTORE_PASSWORD }}
    ANDROID_KEY_PASSWORD: ${{ secrets.ANDROID_KEY_PASSWORD }}
  run: ./gradlew bundleProductionRelease assembleProductionRelease
```

The `ANDROID_KEYSTORE_PASSWORD` and `ANDROID_KEY_PASSWORD` env vars are what `build.gradle`'s `signingConfigs.release` reads via `System.getenv()`. The conditional guard in build.gradle will detect these are present and apply the signing config.

**Upload AAB artifact:**

```yaml
- name: Upload AAB artifact
  uses: actions/upload-artifact@v4
  with:
    name: production-aab-${{ steps.version.outputs.name }}
    path: el-templo-app/src-capacitor/android/app/build/outputs/bundle/productionRelease/app-production-release.aab
    retention-days: 90
```

**Upload APK artifact:**

```yaml
- name: Upload APK artifact
  uses: actions/upload-artifact@v4
  with:
    name: production-apk-${{ steps.version.outputs.name }}
    path: el-templo-app/src-capacitor/android/app/build/outputs/apk/production/release/app-production-release.apk
    retention-days: 90
```

Artifact naming uses `steps.version.outputs.name` which produces e.g. `production-aab-v1.0.0-abc1234`. Retention is 90 days per user decision (longer than staging's 30 days since these are release builds).
</action>
