    In `member-routes.ts`, the GET /me/subscription handler calls `subscriptionService.getMemberSubscription()` which returns a `SubscriptionDetail`. This detail includes `planId` but NOT `isPersonalizada`/`personalizadaType`.

    Two approaches:
    A) Add isPersonalizada/personalizadaType to the getMemberSubscription select query and SubscriptionDetail type (heavier, touches shared type)
    B) Do a lightweight secondary query in the member-routes handler to get the plan's isPersonalizada and personalizadaType by planId (simpler, isolated)

    Use approach B — add a quick lookup after getting the subscription:

    1. In the GET /me/subscription handler, after getting `sub`, query the plan to get isPersonalizada and personalizadaType:
       ```typescript
       // Get plan personalizada info
       const [plan] = await fastify.db
         .select({
           isPersonalizada: schema.subscriptionPlans.isPersonalizada,
           personalizadaType: schema.subscriptionPlans.personalizadaType,
         })
         .from(schema.subscriptionPlans)
         .where(eq(schema.subscriptionPlans.id, sub.planId))
         .limit(1);
       ```

    2. Import the required drizzle symbols at the top:
       - `import { eq } from "drizzle-orm";`
       - `import * as schema from "../../db/schema/index";` (or the specific subscription-plans schema)

    3. Add the fields to the response object:
       ```typescript
       return {
         id: sub.id,
         planName: sub.planName,
         planTier: sub.planTier,
         status: sub.status,
         startDate: sub.startDate,
         endDate: sub.endDate,
         daysRemaining,
         pricePaid: sub.pricePaid,
         isPersonalizada: plan?.isPersonalizada ?? false,
         personalizadaType: plan?.personalizadaType ?? null,
       };
       ```

    This approach avoids touching the shared SubscriptionDetail type and getMemberSubscription service method, keeping changes isolated to the member-facing route.
