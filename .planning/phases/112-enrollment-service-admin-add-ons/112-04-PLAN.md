<objective>
Ship the admin add-on assignment surface: extend the `transaction_links.target_kind` enum with `'enrollment'`, fill EnrollmentService.enrollAddon, register a new admin endpoint, and integrate the finance module so paid add-ons emit an atomic financial transaction.

Purpose: Closes the operational use case driving the milestone — Ignacio (admin) wants to "regalar" or sell program add-ons to members on top of their active subscription, with proper financial trazability and audit log. ENROLL refactor (Plan 02) and lifecycle hooks (Plan 03) made this possible without spaghetti.

Output:

- 1 hand-written SQL migration (0112) extending `transaction_links.target_kind` with `enrollment`.
- 1 Drizzle schema update mirroring the migration.
- TransactionService.create extended to validate `target_kind='enrollment'` (target_id refers to program_enrollments.id).
- EnrollmentService.enrollAddon body filled (creates enrollment + optional financial transaction in one tx).
- New endpoint `POST /api/admin/users/:userId/program-addons`.
- Audit log entry on assignment + on cancel (existing cancel endpoint enhanced).
- 8+ integration tests covering happy path, gift path, no-sub, duplicate, RBAC, atomicity rollback.

D-13 decision (locked by planner): EXTEND `transaction_links.target_kind` enum with `'enrollment'` (NOT extend `kind`). Rationale: `kind='plan_charge'` semantically fits — it remains a charge for program access — and the granular trazability lives at the link layer. Reusing `plan_charge` keeps Phase 105-04 D-01 canonical revenue filter unchanged (no audit needed across analytics queries). Cost: one enum extension on `target_kind` + a new branch in TransactionService's TXN-07 referential integrity probe. Minimal-surface option.

D-22 decision (locked by planner): RBAC = `FINANCE_WRITE_ROLES` (owner|admin|gestion|recepcion). Rationale: matches existing precedent — recepcion already creates `kind='plan_charge'` transactions via `recordAssignmentCharge` (Phase 107) and assigns plans (Phase 63). Asymmetric blocking would create operational friction for the same role surface.
</objective>

    **Step C — Fill the body** of `enrollAddon`:

    ```typescript
    async enrollAddon(
      userId: number,
      subscriptionId: number,
      input: EnrollAddonInput,
      tx?: TxHandle,
    ): Promise<{ enrollmentId: number }> {
      // Resolve everything we need under the caller's tx if provided, else open one.
      const runner = tx
        ? <T>(cb: (h: TxHandle) => Promise<T>): Promise<T> => cb(tx)
        : <T>(cb: (h: TxHandle) => Promise<T>): Promise<T> => this.db.transaction(cb);

      return await runner<{ enrollmentId: number }>(async (txHandle) => {
        // 1. Validate active sub belongs to userId AND id matches subscriptionId.
        //    Pull plan.currency, plan.grantsAllPrograms, sub.branchId for downstream use.
        const [activeSub] = await txHandle
          .select({
            id: schema.subscriptions.id,
            status: schema.subscriptions.status,
            branchId: schema.subscriptions.branchId,
            planId: schema.subscriptions.planId,
            currency: schema.subscriptionPlans.currency,
            grantsAllPrograms: schema.subscriptionPlans.grantsAllPrograms,
          })
          .from(schema.subscriptions)
          .innerJoin(
            schema.subscriptionPlans,
            eq(schema.subscriptions.planId, schema.subscriptionPlans.id),
          )
          .where(
            and(
              eq(schema.subscriptions.userId, userId),
              eq(schema.subscriptions.id, subscriptionId),
              or(
                eq(schema.subscriptions.status, "active"),
                eq(schema.subscriptions.status, "paused"),
              ),
            ),
          )
          .limit(1);
        if (!activeSub) {
          const err = new BadRequestError("El miembro no tiene suscripcion activa");
          (err as { code?: string }).code = "ASSIGN_PLAN_FIRST";
          throw err;
        }

        // 2. Validate program exists + is active.
        const [program] = await txHandle
          .select({ id: schema.programs.id, isActive: schema.programs.isActive })
          .from(schema.programs)
          .where(eq(schema.programs.id, input.programId))
          .limit(1);
        if (!program || !program.isActive) {
          throw new NotFoundError("Programa no encontrado o inactivo");
        }

        // 3. Duplicate check across ALL sources (D-12).
        const dupes = await txHandle
          .select({ id: schema.programEnrollments.id })
          .from(schema.programEnrollments)
          .where(
            and(
              eq(schema.programEnrollments.userId, userId),
              eq(schema.programEnrollments.programId, input.programId),
              or(
                eq(schema.programEnrollments.status, "active"),
                eq(schema.programEnrollments.status, "paused"),
              ),
            ),
          )
          .limit(1);
        if (dupes.length > 0) {
          const err = new ConflictError("El miembro ya tiene una inscripcion activa para este programa");
          (err as { code?: string }).code = "PROGRAM_ALREADY_ACTIVE";
          throw err;
        }

        // 4. Insert enrollment row.
        const [insertResult] = await txHandle
          .insert(schema.programEnrollments)
          .values({
            userId,
            programId: input.programId,
            status: "active",
            currentWeek: 1,
            sessionsCompletedThisWeek: 0,
            weekUnlockedAt: new Date(),
            source: "admin_addon",
            subscriptionId,
            pricePaid: input.pricePaid ?? null,
            assignedBy: input.assignedBy,
            notes: input.notes ?? null,
          });
        // Drizzle MySQL InsertResult has insertId on the result header.
        const enrollmentId = (insertResult as unknown as { insertId: number }).insertId;

        // 5. Create financial_transaction if pricePaid > 0.
        if ((input.pricePaid ?? 0) > 0) {
          if (!this.transactionService) {
            throw new Error("TransactionService not injected — enrollAddon with pricePaid > 0 requires it");
          }
          const today = new Date().toISOString().split("T")[0];
          await this.transactionService.create(
            {
              memberId: userId,
              kind: "plan_charge",
              direction: "inflow",
              amount: input.pricePaid as number,
              currency: activeSub.currency,
              paymentMethod: input.paymentMethod ?? "cash",
              transactionDate: today,
              effectiveDate: today,
              branchId: input.branchId ?? activeSub.branchId,
              links: [
                {
                  targetKind: "enrollment",
                  targetId: enrollmentId,
                  allocatedAmount: input.pricePaid as number,
                },
              ],
              notes: `Add-on programa ${input.programId} asignado por admin`,
            },
            input.assignedBy,
            txHandle,
          );
        }

        // 6. Audit log entry (D-24).
        await auditLog.write(txHandle, {
          actorId: input.assignedBy,
          action: "plan_assigned",
          targetKind: "member",
          targetId: userId,
          payload: {
            enrollmentId,
            programId: input.programId,
            pricePaid: input.pricePaid ?? null,
            subscriptionId,
            currency: activeSub.currency,
            source: "admin_addon",
          },
          reason: input.notes ?? null,
        });

        this.log.info(
          { userId, programId: input.programId, enrollmentId, pricePaid: input.pricePaid ?? null },
          "Admin add-on enrollment created",
        );

        return { enrollmentId };
      });
    }
    ```
