Backfill rules (D-03 + D-05, locked by planner):

1. `source`:
   - JOIN subscription_plans via the user's most-recent subscription whose plan.linkedProgramId = enrollment.program_id → `plan_linked`
   - else if any subscription_plans.grants_all_programs=true sub of the user is active when enrolled_at falls inside its [start_date, end_date] → `plan_bundle`
   - else default `admin_addon` (covers any pre-existing manual rows; expected count = 0 today but safe-by-default)
2. `subscription_id`: pick the user's subscription where (a) start_date <= enrolled_at AND (end_date IS NULL OR end_date >= enrolled_at) AND (b) the plan binding matches the chosen `source` (linkedProgramId match OR grants_all_programs match). If exactly one row matches, set it. If 0 or >1, leave NULL (documented in migration comments).
3. `price_paid`, `assigned_by`: always NULL on backfill (these are admin_addon-specific data points, never present in legacy rows).

Idempotency pattern (matches phase 86 / 90 / 103-01 / 111 precedent):

- Each `ALTER TABLE … ADD COLUMN` is the FIRST run only. Re-runs are blocked by the `_migrations` tracker (the runner's name='0111_program_enrollments_addon_columns.sql' insert prevents replay).
- The intra-migration backfill UPDATEs are GUARDED with `WHERE source IS NULL` (etc.) so even if the file were replayed manually outside the runner, it is a 0-row no-op.

    Step 3a — `plan_linked`: enrollments whose program_id matches a plan.linked_program_id of one of the user's subscriptions whose period covers enrolled_at.
    ```sql
    UPDATE program_enrollments pe
    INNER JOIN subscriptions s ON s.user_id = pe.user_id
    INNER JOIN subscription_plans sp ON sp.id = s.plan_id
    SET pe.source = 'plan_linked'
    WHERE pe.source IS NULL
      AND sp.linked_program_id = pe.program_id
      AND s.start_date <= DATE(pe.enrolled_at)
      AND (s.end_date IS NULL OR s.end_date >= DATE(pe.enrolled_at));
    ```

    Step 3b — `plan_bundle`: enrollments whose user has a bundle subscription covering enrolled_at AND was not already classified as plan_linked.
    ```sql
    UPDATE program_enrollments pe
    INNER JOIN subscriptions s ON s.user_id = pe.user_id
    INNER JOIN subscription_plans sp ON sp.id = s.plan_id
    SET pe.source = 'plan_bundle'
    WHERE pe.source IS NULL
      AND sp.grants_all_programs = 1
      AND s.start_date <= DATE(pe.enrolled_at)
      AND (s.end_date IS NULL OR s.end_date >= DATE(pe.enrolled_at));
    ```

    Step 3c — Default fallback for any remaining row: `admin_addon` (expected count today is 0 — there are no manual enrollments yet — but this is the safe default classification rule).
    ```sql
    UPDATE program_enrollments pe
    SET pe.source = 'admin_addon'
    WHERE pe.source IS NULL;
    ```

    Step 4 — Backfill `subscription_id` for plan_linked rows: unique sub whose plan.linked_program_id matches AND period covers enrolled_at.
    ```sql
    UPDATE program_enrollments pe
    INNER JOIN (
      SELECT pe2.id AS enrollment_id, MIN(s.id) AS sub_id, COUNT(s.id) AS n
      FROM program_enrollments pe2
      INNER JOIN subscriptions s ON s.user_id = pe2.user_id
      INNER JOIN subscription_plans sp ON sp.id = s.plan_id
      WHERE pe2.source = 'plan_linked'
        AND sp.linked_program_id = pe2.program_id
        AND s.start_date <= DATE(pe2.enrolled_at)
        AND (s.end_date IS NULL OR s.end_date >= DATE(pe2.enrolled_at))
      GROUP BY pe2.id
    ) m ON m.enrollment_id = pe.id
    SET pe.subscription_id = m.sub_id
    WHERE pe.subscription_id IS NULL
      AND m.n = 1;
    ```

    Step 4b — Backfill `subscription_id` for plan_bundle rows: unique bundle sub whose period covers enrolled_at.
    ```sql
    UPDATE program_enrollments pe
    INNER JOIN (
    ```
