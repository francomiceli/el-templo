**1. Header** with purpose: checklist of all GitHub Secrets that must be configured in the repository settings before the bot can deploy via GitHub Actions.

**2. "New Secrets for Bot" table** -- secrets that need to be ADDED to GitHub (not already present for the API). Columns: Secret Name | Value/Source | Used By | Notes.

New bot-specific secrets:

- WHATSAPP_TOKEN -- permanent System User token (see whatsapp-token-setup.md), shared API+bot

<task type="auto">
  <name>Task 2: Document WhatsApp permanent System User token generation</name>
  <files>docs/deployment/whatsapp-token-setup.md</files>
  <action>
Create `docs/deployment/whatsapp-token-setup.md` with step-by-step instructions for generating a permanent WhatsApp System User token for production use.

Use the content from ENV-ANALYSIS.md Section 6 as the primary source, but expand with more detail and structure:

**1. Overview** -- Explain WHY this is needed: development tokens from Graph API Explorer expire in 24 hours. Production requires a permanent token via a System User in Meta Business Manager.

**2. Prerequisites** -- Must have: Meta Business Manager admin access, a registered Meta App with WhatsApp product added, WhatsApp Business Account.

**3. Step-by-step instructions** (numbered, clear):

1. Go to Meta Business Manager (business.facebook.com) > Business Settings
2. Navigate to Users > System Users
3. Click Add to create a new System User (Name: "el-templo-bot", Role: Admin)
4. Click on the created System User > Add Assets
5. Select the WhatsApp Business Account > Grant Full Control
6. Click Generate New Token
7. Select the Meta App (El Templo's app)
8. Select required permissions: whatsapp_business_messaging, whatsapp_business_management
9. Click Generate Token
10. COPY THE TOKEN IMMEDIATELY (shown only once)

**4. Store the token** -- Add as GitHub Secret named WHATSAPP_TOKEN. The deploy workflow injects it into both API and bot .env.production files. For local dev, add to both el-templo-api/.env and el-templo-bot/.env.

**5. Token properties** -- Does not expire (unlike Graph API Explorer tokens). Can be revoked from Business Manager. Scoped to the WhatsApp Business Account. Works with the existing WHATSAPP_PHONE_ID.

**6. Token rotation** -- If compromised: revoke in Business Manager > generate new > update GitHub Secret > next deploy propagates automatically.

**7. Troubleshooting** -- Common issues: "Invalid OAuth access token" (token expired/revoked, regenerate), "Permission denied" (check whatsapp_business_messaging permission), "System User not found" (ensure it's in the correct Business Manager account).

Keep it practical and scannable. Use numbered steps, not paragraphs.
</action>
