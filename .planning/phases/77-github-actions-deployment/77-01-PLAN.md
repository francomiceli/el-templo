<task type="auto">
  <name>Task 1: Add bot to GitHub Actions deploy workflow</name>
  <files>.github/workflows/deploy.yml</files>
  <action>
Modify .github/workflows/deploy.yml to add the bot to the full deploy pipeline. Follow the exact same patterns used by the existing api/app/admin/web steps. Specifically:

**a. detect-changes job:** Add `bot` output and paths-filter entry:

```yaml
bot: ${{ steps.filter.outputs.bot }}
```

Filter: `'el-templo-bot/**'`

**b. Add build-bot job** (after build-web, before deploy):

- Same structure as build-api but WITHOUT MySQL service, WITHOUT test step, WITHOUT migration copy step
- working-directory: el-templo-bot
- Steps: checkout, setup pnpm, setup node (cache pnpm, cache-dependency-path: el-templo-bot/pnpm-lock.yaml), install deps (--frozen-lockfile), type check (pnpm exec tsc --noEmit), build (pnpm run build)
- Upload artifact named `bot-dist` containing: el-templo-bot/dist, el-templo-bot/package.json, el-templo-bot/pnpm-lock.yaml
- Condition: `github.event_name == 'workflow_dispatch' || needs.detect-changes.outputs.bot == 'true'`

**c. Update deploy job:**

- Add `build-bot` to `needs` array: `[build-api, build-app, build-admin, build-web, build-bot]`
- Update the `if` condition to include build-bot (same pattern: success or skipped, and add to the "at least one success" check)
- Add "Download Bot artifact" step (same pattern as others, name: bot-dist, path: bot-build)

**d. Add "Create .env.production for bot" step** (after the API .env.production step):

- Condition: `needs.build-bot.result == 'success'`
- Use heredoc to create bot-build/.env.production with these vars from secrets:
  NODE_ENV=production, PORT (from BOT_PORT, default 3001), DB_HOST, DB_PORT (default 3306), DB_USER, DB_PASSWORD, DB_NAME, REDIS_URL, WHATSAPP_TOKEN, WHATSAPP_PHONE_ID, WHATSAPP_VERIFY_TOKEN, AI_PROVIDER, AI_MODEL, OPENAI_API_KEY, ANTHROPIC_API_KEY, BOT_API_KEY, API_BASE_URL, CLASS_REMINDER_HOURS (default 2)
- IMPORTANT: Use the same heredoc pattern as the API step. No leading whitespace before var names (the existing API step has this issue -- match it for consistency, do not fix it).

**e. Fix "Create .env.production for API" step** -- add missing vars that the API needs in production:

- WHATSAPP_TOKEN=${{ secrets.WHATSAPP_TOKEN }}
- WHATSAPP_PHONE_ID=${{ secrets.WHATSAPP_PHONE_ID }}
- REDIS_URL=${{ secrets.REDIS_URL }}
- BOT_API_KEY=${{ secrets.BOT_API_KEY }}
- RESEND_API_KEY=${{ secrets.RESEND_API_KEY }}
- FRANCHISE_NOTIFICATION_EMAIL=${{ secrets.FRANCHISE_NOTIFICATION_EMAIL }}
- GLADIUS_NOTIFICATION_EMAIL=${{ secrets.GLADIUS_NOTIFICATION_EMAIL }}
- ACADEMY_NOTIFICATION_EMAIL=${{ secrets.ACADEMY_NOTIFICATION_EMAIL }}
- APP_NOTIFICATION_EMAIL=${{ secrets.APP_NOTIFICATION_EMAIL }}
- ANTHROPIC_API_KEY=${{ secrets.ANTHROPIC_API_KEY }}
  Add these AFTER the existing R2_PUBLIC_URL line.

**f. Add "Deploy bot to server" rsync step** (after Deploy Web):

- Condition: `needs.build-bot.result == 'success'`
- Same rsync pattern: `rsync -avz --delete --exclude node_modules bot-build/ ${{ secrets.SSH_USER }}@${{ secrets.SERVER_HOST }}:${{ secrets.BOT_DEPLOY_PATH }}`

**g. Add "Install bot dependencies on server" step** (after API deps install):

- Condition: `needs.build-bot.result == 'success'`
- SSH into server, cd to BOT_DEPLOY_PATH, pnpm install --prod --frozen-lockfile

**h. Add "Restart bot" step** (after Restart API):

- Condition: `needs.build-bot.result == 'success'`
- SSH: `cd $BOT_DEPLOY_PATH && NODE_ENV=production pm2 restart eltemplo-bot --update-env || NODE_ENV=production pm2 start dist/el-templo-bot/src/index.js --name eltemplo-bot`
- NOTE: Use the correct script path `dist/el-templo-bot/src/index.js` (NOT dist/index.js) because the bot's tsconfig has rootDir: ".." to include shared schema files, so tsc outputs to dist/el-templo-bot/src/

**i. Update "Backup current deployment" step** -- add bot backup block:

```
if [ -d "${{ secrets.BOT_DEPLOY_PATH }}" ]; then
  rm -rf ${{ secrets.BOT_DEPLOY_PATH }}.previous
  cp -r ${{ secrets.BOT_DEPLOY_PATH }} ${{ secrets.BOT_DEPLOY_PATH }}.previous
fi
```

**j. Update "Rollback on failure" step** -- add bot rollback block:

```
if [ -d "${{ secrets.BOT_DEPLOY_PATH }}.previous" ]; then
  rm -rf ${{ secrets.BOT_DEPLOY_PATH }}
  mv ${{ secrets.BOT_DEPLOY_PATH }}.previous ${{ secrets.BOT_DEPLOY_PATH }}
fi
```

Also add bot PM2 restart in rollback: `pm2 restart eltemplo-bot --update-env || true` (with || true since bot might not exist yet on first deploy).
