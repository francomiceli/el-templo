# Phase 119 — UI Design Contract

> Visual and interaction contract for Phase 119 (campaña de sesión de prueba freemium).
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Three UI surfaces, in priority order: **(1) Email de campaña (MJML)**, **(2) "Modo reservar prueba" en el member app**, **(3) Sección "Campañas" en el admin**.

---

## IMPORTANT — Brand correction vs. the orchestrator prompt

The spawning prompt referenced "Navy `#2c3e5c` + Bronze `#b8956c`". **That palette is stale and is NOT the El Templo brand.** Verified against the codebase (HIGH trust):

- `el-templo-app/src/css/quasar.variables.scss` and `el-templo-admin/src/css/quasar.variables.scss` (Phase 39): warm palette, **explicitly "no blue anywhere"**.
- `el-templo-web/.docs/brand-landing/spec-franquicias-pt2.md`: full token registry (Terracotta / Marble Cream / Clay / Deep Charcoal / Aged Gold).

This contract uses the **real brand**: **Marble Cream `#F2EDE5`** (dominant), **Terracotta `#C07A56`** (accent — email/landing value; the app uses a darker `#96593a` for AA contrast on cream), **Clay `#A0755A`**, **Deep Charcoal `#3D3732`** (text), **Aged Gold `#B89B5E`**. The email must match the landing/marketing brand, not the in-app contrast-tuned shade. If the user truly wants Navy/Bronze, that is a **decision to re-confirm before build** — do not silently introduce blue, which violates the documented brand.

## Spacing Scale

Declared values (multiples of 4). App/admin use Quasar's `q-*` spacing classes; email uses table cell padding in these increments.

| Token | Value | Usage                                                     |
| ----- | ----- | --------------------------------------------------------- |
| xs    | 4px   | Icon gaps, inline padding, day-pill internal              |
| sm    | 8px   | Compact element spacing, badge gaps                       |
| md    | 16px  | Default element spacing, card padding, email cell padding |
| lg    | 24px  | Section padding, email section gaps                       |
| xl    | 32px  | Layout gaps, email hero vertical padding                  |
| 2xl   | 48px  | Major section breaks                                      |
| 3xl   | 64px  | Email outer top/bottom padding, page-level spacing        |

Exceptions:

- **Tap targets:** all tappable controls (slot-card "Reservar" button, CTA buttons in email, branch select) must be ≥ **44px** tall for touch.
- **Email content width:** fixed **600px** container (table-based). Mobile media query collapses to **100%** with **16px** side gutters.
- App `slot-card`/`day-pill` use existing 6px/12px values from `ReservasPage.vue` — keep them unchanged for visual consistency (do not re-spec the existing grid).

## Email Layout Contract (PRIMARY surface — D-13, D-14, D-16, D-23, D-27)

Built with **MJML** (D-23) compiling to table-based bulletproof HTML. Single layout, no variants. Copy is supplied by the user (workflow: user gives raw info, Claude shapes brand voice) — this contract defines **slots and structure**, not final copy.

### Vertical structure (top → bottom)

1. **Tracking pixel** — 1×1 transparent GIF as the first element, `src` = `GET /api/campaigns/track/open?t=<token>`, `alt=""`, width/height 1, `display:block`. (Invisible; not a visual element but must be present.)
2. **Hero** — Marble Cream background (`#F2EDE5`), centered. El Templo **logo** (self-hosted PNG in `el-templo-web/public/email/logo.png`, max-width 160px, `alt="El Templo"`) + a brand hero image (self-hosted in `el-templo-web/public/email/`, full-width within 600px, `alt` describing a training scene). 32px top/bottom padding.
3. **Offer headline** — Georgia 28px/700 Deep Charcoal: the "sesión de prueba gratis" headline `{{HEADLINE}}` slot. Sub-line Georgia 20px or Arial 16px `{{SUBHEADLINE}}` slot. Terracotta divider rule below.
4. **Body copy** — Arial 16px/1.5 Deep Charcoal, `{{BODY}}` slot (1–2 short paragraphs explaining the free trial offer + the 30-day window, D-04).
5. **Dual CTA block (D-14)** — two stacked bulletproof buttons, ≥44px tall, ≥16px gap:
   - **Primary: "Reservá en la app"** — Terracotta `#C07A56` bg, Marble Cream `#F2EDE5` text, 4px radius. `href` = `GET /api/campaigns/track/click?t=<token>` → 302 → `https://eltemplo.org/r/trial?t=<token>` deep link (D-25). VML `<v:roundrect>` fallback for Outlook. Live text, not an image.
   - **Secondary: "Agendá por WhatsApp"** — WhatsApp green `#25D366` bg, white text, same dimensions. `href` = `https://wa.me/<number>?text=<preloaded>` per recipient country (AR `5492235820521`, ES `34680774331`, from `whatsapp.ts`). Inline WhatsApp glyph optional (must degrade with images off — keep the text label authoritative).
6. **Sedes list (D-13)** — section heading "Nuestras sedes" (Georgia 20px). A table listing each **active physical branch** with **name + street address**, sourced from `branches.address` (new column, D-24) — the canonical addresses already exist in `el-templo-web/data/sedes.ts` (7 Mar del Plata + 1 Barcelona "Eixample, Av. Diagonal 368"). Each row: branch name (Montserrat-feel → Georgia bold 16px), address (Arial 14px Olive Stone), optional "Cómo llegar" text link to `mapsUrl`. Group visually by city if multi-country in the send.
7. **Footer** — Olive Stone 12px on cream: El Templo legal line + **unsubscribe link** (D-15): "¿No querés recibir más novedades? Darte de baja" → `GET /api/campaigns/unsubscribe?t=<token>`. Marketing-only scope note. Physical sender address (CAN-SPAM/best practice).

### Cross-client compatibility rules (accionables — D-16)

| Rule      | Requirement                                                                                                                                                                                                                                                                                                                        |
| --------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Layout    | 100% table-based (`role="presentation"`, `cellpadding=0 cellspacing=0 border=0`). MJML emits this. Container fixed **600px**.                                                                                                                                                                                                      |
| CSS       | All base styles **inline**. `<style>` in `<head>` only for media queries / dark-mode (clients that strip head still get inline base).                                                                                                                                                                                              |
| Buttons   | **Bulletproof**: VML `<v:roundrect>` for Outlook (Word engine) + HTML/CSS for the rest. Live text, contrast ≥ 4.5:1, meaningful label (never "click aquí").                                                                                                                                                                        |
| Mobile    | `@media screen and (max-width:600px)`: container → 100%, side gutters 16px, CTAs full-width, font sizes hold or grow. Outlook desktop ignores media queries → base layout must already read well at 600px.                                                                                                                         |
| Dark mode | `@media (prefers-color-scheme: dark)` to pin brand colors, **always with a solid light fallback** (some clients ignore it). Avoid charcoal text on a fill the client might invert — keep text on Marble Cream with robust contrast. Logo must have a version that survives inversion (or use a PNG with its own light background). |
| Images    | `alt` on **every** image. The email must read completely with images OFF (Outlook blocks by default). Primary CTA is a text button, never an image. Sedes addresses are live text, not a baked image.                                                                                                                              |
| Fonts     | Web-safe stack only (Georgia / Arial). No `@font-face`, no Google Fonts, no CDN (NO-CDN rule).                                                                                                                                                                                                                                     |
| Hosting   | All images **self-hosted** in `el-templo-web/public/email/` → served from `https://eltemplo.org/email/...` (D-27, NO-CDN).                                                                                                                                                                                                         |

### Images-blocked appearance (required state)

With images disabled: logo and hero collapse to their `alt` text; the offer headline, body, **both CTA buttons** (HTML/VML, not images), the sedes address table, and footer all render fully. The email is fully actionable with zero images loaded.

## App "Modo reservar prueba" Contract (SECONDARY — D-20, D-22)

`ReservasPage.vue` goes from 2 to 3 states. **Reuse the existing design system** (Montserrat headings, `$primary` `#96593a`, white cards on cream, existing `branch-select`, `day-strip`, `slot-card`, `getWeeklyGrid`). Do not invent new components.

### State 1 — Muro (no-elegibles) — UNCHANGED

Existing `v-else-if="!hasPresencialPlan"` empty state (lines 9–22). No visual changes.

### State 2 — Modo reservar prueba (freemium elegible, sin prueba reservada)

Gated by **eligibility**, not by token (D-20). Layout, top → bottom:

- **Trial banner** (new): full-width card above the grid. Accent: 4px left border in `$primary`, Sandy Beige `#E5D9C8` fill, `card_giftcard`/`event_available` icon. Heading (Montserrat 16px/700 `$primary`): **"Tu sesión de prueba gratis"**. Sub-line (Geologica 13px Olive Stone): **"Elegí una sede y un horario en los próximos 30 días. Es gratis y sin compromiso."** Mirrors the existing `bonus-banner` visual pattern (lines 51–61) — reuse that styling family.
- **Branch selector FIRST** (D-06): reuse the exact `q-select` branch selector pattern (lines 26–44), but **always shown** for trial mode (freemium lives in virtual "Templo Online" → must pick a physical branch before seeing slots). Options = physical active branches of the user's country via `GET /members/scheduling/branches`. Placeholder when none selected: "Elegí una sede para ver los horarios". Grid is hidden/empty until a branch is chosen.
- **30-day grid** (D-05): reuse `day-strip` + `slot-card` exactly. Allow `changeWeek` forward up to +30 days; disable forward navigation beyond. The existing policy line changes (see Copywriting).
- **Reserve action**: tapping an available slot opens the existing `reserveDialog` with trial-specific copy (see Copywriting). On confirm → `reserveTrial(scheduleId, date, branchId)`.
- **NO cancel affordance** (D-03): hide the per-slot `close` cancel button and the next-class-card cancel button when the booking is a trial. The slot of the booked trial shows the "Reservado" badge **without** the cancel `q-btn`.

### State 3 — Prueba ya reservada (D-22)

Replaces the grid. Centered confirmation card (reuse `next-class-card` visual family):

- Icon `check_circle` in `$positive`.
- Heading (Montserrat 16px/700): **"Tu sesión de prueba está reservada"**.
- Body (Geologica 14px): **"Te esperamos el {fecha} en {sede}. ¡Llegá unos minutos antes!"** with `{fecha}` = day + date and `{sede}` = branch name + address.
- **No** reserve and **no** cancel controls. Optional WhatsApp link: "¿Necesitás cambiarla? Escribinos" → `buildWhatsAppUrl`.

### Deep-link entry

`boot/deep-links.ts` routes `eltemplo.org/r/trial?t=…` → `/reservas?trial=1`. The page ignores the token for authorization (D-21); it only triggers navigation. Eligibility is fetched via `GET /members/scheduling/trial-eligibility`. If logged out, store intended route and resume post-login.

## Admin "Campañas" Section Contract (SECONDARY — D-18, D-19)

New `CampaniasPage.vue` + route `path: 'campanias'`. **Follow the `ReportesPage.vue` / phase-117–118 pattern** — do not reinvent the admin design system.

- **Header**: `text-h5` "Campañas" + `text-caption text-grey-7` subtitle "Envíos masivos y seguimiento de conversión".
- **Filters**: country selector (owner only) + branch selector, identical to `ReportesPage.vue` (lines 19–46).
- **Tabs** (`q-tabs`, `active-color="primary"`, `indicator-color="primary"`): tab **"Campañas"** (list) + per-campaign detail view with the funnel. Reuse the tab visual conventions and icons (`campaign`, `trending_up`).
- **Campaign list**: `q-table` or card list — name, status badge (`draft` grey / `sending` warning / `sent` positive), sent date, recipient count. Row click → funnel detail.
- **Funnel visualization (D-18)**: reuse the **`FunnelTab.vue`** chart pattern (chart.js/vue-chartjs already installed). Stages: **enviado → abierto → click → reservó → asistió → convirtió**. Bars/stages descend; first and "convirtió" stage in `$primary`.
  - **"Abierto" must be labeled approximate** (Apple Mail Privacy inflation): caption under the stage — "Aproximado (Apple Mail Privacy puede inflar las aperturas)." Reuse the `q-banner bg-orange-2 text-orange-10` caveat-banner pattern from `FunnelTab.vue`.
- **"Enviar campaña" action**: primary `q-btn color="primary"` with a confirmation dialog (`q-dialog`) summarizing recipient count before send (destructive-adjacent — irreversible mass send).
