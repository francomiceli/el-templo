  <name>Task 2: Add Sentry client-side error monitoring and structured logger</name>
  <files>
    el-templo-web/plugins/sentry.client.ts
    el-templo-web/utils/logger.ts
    el-templo-web/package.json (add @sentry/vue dep)

  <action>
    1. Install `@sentry/vue` in el-templo-web (same package used by el-templo-app and el-templo-admin).

    2. Create `plugins/sentry.client.ts` as a Nuxt client-side plugin (`defineNuxtPlugin`):
       - Get DSN from `useRuntimeConfig().public.sentryDsn`
       - Guard: `if (!dsn) return` — Sentry is optional
       - Import and init `@sentry/vue` with:
         - `app`: from `nuxtApp.vueApp`
         - `router`: from `useRouter()`
         - `dsn`: from runtimeConfig
         - `environment`: from runtimeConfig `appEnvironment` or fallback to `import.meta.env.MODE`
         - `integrations`: `[Sentry.browserTracingIntegration({ router })]`
         - `tracesSampleRate`: `0.2` in production, `1.0` otherwise
         - `initialScope`: `{ tags: { app_name: 'web' } }` — per user decision, distinguishes landing page errors from app/admin in shared Sentry project
         - `beforeSend`: reuse the same `shouldDropEvent` filter pattern from el-templo-app:
           - IGNORED_ERRORS: chunk load failures, resize observer, script error, network errors
           - DENY_URLS: browser extensions
           - Drop events matching these patterns

    3. Create `utils/logger.ts` following the project standard (CLAUDE.md: "Use createLogger() from src/utils/logger.ts. Never console.log/warn/error"):
       - Export `createLogger(context?: string)` returning `{ debug, info, warn, error }`
       - In production: `error()` calls `Sentry.captureException()` or `Sentry.captureMessage()`
       - In dev: logs to console with context prefix
       - Pattern: same as el-templo-app/src/utils/logger.ts but adapted for Nuxt (no Quasar boot context)

  </action>
