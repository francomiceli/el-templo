    **BudgetBar.vue:**
    Per user decision: visual budget bar, single bar, color thresholds green/yellow/red.

    Props:
    - currentReps: number (sum of all non-ISO exercise reps in block)
    - originalBudget: number (block's repsBudget)

    Template:
    - QLinearProgress (rounded, size="20px")
    - Progress value: Math.min(currentReps / originalBudget, 1.5) (cap at 150% for visual)
    - Color computed:
      - green: currentReps <= originalBudget (within budget)
      - yellow/amber: currentReps > originalBudget && currentReps <= originalBudget * 1.1 (within 10% over)
      - red/negative: currentReps > originalBudget * 1.1 (more than 10% over)
    - Label text overlay: "currentReps / originalBudget reps"
    - Per user decision: no auto-adjust, bar reflects changes passively

    **ContractionMixBadge.vue:**
    Per user decision: live contraction breakdown badge, turns red if mix violates intensity rules.

    Props:
    - exercises: SessionExercise[] (exercises in block)
    - intensity: number (block intensity)
    - blockRole: string (to skip INITIUM)

    Template:
    - Row of QBadge or QChip showing CON: X, EXC: Y, ISO: Z counts
    - Use contraction colors: CON=blue-grey, EXC=teal, ISO=orange
    - If violation detected: entire container gets red border or warning icon
    - Per user decision: soft warning, coach can override

    Validation logic:
    - Count exercises by contraction type
    - This is a DISPLAY-ONLY warning - no blocking behavior
    - INITIUM blocks skip validation (per existing pattern)
    - For non-INITIUM: the contraction_rules table defines expected counts per intensity/total_exercises
    - Since we can't easily query the DB from a Vue component, the validation is approximate:
      - Show the current counts as badges
      - The exact rule check happens server-side; here we just display the breakdown
      - If the parent provides a "warning" prop (from server validation), display it in red
    - Alternative simpler approach: just show the breakdown counts, and the server returns warnings in the session data

    Simpler implementation:
    - Just display CON: X, EXC: Y, ISO: Z as colored chips
    - Accept an optional `warning` string prop from parent
    - If warning is set, show a QIcon (warning, color=negative) with QTooltip showing the warning text
    - The warning text will come from future server-side validation on the session detail response
