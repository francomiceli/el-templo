  <files>el-templo-api/src/modules/admin/prescribe-service.ts</files>
  <action>
    Create `el-templo-api/src/modules/admin/prescribe-service.ts` that wraps the pipeline's prescription logic for single-exercise and full-block re-prescription.

    The service must:
    1. Import `prescribeByFormat` from `../../modules/sessions/pipeline/format-prescribers.ts`
    2. Import `calculateRest` logic (replicate the intensity-to-rest mapping from stage-7-prescription.ts since it's not exported)
    3. Import reps calculator utilities from the pipeline

    Methods:
    - `prescribeExerciseInBlock(params)`: Re-prescribe a single exercise within a block context.
      - Params: { exercise (id, name, contraction, difficulty), blockFormatName, blockRepsBudget, blockIntensity, existingExercises (for budget distribution) }
      - Uses prescribeByFormat to get format-specific prescription, then extracts the prescription for the target exercise position
      - Returns: { reps, seconds, rest, notes }
      - Per user decision: swapped exercise gets re-prescribed by algorithm within block's budget

    - `prescribeBlock(params)`: Re-prescribe all exercises in a block (used after format change).
      - Params: { exercises (array with id, name, contraction, difficulty), formatName, repsBudget, intensity }
      - Calls prescribeByFormat, falls back to standard distribution if format not recognized
      - Returns: array of { exerciseId, reps, seconds, rest, notes }
      - Per user decision: format change triggers automatic re-prescription of all exercises

    Important: Import DIRECTLY from the pipeline modules. Do NOT reimplement prescription logic. The prescribe service is a thin wrapper that adapts pipeline functions for on-demand use.

    The key adaptation: the pipeline works with `SelectedExercise` and `PrescriptionContext` types. Map from database exercise data to these types before calling prescribeByFormat.

    Read the SelectedExercise type from `el-templo-api/src/modules/sessions/types.ts` to understand the expected shape.
    Read `stage-7-prescription.ts` fully to understand calculateRest and the standard (non-format-specific) prescription fallback.
  </action>

<task type="auto">
  <name>Task 2: Create AdminEditService - exercise pool, CRUD operations, format change, reset, audit</name>
  <files>el-templo-api/src/modules/admin/edit-service.ts</files>
  <action>
    Create `el-templo-api/src/modules/admin/edit-service.ts` with the following methods:

    **Constructor:** Takes `db: MySql2Database<typeof schema>` (same pattern as AdminSessionService).

    **1. getExercisePool(params)**
    Query exercises table for swap candidates.
    - Params: { blockId, contraction?, route, pattern, excludeExerciseIds }
    - Filter by: route matching block's route, optionally filter by contraction type (effort column)
    - Include cross-route logic per 13-08: for non-INITIUM blocks, include pattern_2 exercises
      - Look up block's pattern field to determine if cross-route applies
      - Cross-route exercises come from SPOM pattern_2 (stored in block's pattern field as comma-separated or from lookup)
    - Sort by: closest linear difficulty (dificultadLineal) to the exercise being replaced
    - Each exercise returns: id, exercise (name), effort (CON/EXC/ISO), dificultadLineal, pattern, route
    - Per user decision: show name, CON/EXC/ISO badge, linear difficulty, pattern badge
    - Exclude exerciseIds already in the block

    **2. swapExercise(params)**
    Replace one exercise in a block with another.
    - Params: { sessionId, blockId, oldPrescriptionId, newExerciseId }
    - Look up the new exercise from exercises table
    - Use PrescribeService.prescribeExerciseInBlock to get prescription for the new exercise
    - Update the session_prescriptions row: exerciseId, exerciseName, contraction, reps, seconds, rest, notes, difficulty
    - If session is approved, revert status to pending_review (per user decision)
    - Log edit action to session_edit_logs
    - Return updated prescription data

    **3. updatePrescription(params)**
    Update prescription fields for an exercise.
    - Params: { sessionId, blockId, prescriptionId, fields: { reps?, seconds?, rest?, notes? } }
    - Simple UPDATE on session_prescriptions for the given fields
    - If session is approved, revert to pending_review
    - Log edit action

    **4. changeBlockFormat(params)**
    Change a block's format and re-prescribe all exercises.
    - Params: { sessionId, blockId, newFormatId, newFormatName }
    - Update session_blocks: formatId, formatName
    - Use PrescribeService.prescribeBlock to re-prescribe all exercises
    - Update all session_prescriptions for the block with new prescriptions
    - If session is approved, revert to pending_review
    - Log edit action
    - Return updated block data (for toast notification on frontend)

    **5. addExercise(params)**
    Add a new exercise to a block.
    - Params: { sessionId, blockId, exerciseId }
    - Look up exercise from exercises table
    - Insert new session_prescriptions row with: exerciseId, exerciseName, contraction, reps=0, seconds=0, rest=0, notes=null, difficulty=dificultadLineal, sortOrder=max+1
    - Per user decision: new exercises start with blank prescription - coach fills in manually
    - Update session_blocks.exerciseCount += 1
    - If session is approved, revert to pending_review
    - Log edit action

    **6. removeExercise(params)**
    Remove an exercise from a block.
    - Params: { sessionId, blockId, prescriptionId }
    - DELETE from session_prescriptions
    - Update session_blocks.exerciseCount -= 1
    - Reorder remaining prescriptions' sortOrder to be sequential
    - If session is approved, revert to pending_review
    - Log edit action

    **7. resetToAlgorithm(params)**
    Restore session to original algorithm output.
    - Params: { sessionId, userId }
    - Read sessions.algorithmSnapshot
    - If null, throw error (no snapshot available)
    - Delete all existing blocks and prescriptions (cascade handles prescriptions)
    - Re-insert blocks and prescriptions from snapshot
    - Reset status to pending_review
    - Log 'reset_to_algorithm' action

    **8. getCompatibleFormats(params)**
    Get formats compatible with a block's characteristics.
    - Params: { blockRole, level, intensity }
    - Map blockRole to format_compatibility block enum (INITIUM->initium, NUCLEUS->nucleus, DEUTEROS_1/2->deuteros, ATHLOS/EPIKOS->athlos or epikos)
    - Map level string to compatibility level enum (spartan->omega per existing convention)
    - Query format_compatibility table where compatibility > 0 for the block/level/intensity
    - Join with formats table to get format names
    - Sort by compatibility score descending (best matches first)
    - Per user decision: dropdown shows only compatible formats, sorted by score

    **Helper: revertToPendingIfApproved(sessionId)**
    Private method that checks session status and reverts to pending_review if currently approved.
    Per user decision: editing an approved session automatically reverts to pending.

    **Helper: logEdit(sessionId, userId, action)**
    Insert into session_edit_logs.
    Per user decision: simple log with action type, no field-level detail.
  </action>
