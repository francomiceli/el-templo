  <action>
    **batch.py** — Batch processing engine with resume capability. Implement:

    1. `VideoStatus` — String enum: PENDING, PROCESSING, COMPLETED, FAILED, FLAGGED_WATERMARK, SKIPPED.

    2. `load_progress(progress_path: Path) -> dict` — Loads progress.json if it exists, otherwise returns default structure:
       ```python
       {
         "started_at": str,      # ISO timestamp
         "updated_at": str,      # ISO timestamp
         "videos": {},           # filename -> {status, started, completed, error, file_size, duration}
         "stats": {"completed": 0, "failed": 0, "skipped": 0, "flagged": 0, "pending": 0}
       }
       ```

    3. `save_progress(progress_path: Path, progress: dict) -> None` — Writes progress.json atomically (write to temp file then rename, to avoid corruption if interrupted mid-write).

    4. `update_video_status(progress: dict, filename: str, status: str, error: str | None = None, file_size: int = 0, duration: float = 0.0) -> None` — Updates a single video entry and recalculates stats.

    5. `run_batch(input_dir: Path, output_dir: Path, progress_path: Path, logo_path: Path | None = None, max_workers: int = 1, skip_watermark_check: bool = False) -> dict` — The main batch processor:
       - Discover all video files in input_dir (use SUPPORTED_EXTENSIONS from config)
       - Load progress.json, skip already COMPLETED videos
       - Create output_dir if needed
       - Process each video sequentially (max_workers=1 by default — MediaPipe + OpenCV memory-intensive)
       - For each video:
         - Update status to PROCESSING, save checkpoint
         - Call `process_video()` from processor module
         - Update status based on result, save checkpoint after EACH video
         - Use tqdm for progress bar display
       - If max_workers > 1, use `concurrent.futures.ProcessPoolExecutor` for parallel processing
         - Note: Each worker needs its own MediaPipe segmenter instance (created inside process_video)
       - Return final stats dict
       - Handle KeyboardInterrupt gracefully — save progress and exit cleanly

    6. `retry_failed(input_dir: Path, output_dir: Path, progress_path: Path, logo_path: Path | None = None) -> dict` — Re-process only videos with status FAILED. Reset their status to PENDING and run batch on them.

    7. `get_pending_videos(progress_path: Path, input_dir: Path) -> list[Path]` — Returns list of video paths not yet completed (for dry-run display).

    **report.py** — Summary report generator. Implement:

    1. `generate_report(progress_path: Path, output_dir: Path, report_path: Path | None = None) -> str` — Reads progress.json and output directory, generates a text report:
       ```
       ═══════════════════════════════════════
       El Templo Video Pipeline — Batch Report
       ═══════════════════════════════════════

       Run: 2026-02-15 03:45:22 → 2026-02-15 08:12:45
       Duration: 4h 27m 23s

       Summary:
         Total videos:     150
         Completed:        142  (94.7%)
         Failed:             5  (3.3%)
         Flagged (review):   2  (1.3%)
         Skipped:            1  (0.7%)

       Output:
         Total size:       856 MB
         Avg file size:    6.0 MB
         Avg duration:     7.2s

       Failed Videos:
         1. deadlift-conventional.mp4 — FFmpeg encoding error: ...
         2. turkish-getup.mp4 — No person detected in any frame

       Flagged for Review (possible watermark):
         1. overhead-press.mp4
         2. cable-fly.mp4

       ═══════════════════════════════════════
       ```
       Returns the report as a string and optionally writes to report_path.

    2. `print_report(progress_path: Path, output_dir: Path) -> None` — Prints the report to stdout.

    Use tqdm for batch progress. Use type hints throughout. No `any` types. Import from config.py where applicable.

  </action>

  <action>
    **cli.py** — argparse-based CLI with subcommands. Implement:

    Main parser with subcommands:

    1. **`source`** subcommand — Source videos from the web:
       - `--level` — Filter exercises by level (e.g., "alfa"). Optional, defaults to all.
       - `--output-dir` — Output directory for downloaded videos. Default: `input/`
       - `--manifest` — Path to manifest JSON. Default: `input/manifest.json`
       - `--rate-limit` — Seconds between requests. Default: 3.0
       - `--dry-run` — List exercises that would be sourced without downloading
       - Action: Calls `get_exercise_list(level)` then `batch_source(exercises, output_dir, manifest, rate_limit)`

    2. **`process`** subcommand — Process a single video:
       - `input` — Input video path (positional)
       - `output` — Output video path (positional)
       - `--no-watermark-check` — Skip watermark detection
       - `--no-logo` — Skip logo watermark overlay
       - Action: Calls `process_video(input, output)`

    3. **`preview`** subcommand — Generate single-frame preview PNG:
       - `input` — Input video path (positional)
       - `--output` — Output PNG path. Default: replaces extension with `.preview.png`
       - Action: Calls `preview_frame(input, output)`

    4. **`batch`** subcommand — Batch process all videos:
       - `--input-dir` — Input directory. Default: `input/`
       - `--output-dir` — Output directory. Default: `output/`
       - `--progress` — Progress file path. Default: `progress.json`
       - `--workers` — Number of parallel workers. Default: 1
       - `--no-watermark-check` — Skip watermark detection for all videos
       - `--no-logo` — Skip logo watermark
       - `--retry` — Only re-process failed videos
       - Action: Calls `run_batch()` or `retry_failed()`, then `print_report()`

    5. **`report`** subcommand — Show batch report:
       - `--progress` — Progress file path. Default: `progress.json`
       - `--output-dir` — Output directory. Default: `output/`
       - `--save` — Save report to file
       - Action: Calls `print_report()` or `generate_report()`

    6. **`status`** subcommand — Show current batch status:
       - `--progress` — Progress file path. Default: `progress.json`
       - `--input-dir` — Input directory. Default: `input/`
       - Action: Shows pending/completed/failed counts without running anything

    Main entry point function `main()`:
    - Parse args with argparse
    - Dispatch to appropriate function
    - Handle errors with clean exit codes (0=success, 1=error)

    Update `pyproject.toml` to register the CLI entry point:
    ```toml
    [project.scripts]
    pipeline = "pipeline.cli:main"

    uv run pipeline report
    uv run pipeline status
    ```

    Add a `--verbose` / `-v` flag to the main parser that increases output detail.

    Use type hints throughout. No `any` types.
