<task type="auto">
  <name>Task 2: Implement video sourcing module with YouTube and stock site search</name>
  <files>
    el-templo-video-pipeline/src/pipeline/sourcer.py
  </files>
  <action>
    **sourcer.py** — Searches for exercise demonstration videos and downloads the best match.

    Implement:

    1. **Curated YouTube channels** — Define a list of preferred YouTube channels known for clean, single-person exercise demonstrations. Research and include channels like:
       - ScottHermanFitness
       - JEFIT (exercise database channel)
       - MuscleWiki
       - Bodybuilding.com
       - ExRx.net
       - ACE Fitness
       - National Academy of Sports Medicine (NASM)
       - Any other high-quality exercise demo channels with consistent formatting

       Store as `CURATED_CHANNELS: list[str]` constant.

    2. `search_youtube(exercise_name: str, curated_only: bool = True) -> dict | None` — Uses yt-dlp to search YouTube. Strategy:
       - First: Search within curated channels (append `channel:ChannelName` to query or use `ytsearch` with channel filter)
       - If curated_only=False and no curated result: Broad YouTube search with query `"{exercise_name}" exercise demonstration`
       - Selection priority per CONTEXT.md: single person > clean background > good quality
       - Use yt-dlp's `extract_info` with `download=False` first to evaluate results
       - Pick the first result that looks like an exercise demo (title contains exercise name or keywords)
       - Return dict with `url`, `title`, `duration`, `channel`, `source: "youtube"` or None if no match

    3. `search_stock_sites(exercise_name: str) -> dict | None` — Searches Pexels and Pixabay APIs for exercise videos:
       - Pexels: Use their free video search API (API key from env var `PEXELS_API_KEY`, optional)
       - Pixabay: Use their free video search API (API key from env var `PIXABAY_API_KEY`, optional)
       - Return dict with `url`, `title`, `duration`, `source: "pexels"|"pixabay"` or None
       - Skip each site if its API key is not set (graceful degradation)

    4. `download_video(video_info: dict, output_path: Path) -> bool` — Downloads the video:
       - For YouTube: Use yt-dlp to download with `format: "bestvideo[height<=1080]+bestaudio/best[height<=1080]"` or just `"best[height<=1080]"`. Merge to mp4.
       - For stock sites: Direct HTTP download with requests
       - Returns True on success, False on failure
       - Writes to `output_path`

    5. `source_exercise_video(exercise_name: str, output_dir: Path, slug: str, rate_limit_seconds: float = 2.0) -> dict` — Orchestrates the full sourcing for one exercise:
       - Search YouTube curated channels first
       - If not found: Search YouTube broadly
       - If not found: Search stock sites
       - If found: Download to `output_dir / f"{slug}.mp4"`
       - Return result dict: `{"exercise": name, "slug": slug, "status": "downloaded"|"no_video_found"|"download_failed", "source_url": url, "source": "youtube"|"pexels"|"pixabay", "filename": str}`
       - Apply rate limiting: `time.sleep(rate_limit_seconds)` between searches
       - Log progress with print statements (will be replaced with proper logging later)

    6. `batch_source(exercises: list[dict], output_dir: Path, manifest_path: Path, rate_limit: float = 3.0) -> dict` — Batch sources videos for a list of exercises:
       - Iterate through exercises, call `source_exercise_video` for each
       - Write results to a JSON manifest file at `manifest_path` (append/update, not overwrite)
       - Skip exercises already in manifest with status "downloaded"
       - Track stats: `{"total": N, "downloaded": N, "no_video_found": N, "failed": N, "skipped": N}`
       - Return stats dict

    Add `PEXELS_API_KEY` and `PIXABAY_API_KEY` to `.env.example` (optional, with comment explaining they're only needed for stock site fallback).

    Important implementation notes:
    - yt-dlp should be imported as `yt_dlp` and used programmatically (not via subprocess)
    - Handle network errors gracefully with try/except — never crash the batch
    - Rate limiting is configurable per CONTEXT.md to avoid getting blocked
    - All downloads go to the pipeline's `input/` directory by convention (gitignored)
    - Use type hints throughout, no `any` types
