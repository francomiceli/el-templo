# Phase 144 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**App:** `el-templo-app` (member app — Quasar + Vue 3 + Capacitor). Admin app is NOT touched.

**Scope:** Two net-new in-app dialogs in the member app, plus push-notification copy. Both dialogs reuse the existing skippable-card convention (`RatingPromptDialog.vue`, `PushPermissionDialog.vue`) — a dark charcoal `q-card` inside a `q-dialog`, Montserrat title, Geologica body, terracotta gradient primary CTA, flat "Ahora no" secondary. NO new design-system primitives are introduced.

| Surface                                                     | Trigger                                                 | Spec ref   |
| ----------------------------------------------------------- | ------------------------------------------------------- | ---------- |
| 1. Expiry pop-up (`PlanExpiryDialog.vue`, new)              | App open/foreground when covered-until ≤3 days          | D-06..D-10 |
| 2. Booking-block pop-up (in `ReservasPage.vue`, new dialog) | `reserve()` rejected because class date > covered-until | D-12, D-15 |
| 3. Push copy (not in-app UI)                                | Cron 7d / 3d / expiry-day                               | D-02, D-04 |

## Spacing Scale

Declared values (8-point base):

| Token | Value | Usage                                                                  |
| ----- | ----- | ---------------------------------------------------------------------- |
| xs    | 4px   | `q-card-actions` gap between primary/secondary, secondary `margin-top` |
| sm    | 8px   | Card outer padding top, icon section padding                           |
| md    | 16px  | Body padding-top, title bottom margin, actions vertical padding        |
| lg    | 24px  | (reserved — not needed at this card size)                              |

Exceptions: `12px` (title bottom margin in push-style card, card bottom padding) and `20px` (`q-card-actions` horizontal padding). Both are pre-existing dialog conventions in `RatingPromptDialog.vue` / `PushPermissionDialog.vue` and MUST be matched for visual parity. Card `border-radius: 16px`, button `border-radius: 8px`. Card `max-width: 340px`, `width: 100%`.

## Color

Contract applies to the dialog surfaces (dark charcoal cards), per existing convention. Source of truth: `el-templo-app/src/css/_brand.scss` + `quasar.variables.scss`.

| Role            | Value                     | Usage                                                                      |
| --------------- | ------------------------- | -------------------------------------------------------------------------- |
| Dominant (60%)  | `#2e2a26` (charcoal card) | Dialog `q-card` background                                                 |
| Secondary (30%) | `#f2ede5` (marble cream)  | All text; reduced opacity for helper/secondary (`rgba($cream, 0.55–0.75)`) |
| Accent (10%)    | `#96593a` (terracotta)    | See reserved-for list below                                                |
| Destructive     | not applicable            | No destructive actions in this phase                                       |

Accent reserved for: (a) primary CTA `q-btn` gradient `linear-gradient(135deg, #96593a 0%, #ad6540 100%)`; (b) card `border-top: 2px solid rgba(#96593a, 0.6)`; (c) optional leading `q-icon` tint in the expiry card. NOT used on the "Ahora no" / "Entendido" secondary button (stays `rgba($cream, 0.55)`), NOT on body text.

No new semantic colors. The block/expiry dialogs are advisory, not error-red — use the terracotta accent, NOT `$negative`. The pre-existing generic reserve failure path keeps its `$q.notify({ type: 'negative' })`.

## Component & Interaction Contract

### Surface 1 — `PlanExpiryDialog.vue` (NEW component)

Clone `RatingPromptDialog.vue` structure and styles.

- `q-dialog v-model="show"` — NOT `persistent` (D-07: skippable, does not block app).
- Single primary CTA `Renovar por WhatsApp` → open `buildWhatsAppUrl(authStore.country, 'Hola, quiero renovar mi membresía 💪')` (helper `el-templo-app/src/utils/whatsapp.ts`). Open via the same external-link mechanism existing CTAs use (Capacitor `Browser` / `window.open`).
- Secondary flat `Ahora no` → close, record "shown today".
- Tapping the CTA also records "shown today" and closes.
- Optional leading `q-icon` (`event_busy` or `schedule`, terracotta tint) mirroring `PushPermissionDialog` icon section — allowed, not required.
- Trigger: `watch(authStore.isAuthenticated, immediate)` + foreground, exactly like `RatingPromptDialog` / `PushPermissionDialog`.
- `shouldShow()` gate (D-06/D-08/D-10): authenticated AND covered-until ≤3 days AND not already shown today. Persist last-shown date with Capacitor `Preferences` (key e.g. `plan_expiry_shown_v1` storing `YYYY-MM-DD`); reappears at most once per calendar day until covered-until extends. Planner decides server-vs-local source of the covered-until value; persistence of "shown today" is local (`Preferences`), matching D-08 discretion and the established one-shot pattern.

### Surface 2 — Booking-block dialog (NEW dialog inside `ReservasPage.vue`)

- Add a `q-dialog` styled identically to the charcoal cards (reuse the same scoped classes — extract a shared style or duplicate the existing block; do NOT invent new styling).
- Wire into `confirmReserve()` `catch` (`ReservasPage.vue` ~L1200). Discriminate the D-12 error: when the backend returns the distinguishable code/discriminator (e.g. `err.response?.data?.code === 'COVERAGE_EXPIRED'` — exact code set by the API task), open THIS dialog instead of the generic `$q.notify({ type: 'negative' })`. All other reserve errors keep the existing notify path unchanged.
- Primary CTA `Renovar por WhatsApp` → `buildWhatsAppUrl(country, 'Hola, quiero renovar mi membresía para reservar una clase 💪')`.
- Secondary flat `Entendido` → close. No persistence (it is action-scoped, re-shows whenever the member retries a too-late class).
