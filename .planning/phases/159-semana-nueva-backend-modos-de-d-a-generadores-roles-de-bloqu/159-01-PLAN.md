<objective>
Extender los contratos de tipos, los validadores y el JSON Schema del body para que el sistema RECONOZCA los dos modos nuevos (`combos`, `tecnica`) y los cinco roles de bloque nuevos (COMBOS_I/II, TECNICA_I/II, STRETCHING) SIN cambio de schema de DB (las columnas ya son varchar libres). Este plan es la base de tipos que consumen los generadores (plan 02/03) y el ruteo (plan 05).

La ÚNICA red de contención contra un `session_mode` arbitrario persistido es el `enum` del JSON Schema del body de `/generate` (V5 Input Validation). Los dos `Record<BlockRole, …>` exhaustivos convierten la extensión de roles en un checklist de compilación. Combos/técnica se seleccionan EXCLUSIVAMENTE como override per-request en `/generate` (`dayModes`, plan 05), NUNCA como valor fijable de la fila `day_modes` (D-02): `day_modes` es config persistente semana-independiente, y fijar combos/tecnica ahí reabriría el modelo de "día fijo" que la evidencia de prod W21–W26 (alternancia por decisión del coach) desmiente.
