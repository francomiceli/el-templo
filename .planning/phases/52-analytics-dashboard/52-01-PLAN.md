    **types.ts** — Define response interfaces:
    - `KpiStats`: activeMembers (number), monthlyRevenue (number), dailyAttendanceAvg (number), morososCount (number). Each with a `trend` sub-object: { direction: 'up' | 'down' | 'flat', percentage: number }.
    - `AttentionMember`: userId (number), firstName (string|null), lastName (string|null), planName (string), phone (string|null), type ('expiring' | 'overdue'), daysUntilExpiry (number|null), daysOverdue (number|null).
    - `MemberAnalytics`: newMembers (number), churnedMembers (number), retentionRate (number), planDistribution (Array<{ planName: string, count: number }>), attentionList (AttentionMember[]).
    - `HeatmapCell`: dayOfWeek (number 1-6), hour (number 6-22), averageOccupancy (number 0-100).
    - `SlotOccupancy`: scheduleId (number), activityName (string), dayOfWeek (number), startTime (string), averageOccupancy (number).
    - `AttendanceAnalytics`: dailyCheckins (Array<{ date: string, count: number }>), peakHoursHeatmap (HeatmapCell[]), slotOccupancy (SlotOccupancy[]), noShowRate (number).
    - `FinancialAnalytics`: revenueTrend (Array<{ month: string, revenue: number }>), revenueByMethod ({ cash: number, transfer: number, card: number }), revenueByBranch (Array<{ branchId: number, branchName: string, revenue: number }>), totalOutstanding (number), collectionRate (number).
    - `AnalyticsFilters`: branchId? (number), dateFrom? (string YYYY-MM-DD), dateTo? (string YYYY-MM-DD).

    **service.ts** — AnalyticsService with constructor DI (db, log):

    `getKpis(filters)`: Run 4 parallel aggregate queries:
    1. Active members count: COUNT users WHERE role='member' AND isActive=true (+ branch filter). For trend: compare against prior period of same length.
    2. Monthly revenue: SUM non-voided payments in period (reuse same logic as PaymentService.getFinancialSummary). Trend vs prior period.
    3. Daily attendance average: COUNT attendance records in period / number of days in period. Trend vs prior period.
    4. Morosos count: COUNT members with overdue subscriptions (endDate < CURDATE() AND payments sum < pricePaid). Use correlated subquery pattern from payments module.
    Compute trend for each KPI using `computeTrend(current, prior)` helper: percentage = abs((current - prior) / prior * 100), direction = up/down/flat.

    `getMemberAnalytics(filters)`:
    1. New members: COUNT users WHERE role='member' AND createdAt within date range (+ branch filter).
    2. Churned members: COUNT subscriptions WHERE status='cancelled' AND updatedAt within date range.
    3. Retention rate: (members with active/paused subscription) / (total members who had a subscription ending in period) * 100. Use subscriptions table: count those whose endDate falls in period, count those who renewed (have a newer subscription after that one).
    4. Plan distribution: COUNT subscriptions grouped by plan name WHERE status in ('active', 'paused').
    5. Attention list: UNION of (a) members with active subscriptions expiring in next 7 days and (b) overdue members (reuse overdue subquery pattern). Include phone for WhatsApp link. Limit to 20 items, ordered by urgency (days until expiry ASC, then days overdue DESC).

    `getAttendanceAnalytics(filters)`:
    1. Daily checkins: COUNT attendance grouped by DATE(checkedInAt) within date range, ordered by date ASC. Include all dates (even zero days — fill gaps in SQL or service layer).
    2. Peak hours heatmap: For each (dayOfWeek, HOUR(checkedInAt)) combination, compute average check-ins per week in the period. Normalize to 0-100 scale based on branch maxCapacity. Use attendance table + branch filter.
    3. Slot occupancy: For each active schedule, compute average bookings per occurrence vs maxCapacity over the period. Join bookings WHERE status='confirmed' grouped by scheduleId, divide by number of weeks in period.
    4. No-show rate: COUNT bookings WHERE status='no_show' / COUNT bookings WHERE status IN ('confirmed','no_show') * 100 in the date range. If no bookings, return 0.

    `getFinancialAnalytics(filters)`:
    1. Revenue trend: SUM non-voided payments grouped by YEAR-MONTH, for each month in date range. If dateFrom/dateTo span multiple months, return one entry per month.
    2. Revenue by method: SUM grouped by paymentMethod (same as PaymentService but fresh query with date filters).
    3. Revenue by branch: SUM grouped by user's branchId joined to branches table.
    4. Outstanding + collection rate: Reuse same logic as PaymentService.getFinancialSummary — overdue subscriptions where payments < pricePaid.

    All methods must handle the case where no filters are provided — default to current month (same pattern as PaymentService).

    **schemas.ts** — Fastify JSON schemas for request querystring validation (branchId optional integer, dateFrom/dateTo optional string format date) and response body schemas for each endpoint.

    **routes.ts** — FastifyPluginAsync:
    - Plugin-level onRequest hook for admin role guard (same pattern as members/routes.ts).
    - GET / (kpis) — returns KpiStats
    - GET /members — returns MemberAnalytics
    - GET /attendance — returns AttendanceAnalytics
    - GET /financial — returns FinancialAnalytics
    - All accept querystring: branchId?, dateFrom?, dateTo?
    - Use handleServiceError pattern (try/catch wrapping service calls).

    **index.ts** — Barrel export: `export { analyticsRoutes } from './routes'`

    **app.ts** — Register: `await app.register(analyticsRoutes, { prefix: '/api/admin/analytics' })` after the scheduling routes. Add import at top.
