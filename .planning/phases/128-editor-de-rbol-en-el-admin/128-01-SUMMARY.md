# Phase 128 Plan 01: Locked-Partition Guard Summary

Manual profe overrides now PREVAIL over the SPOM auto order and SURVIVE a full graph rebuild — the rebuild constructor skips both the auto-delete and auto-insert for any `(subfamily_id × effort)` partition that owns a same-partition `manual` edge (D-02, the load-bearing risk mitigation of TREE-07).

## What Was Built

### Task 1 — Locked-partition guard in the rebuild WRITE step (commit `38ed955d`)

`runRebuildProgressionGraph` now:

1. **Derives the LOCKED partition set** via `readManualEdgePartitions` — a SQL join of `exercise_progressions` (source='manual') to the `exercises` of BOTH endpoints, keeping only rows where the FROM and TO nodes share `subfamily_id` AND `effort` (a same-partition chain rewrite, D-03). Both endpoints must be confirmed/canonical/valid-effort, matching the node READ. Result is narrowed by `readManualEdgePartitionRows` with the same defensive, `any`-free pattern as `readExerciseNodes`.
2. **Skips locked partitions on insert** — `buildBackboneEdges(nodes, lockedPartitions)` emits NO backbone edges for any node whose `${subfamilyId}|${effort}` key is locked (the EXACT key shape the builder already uses).
3. **Replaces the global `DELETE ... WHERE source='auto'`** with a partition-scoped delete: `WHERE source='auto' AND from_exercise_id IN (<unlocked node ids>)`, built from `nodes` minus locked partitions. An empty unlocked-id list skips the delete entirely (empty `IN ()` is a MySQL syntax error).
4. **Reports** nodes, partitions, **locked-partition count**, and auto edges written (now unlocked-only).

No new DB column, no migration, no enum rename — `source` is the real existing column (D-01). No `any`.

### Task 2 — Dedicated integration test (commit `f2e58c07`)

Added `it("locked partition — ... is NOT regenerated; untouched partitions still regenerate (D-02)", ...)` to the existing `describe("rebuild-progression-graph (Phase 126 Plan 02)")` block, reusing the file's `seedSubfamily`/`seedExercise`/`getAutoEdges` helpers and afterEach cleanup. It:

- Seeds partition **X** (subfamily X, CON, dl 1/3/5) whose auto chain is REPLACED by a MANUAL chain in a different order (5→1→3), and partition **Y** (subfamily Y, CON, dl 1/3/5) left untouched.
- Runs the rebuild and asserts the EXACT edge set: **X** keeps exactly its 2 manual edges with zero auto; **Y** regenerates its full auto backbone (y1→y3, y3→y5).
- Re-runs the rebuild for regression: **X**'s manual edges are unchanged and **Y** has no duplicate auto edges.

This test FAILS against the pre-Task-1 constructor (the old global delete would wipe X's edges) and PASSES against the guarded constructor.
