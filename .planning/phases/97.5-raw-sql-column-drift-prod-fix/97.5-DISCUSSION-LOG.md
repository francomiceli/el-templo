## Sweep-lint scanner strategy

| Option                                    | Description                                                                                                                                                                   | Selected |
| ----------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------- |
| Regex + line accumulator                  | Walk `.ts` files; find `` sql`...` `` blocks via stateful line accumulator (multi-line); regex aliases + column refs. ~30–60 LOC, zero new deps, fast on 175 known sites.     | ✓        |
| ts-morph AST parser                       | Add `ts-morph` devDep; walk TS AST for `TaggedTemplateExpression` nodes with `sql` tag. Robust against weird formatting; ~5MB dep; ~80–120 LOC; slower test boot.             |          |
| Hybrid — regex blocks, mini-parser bodies | Regex finds `` sql`...` `` blocks; tiny hand-rolled tokenizer parses `FROM/JOIN <table> <alias>` and `<alias>.<col>`. Engineering-balance middle ground but extra complexity. |          |

**User's choice:** Option 1 — regex + line accumulator, zero new deps.

**Notes:** Two REQUIRED scope additions documented as sub-clauses in CONTEXT.md D-02:

- (i) **Detect bare unqualified columns in single-table queries** (parse FROM/JOIN; in single-table blocks, cross-check bare tokens against the FROM-table's renamed columns too). The codebase mixes both styles (`SELECT sub.status FROM subscriptions sub` AND `SELECT id, conversation_status FROM whatsapp_conversations` no-alias). Without bare-column detection, a future `SELECT status FROM subscriptions` drift is a false negative.
- (ii) **Synthetic-drift positive-control test** — feed scanner a known-drift fixture string; assert it flags it. Guards against scanner silently becoming a no-op (regex bug → matches nothing → false green). Survives PERMANENTLY in the test file after real drift is fixed.
- (iii) Skip Drizzle-interpolated refs (`${schema.table.column}`) — they resolve at query build.

Rationale: 175 SQL sites are uniform/finite (sweep-confirmed); this lint is a SECONDARY guard behind the D-01 RED integration test, so AST precision overkill; ts-morph is a 5MB dep this codebase doesn't need.

## Rename map source

| Option                               | Description                                                                                                                                                             | Selected |
| ------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------- |
| Hybrid: introspect + assert coverage | Live Drizzle introspection at test boot AND assert discovered map covers the 22 high-risk renames from debug-session sweep. Auto-updates + guards against silent no-op. | ✓        |
| Live Drizzle introspection only      | Walk schema exports, read each column's `.name`. Map auto-updates. Risk: if Drizzle internals shift or import breaks, map silently empties — false green.               |          |
| Hand-maintained constant             | Hardcode the 22 high-risk renames as a `const`. Predictable; drifts from schema over time; violates DRY against Drizzle declarations.                                   |          |

**User's choice:** Option 1 — hybrid live introspection + must-include SUBSET coverage assertion.

**Notes:** REQUIRED: coverage assertion is SUBSET / must-include (`discoveredMap ⊇ knownHighRiskSet`), NOT equality. Equality would break every time a new schema column-rename is added in v5.4.0+, defeating the auto-coverage benefit. Anchor on plain-word → prefixed renames (status/source/direction/level → prefixed); medium camelCase → snake renames covered by introspection but not asserted. Same guard-the-guard logic as D-02 (ii): if Drizzle internals shift or a schema import breaks, the coverage assertion fails LOUD instead of the scanner silently checking nothing.
