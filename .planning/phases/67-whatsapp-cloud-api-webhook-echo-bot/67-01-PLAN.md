**el-templo-bot/src/whatsapp/types.ts** — Define complete Meta webhook payload types:

Replace the stub with full types based on Meta's Cloud API webhook format:
- `MetaWebhookPayload` — the top-level POST body from Meta (object, entry[], changes[])
- `MetaWebhookEntry` — entry with id and changes array

- `MetaWebhookStatus` — id, status (sent/delivered/read), timestamp, recipient_id
- `ParsedInboundMessage` — the parsed result used by the bot: phone, contactName, text, messageType, whatsappMessageId, timestamp, rawPayload (the original full body)

**el-templo-bot/src/whatsapp/client.ts** — Implement Cloud API functions:

1. `verifyWebhook(mode: string, token: string, challenge: string): string | null` — If mode is "subscribe" and token matches `WHATSAPP_VERIFY_TOKEN` env var, return challenge. Otherwise return null. Pure function, no HTTP.

2. `sendTextMessage(phone: string, text: string): Promise<string>` — POST to `https://graph.facebook.com/v21.0/{WHATSAPP_PHONE_ID}/messages` with:
   - Headers: `Authorization: Bearer {WHATSAPP_TOKEN}`, `Content-Type: application/json`
   - Body: `{ messaging_product: "whatsapp", to: phone, type: "text", text: { body: text } }`
   - Return the `messages[0].id` from the response (the wamid of the sent message)
   - Use Node.js native `fetch` (available in Node 22). No axios dependency.
   - On error: log with Pino and throw. Do NOT swallow errors silently.

3. `parseWebhookPayload(body: MetaWebhookPayload): ParsedInboundMessage | null` — Extract the first text message from the Meta payload. Return null if: no messages in payload, message type is not "text", or no text body. This handles the "ignore non-text messages silently" user decision. Store the full body as `rawPayload`.

Use a module-level Pino logger instance: `import pino from "pino"; const log = pino({ name: "whatsapp-client" });`
