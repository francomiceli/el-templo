Create new directory `el-templo-bot/src/webhook/` with two files.

**el-templo-bot/src/webhook/handler.ts** — Core message processing logic:

Export `handleInboundMessage(db, log, message: ParsedInboundMessage): Promise<void>`:

1. **Find or create conversation:**
   - Query `whatsapp_conversations` by phone number
   - If not found: INSERT new row with `phone`, `contactName`, `status: "active"`, `clientState: "lead"`, `lastMessageAt: now()`. Use Drizzle's `insert().values()`.
   - If found: UPDATE `lastMessageAt` to now() and `contactName` if changed. Use Drizzle's `update().set().where()`.

2. **Dedup check:**
   - Try to INSERT the inbound message into `whatsapp_messages`. Use: `conversationId`, `direction: "inbound"`, `content: message.text`, `messageType: "text"`, `whatsappMessageId: message.whatsappMessageId`, `rawPayload: message.rawPayload`.
   - If INSERT fails with a duplicate key error on `whatsapp_message_id` (MySQL error code 'ER_DUP_ENTRY' or code 1062), log a warning and return early — do not echo.
   - Important: Catch the specific MySQL duplicate error, not all errors. Check `err.code === 'ER_DUP_ENTRY'` or `err.errno === 1062`.

3. **Echo reply:**
   - Format reply: `"Echo: " + message.text`
   - Call `sendTextMessage(message.phone, replyText)` — this returns the wamid of the sent message.
   - INSERT the outbound message into `whatsapp_messages`: `conversationId`, `direction: "outbound_bot"`, `content: replyText`, `messageType: "text"`, `whatsappMessageId: sentWamid`.
   - If sendTextMessage fails (e.g., network error), log the error but do NOT crash — the inbound message is already saved. The reply is best-effort.

Use constructor injection pattern: the function receives `db` (Drizzle instance) and `log` (Pino logger) as parameters.

**el-templo-bot/src/webhook/routes.ts** — Fastify plugin:

Export `webhookRoutes: FastifyPluginAsync`:

1. **GET /webhook** — Meta verification handshake:
   - Extract query params: `hub.mode`, `hub.verify_token`, `hub.challenge`
   - Call `verifyWebhook(mode, token, challenge)` from whatsapp/client.ts
   - If result is non-null: return 200 with the challenge string as plain text (not JSON)
   - If null: return 403 with `{ error: "Forbidden" }`
   - Use Fastify's typed generics: `fastify.get<{ Querystring: { "hub.mode"?: string; ... } }>`

2. **POST /webhook** — Incoming messages:
   - Always return 200 immediately for Meta (they retry on non-200). Use `reply.code(200).send("EVENT_RECEIVED")` after triggering async processing.
   - Parse body with `parseWebhookPayload(request.body)`.
   - If parse returns null (non-text, status update, no message): return 200 immediately.
   - If parse returns a message: call `handleInboundMessage(fastify.db, request.log, message)` — but do NOT await it before sending 200. Instead, fire-and-forget with `.catch(err => request.log.error({ err }, "Error handling inbound message"))`.
   - This pattern ensures Meta always gets a fast 200 and never retries unnecessarily.

2. Register it: `app.register(webhookRoutes)` (no prefix — routes are already /webhook)
