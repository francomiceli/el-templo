Contratos NUEVOS:
- `getCatalogForAdmin(db, ctx)` → `{ ladders: { id; code; name; sortOrder; isActive; rungs: { id; code; name; position; brazosRectos; unilateral; isActive; inUse: boolean }[] }[]; exercises: { id; code; name; ladderId; ladderCode; unit; muscles; startSteps; sortOrder; isActive }[]; templateDays: TemplateDayView[]; zones: { slug: string; label: string }[] }`
  (`inUse` = algún `conquer_steps` del gimnasio apunta al peldaño; una query con GROUP BY).
- `createRung(db, ctx, ladderId, body: { name: string 1-60; brazosRectos: boolean; unilateral: boolean })` — se agrega al final (más
  fácil); `code` = slug ASCII del nombre, único en la escalera (sufijo `_2`, `_3` si choca); 404 si la escalera no es del gimnasio.
- `updateRung(db, ctx, rungId, body: { name?; brazosRectos?; unilateral?; isActive? })` — `isActive: false` sobre un peldaño usado en
  algún `start_steps` de un ejercicio de su escalera → 409 `CONQUER_PELDANO_EN_ARRANQUE`; desactivar el último activo → 409
  `CONQUER_ESCALERA_VACIA`. Nunca se borra un peldaño.
- `reorderRungs(db, ctx, ladderId, body: { rungIds: number[] })` — tienen que ser EXACTAMENTE todos los peldaños de la escalera (400 si
  no); en transacción: posiciones temporales `1000 + i` y después `i` (evita chocar con el UNIQUE de posición). Índice 0 = más difícil.
- `updateExercise(db, ctx, exerciseId, body: { name?; startSteps?; muscles? })` — `startSteps` = exactamente 4 (e1, e2, e3, hold, sin
  repetir), `rung` = `code` de un peldaño ACTIVO de la escalera del ejercicio, `mode` válido y `hold` con `mode "hold"`; `muscles` con
  `isConquerZone`, rol principal|secundario, sin pares repetidos y al menos una principal. `unit` y escalera NO se editan (consistencia
  del historial). 400 `CONQUER_CATALOGO_INVALIDO` con el detalle en el mensaje.
- `updateTemplateDay(db, ctx, id, body: { label?; finisherText?; exerciseCodes? })` — 3 códigos distintos de ejercicios activos; ningún
  ejercicio repetido entre los días del mismo `days_count` (409 `CONQUER_EJERCICIO_REPETIDO`: `conquer_steps` se identifica por
  ejercicio). Los alumnos reciben los escalones nuevos de forma perezosa (`ensureStepsForPlan` en `loadMemberContext`).
- `saveConquerSettings(db, ctx, patch: Partial<{ startOffsetTernero: number; startOffsetNovillo: number; comboWeeksN: number }>)` —
  valida contra `CONQUER_SETTING_RANGES` (400) y hace upsert por clave.
- Rutas (`/api/admin/conquer`, guard de plugin): `GET /catalog`, `POST /ladders/:ladderId/rungs`, `PUT /rungs/:rungId`,
  `PUT /ladders/:ladderId/order`, `PUT /exercises/:exerciseId`, `PUT /template-days/:id`, `GET /settings`
  (→ `{ settings: ConquerSettings; ranges }`), `PUT /settings` (→ igual).
