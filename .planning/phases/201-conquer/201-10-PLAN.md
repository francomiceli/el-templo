- `combos.ts` (CERO imports): `COMBO_KEYS = ["plancha","front","vertical","dominadas","push","pull"] as const`; `type ComboKey`;
  `COMBOS: Record<ComboKey, { label: string; press: string; push: string; hold: string }>` exacto de §3.4 / `CMB` del oráculo
  (plancha: Press de plancha / Push-up en plancha / Hold de plancha; front: Press a front lever / Pull-up en front lever / Hold de front
  lever; vertical: 90° press / HSPU / Hold de plancha (A17: manda la síntesis); dominadas: Press a front lever / Muscle-up / Hold de
  front lever; push: Press de plancha / HSPU / Hold de plancha; pull: Press a front lever / Muscle-up / Hold de front lever);
  `COMBO_LADDER_CODE = "palanca"`; `DEFAULT_COMBO_RUNG_CODE = "straddle"` (default del oráculo);
  `SATURDAY_WARMUP` = el texto de la entrada en calor de `vSab` del oráculo ("10 a 15 min. Dos vueltas suaves de la cadena, lejos del
  fallo. Lo único de la semana que no va al fallo.").
- `ComboView = { comboKey: ComboKey; label; press; push; hold; rungs: { id; code; name; position }[]; rungId: number; rungName: string; target: number; value: number; maxSeries: number | null; drops: number | null; subir: { ready: boolean; toRungName: string | null } }`
  (`rungId` = `combo_state[comboKey].rungId` o el peldaño `straddle` de Palanca; `value` = lo guardado hoy o `target`; `maxSeries`/`drops` solo en sábado).
- `TodayResponse` gana `opening: ComboView | null` (Toro, día con `opening_combo_key` y `openingTarget` no null) y
  `saturday: { warmup: string; push: ComboView; pull: ComboView } | null` (solo `day=sabado`; ahí `exercises: []` y `finisher: ""`).
  `buildPlanWeek` agrega `{ dayKey: "sabado", label: "Sábado" }` al final si `saturdayPlan(level, cutStage)` no es null.
  `day=sabado` sin sábado habilitado → 400 `CONQUER_DIA_INVALIDO` (igual que cualquier día fuera del plan).
- `PUT /sessions` body gana `opening?: { rungId: integer; series: integer 0-10 }`, `push?: { rungId; series: 0-13 }`, `pull?: { rungId; series: 0-13 }`
  y `exercises` pasa a opcional (obligatorio salvo sábado). Reglas: día normal de Toro con apertura → `opening` obligatorio (400
  `CONQUER_COMBO_FALTA`); `opening`/`push`/`pull` cuando no corresponden → 409 `CONQUER_SIN_COMBOS`; sábado → `push` y `pull`
  obligatorios y sin `exercises`; `rungId` tiene que ser un peldaño activo de Palanca (400 `CONQUER_PELDANO_INVALIDO`). Se guardan
  `combo_rung_id/combo_series/combo_target` (target = `openingTarget` del día) o `push_*`/`pull_*` (target = `saturdayPlan.target`).
  Si el `rungId` difiere del de `combo_state[comboKey]` (o no hay), `combo_state[comboKey] = { rungId, since: hoy }` (cambio a mano =
  mismo efecto, §4.5). El sábado no calcula calibración ni caída (no tiene escalones); sí molestia.
- `comboSubirState(mctx, comboKey, sessions): { ready: boolean; toRungName: string | null }` — semanas calendario desde
  `combo_state[comboKey].since` (o `activation_date`) con `hit = series >= target` (de la fila); `comboSubirReady(semanas, comboWeeksN)`.
- `subirCombo(db, ctx, userId, comboKey)`: no Toro → 409 `CONQUER_SIN_COMBOS`; `!ready` → 409 `CONQUER_NO_TOCA_SUBIR`; sin peldaño más
  difícil → 409 `CONQUER_TOPE_ESCALERA` + `upsertEventAlert(tope_escalera, dedupeKey "tope:combo:<comboKey>:<rungId>")`; si no,
  `combo_state[comboKey] = { rungId: más difícil, since: hoy }`. Devuelve `{ combo: ComboView }`.
  Ruta `POST /api/members/conquer/combos/:comboKey/subir` (comboKey enum de `COMBO_KEYS`).
- `ProgressResponse` gana `comboSubir: { comboKey; label; fromRungName; toRungName: string | null }[]` (combos listos para subir, solo Toro).
- Helper de test: `insertConquerSession` acepta además `combo?: { rungCode: string; series: number; target: number }`,
  `push?`/`pull?` con la misma forma; y `setComboState(app, userId, state)`.
