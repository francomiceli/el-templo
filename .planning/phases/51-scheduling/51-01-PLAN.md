**Schema files (4 new + 2 modified):**

1. **activities.ts** — `activities` table:
   - `id` int PK auto-increment
   - `name` varchar(150) NOT NULL (e.g., "Sesion Grupal", "ROM")
   - `description` text nullable
   - `isActive` boolean default true NOT NULL
   - `createdAt`, `updatedAt` timestamps
   - Relations: many schedules

2. **schedules.ts** — `schedules` table (weekly recurring slots):
   - `id` int PK auto-increment
   - `branchId` int FK branches NOT NULL
   - `activityId` int FK activities NOT NULL
   - `dayOfWeek` tinyint NOT NULL (1=Monday..6=Saturday, ISO weekday)
   - `startTime` varchar(5) NOT NULL (HH:MM format, e.g. "07:00", "17:00") — use varchar instead of MySQL TIME for simpler handling
   - `endTime` varchar(5) NOT NULL
   - `isActive` boolean default true NOT NULL
   - `createdAt`, `updatedAt` timestamps
   - Composite index on (branchId, dayOfWeek, startTime) for weekly grid lookups
   - Relations: one branch, one activity, many bookings

   NOTE: Capacity is NOT on schedules — it comes from branches.maxCapacity (all slots at a branch share the same capacity per CONTEXT decisions).

3. **bookings.ts** — `bookings` table:
   - `id` int PK auto-increment
   - `memberId` int FK users NOT NULL
   - `scheduleId` int FK schedules NOT NULL
   - `bookingDate` date NOT NULL (the specific date of the booking, e.g. "2026-03-14")
   - `status` mysqlEnum booking_status ["confirmed", "cancelled", "waitlist", "no_show"] default "confirmed" NOT NULL
   - `waitlistPosition` int nullable (1-based position when status=waitlist)
   - `bookedAt` timestamp defaultNow NOT NULL
   - `cancelledAt` timestamp nullable
   - Composite index on (scheduleId, bookingDate, status) for capacity counting
   - Composite index on (memberId, bookingDate) for weekly limit counting
   - Unique constraint on (memberId, scheduleId, bookingDate) to prevent double-booking same slot — use Drizzle `uniqueIndex`
   - Relations: one user, one schedule

4. **holidays.ts** — `holidays` table:
   - `id` int PK auto-increment
   - `country` varchar(2) NOT NULL (e.g., "AR", "ES")
   - `date` date NOT NULL
   - `name` varchar(150) NOT NULL (e.g., "Dia del Trabajador")
   - `createdAt` timestamp defaultNow NOT NULL
   - Unique constraint on (country, date)
   - Relations: none (standalone)

5. **branches.ts** — Add 3 columns to existing branches table:
   - `country` varchar(2) default "AR" NOT NULL — for holiday grouping
   - `maxCapacity` int default 22 NOT NULL — branch-wide slot capacity (22 default, 12 for Jujuy and Alem per CONTEXT)
   - `romEnabled` boolean default false NOT NULL — whether Saturday ROM slots appear for this branch

6. **attendance.ts** — Add 1 column:
   - `scheduleId` int FK schedules nullable — links check-ins to booked slots (nullable because existing records predate scheduling)

7. **index.ts** — Add exports for activities, schedules, bookings, holidays

**SchedulingService (service.ts):**
Follow constructor DI pattern (db + log), instantiate SubscriptionService and PaymentService internally (same pattern as AttendanceService).

Methods:

_Activities:_

- `createActivity(name, description?)` — insert and return ActivityRecord
- `listActivities()` — return all active activities
- `updateActivity(id, { name?, description?, isActive? })` — update and return
- `getActivity(id)` — single activity

_Schedules:_

- `createSchedule(branchId, activityId, dayOfWeek, startTime, endTime)` — validate branch exists and is not virtual, validate activity exists, prevent duplicate (same branch+day+time), insert
- `getWeeklyGrid(branchId, weekStartDate)` — return WeeklySlotView[] for all active schedules at branch. For each slot, count confirmed bookings for the specific date of that day in the given week. Check holidays table to mark slots on cancelled days. weekStartDate is a Monday ISO date.
- `getSlotDetail(scheduleId, date)` — return SlotDetailView with all bookings for that slot on that date
- `toggleSchedule(scheduleId, isActive)` — enable/disable a slot
- `seedDefaultSchedules(branchId)` — create the standard 8 weekday slots (7,8,9,10,17,18,19,20) for regular class + 2 Saturday ROM slots (8,9) if romEnabled. Used when admin sets up a branch. Each slot is 1 hour (startTime to startTime+1).

_Bookings:_

- `reserve(memberId, scheduleId, date)` — the core booking method:
  1. Validate schedule exists and is active
  2. Validate date is within current week (Mon-Sat) and not in the past (allow up to 5 min before class)
  3. Validate date matches schedule's dayOfWeek
  4. Check holiday — if date is a holiday for the branch's country, block with message
  5. Check active subscription (reuse SubscriptionService.getMemberSubscription)
  6. Check overdue (reuse PaymentService.getMemberBalance)
  7. Check weekly booking count < classesPerWeek (null classesPerWeek = unlimited). Count confirmed bookings for this member in the same Mon-Sat week.
  8. Check no duplicate booking (same member+schedule+date with status confirmed/waitlist)
  9. Count confirmed bookings for this schedule+date. If < maxCapacity (from branch), insert with status "confirmed". If >= maxCapacity, insert with status "waitlist" and set waitlistPosition = max existing position + 1.
  10. Return BookingRecord

- `cancel(memberId, bookingId)` — cancel a booking:
  1. Validate booking exists and belongs to member
  2. Validate booking is confirmed or waitlist (not already cancelled)
  3. Validate cancellation is at least 20 min before class start (using schedule startTime + booking date)
  4. Update status to "cancelled", set cancelledAt
  5. If cancelled booking was "confirmed", auto-promote first waitlisted member (lowest waitlistPosition) to "confirmed" and reorder remaining waitlist positions
  6. Return updated BookingRecord

- `getMyBookings(memberId, weekStartDate)` — return BookingRecord[] for the member's confirmed + waitlist bookings in the given week, ordered by date and time

- `adminAddBooking(scheduleId, memberId, date)` — admin override: skip overdue/subscription checks, just enforce capacity. If full, add to waitlist.
- `adminRemoveBooking(bookingId)` — admin cancel without time restriction, triggers waitlist promotion

_Holidays:_

- `addHoliday(country, date, name)` — insert holiday, auto-cancel all confirmed bookings at branches in that country for that date (update status to "cancelled", trigger waitlist promotions for each — but actually since the whole day is cancelled, just cancel all confirmed+waitlist bookings)
- `removeHoliday(id)` — delete holiday record (does NOT restore cancelled bookings)
- `listHolidays(country?, year?)` — return holidays filtered by country and/or year
- `getHolidaysForWeek(country, weekStartDate)` — return holidays in date range for grid display

_Private helpers:_

- `getWeekRange(date)` — return { monday, saturday } for the week containing the given date
- `isWithinBookingWindow(scheduleStartTime, bookingDate)` — true if now <= bookingDate+startTime - 5min
- `isWithinCancelWindow(scheduleStartTime, bookingDate)` — true if now <= bookingDate+startTime - 20min
- `promoteWaitlist(scheduleId, date)` — promote first waitlisted to confirmed, reorder positions

Use module-local error classes (BadRequestError, NotFoundError, ConflictError) — same pattern as AttendanceService and SubscriptionService.
