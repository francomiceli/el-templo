```typescript
export type BookingStatus = "confirmed" | "cancelled" | "waitlist" | "no_show";
export type DayOfWeek = 1 | 2 | 3 | 4 | 5 | 6;

export interface ActivityRecord {
  id: number;
  name: string;
  description: string | null;
  isActive: boolean;
}
export interface ScheduleSlot {
  id: number;
  branchId: number;
  branchName: string;
  activityId: number;
  activityName: string;
  dayOfWeek: DayOfWeek;
  startTime: string;
  endTime: string;
  isActive: boolean;
}
export interface WeeklySlotView extends ScheduleSlot {
  bookedCount: number;
  maxCapacity: number;
  isFull: boolean;
  isHoliday: boolean;
}
export interface BookingRecord {
  id: number;
  memberId: number;
  memberName: string;
  scheduleId: number;
  activityName: string;
  dayOfWeek: DayOfWeek;
  startTime: string;
  bookingDate: string;
  status: BookingStatus;
  waitlistPosition: number | null;
  bookedAt: string;
  cancelledAt: string | null;
}
export interface HolidayRecord {
  id: number;
  country: string;
  date: string;
  name: string;
}
export interface SlotDetailView {
  schedule: ScheduleSlot;
  date: string;
  bookings: BookingRecord[];
  maxCapacity: number;
}
```

Admin API endpoints (Plan 01):

- POST /api/admin/scheduling/activities — create activity
- GET /api/admin/scheduling/activities — list activities
- PUT /api/admin/scheduling/activities/:activityId — update activity
- POST /api/admin/scheduling/schedules — create schedule
- GET /api/admin/scheduling/schedules/weekly?branchId=X&weekStart=YYYY-MM-DD — weekly grid
- GET /api/admin/scheduling/schedules/:scheduleId/detail?date=YYYY-MM-DD — slot detail
- PUT /api/admin/scheduling/schedules/:scheduleId/toggle — toggle active
- POST /api/admin/scheduling/schedules/seed — seed defaults for branch
- POST /api/admin/scheduling/bookings — admin add booking { scheduleId, memberId, date }
- DELETE /api/admin/scheduling/bookings/:bookingId — admin remove booking
- POST /api/admin/scheduling/holidays — add holiday { country, date, name }
- DELETE /api/admin/scheduling/holidays/:holidayId — remove holiday
- GET /api/admin/scheduling/holidays?country=XX&year=YYYY — list holidays

**Types (scheduling.ts):**
Mirror the API types for frontend use:
- `BookingStatus`, `DayOfWeek` types
- `ActivityRecord`, `WeeklySlotView`, `BookingRecord`, `HolidayRecord`, `SlotDetailView` interfaces
- `DAY_LABELS` map: { 1: "Lunes", 2: "Martes", 3: "Miercoles", 4: "Jueves", 5: "Viernes", 6: "Sabado" }
- `BOOKING_STATUS_LABELS` and `BOOKING_STATUS_COLORS` maps for display (confirmed=positive/green, waitlist=warning/amber, cancelled=grey, no_show=negative/red)

**API composable (useSchedulingApi.ts):**
Follow the pattern from `useAttendanceApi.ts`. Return object with methods:

- `createActivity(data)`, `listActivities()`, `updateActivity(id, data)`
- `createSchedule(data)`, `getWeeklyGrid(branchId, weekStart)`, `getSlotDetail(scheduleId, date)`, `toggleSchedule(scheduleId, isActive)`, `seedSchedules(branchId)`
- `adminAddBooking(data)`, `adminRemoveBooking(bookingId)`
- `addHoliday(data)`, `removeHoliday(id)`, `listHolidays(params)`

Each method uses the authenticated fetch pattern from the existing composable.

**HorariosPage.vue:**
A full-featured scheduling management page. Major sections:

1. **Header area:**
   - Page title "Horarios"
   - Branch selector (QSelect, defaults to coach's branch, same pattern as AsistenciaHoyPage)
   - Week navigation: left/right arrows + "Esta semana" button, showing date range label (e.g., "10 Mar - 15 Mar 2026")
   - Action buttons row: "Gestionar actividades" (opens dialog), "Feriados" (opens dialog), "Crear horarios por defecto" (seeds default slots if branch has none)

2. **Weekly calendar grid (the main view):**
   Build as a custom HTML/CSS grid (NOT QTable — tables don't render well for calendar grids).
   - Columns: Mon through Sat (show date below day name, e.g., "Lun 10")
   - Rows: each time slot that exists for the branch (7:00, 8:00, 9:00, 10:00, 17:00, 18:00, 19:00, 20:00 for weekdays; 8:00, 9:00 for Saturday ROM)
   - Each cell shows:
     - Activity name (small, above)
     - Occupancy: "12/22" in larger font
     - Color coding: green (<70% full), amber (70-99%), red (100%), grey (holiday)
     - Holiday cells show "FERIADO" text, greyed out, not clickable
   - Click on a cell opens the slot detail dialog

3. **Slot detail dialog (QDialog):**
   - Header: activity name + day + date + time (e.g., "Sesion Grupal - Martes 11 Mar - 8:00")
   - Occupancy: "12/22 reservas"
   - Member list (QList): each item shows member name + status badge (confirmed/waitlist) + remove button (trash icon)
   - "Agregar alumno" button opens a member search QSelect (same pattern as manual check-in in AsistenciaHoyPage — search by name/DNI)
   - Adding a member calls adminAddBooking, removing calls adminRemoveBooking
   - Refresh the grid after any change

4. **Activities management dialog (QDialog):**
   - Simple list of activities with name, description, active status toggle
   - "Nueva actividad" form with name + description fields
   - Edit inline or via sub-dialog
   - This is a simple settings-style dialog, not a full page

5. **Holidays management dialog (QDialog):**
   - Country selector at top (default to branch's country)
   - List of holidays for selected country and current year
   - "Nuevo feriado" form: date picker + name field
   - Delete button per holiday with confirmation
   - Warning text: "Al agregar un feriado, las reservas existentes para ese dia se cancelan automaticamente"

Load the weekly grid data on mount and when branch/week changes. Use `watchEffect` or explicit watchers.

For the "seed default schedules" button: call seedSchedules(branchId), then reload the grid. Show a confirmation dialog first ("Esto creara los horarios predeterminados para esta sede. Continuar?").

Styling: Follow existing admin page patterns. Use Quasar utility classes. The grid should be responsive — on smaller screens, horizontally scroll if needed.
