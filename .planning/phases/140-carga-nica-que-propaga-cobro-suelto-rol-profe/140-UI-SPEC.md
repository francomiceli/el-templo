## Spacing Scale

Quasar spacing utilities map to a 4px base (`xs=4, sm=8, md=16, lg=24, xl=48`). The screen uses these utility classes only — no custom px values.

| Token | Value | Quasar class              | Usage                                                            |
| ----- | ----- | ------------------------- | ---------------------------------------------------------------- |
| xs    | 4px   | `q-pa-xs` / `q-mr-xs`     | Icon-to-label gaps inside buttons                                |
| sm    | 8px   | `q-pa-sm` / `q-gutter-sm` | Compact spacing between stacked form fields                      |
| md    | 16px  | `q-pa-md` / `q-gutter-md` | Default page padding, gap between the big payment-method buttons |
| lg    | 24px  | `q-pa-lg` / `q-mt-lg`     | Section breaks (form block ↔ "Mis cargas" list)                  |
| xl    | 48px  | `q-mt-xl`                 | Bottom safe-area padding above the sticky Confirmar bar          |

**Exceptions (PoS touch targets):**

- Payment-method buttons (`Efectivo / Transferencia / Tarjeta`): **minimum 56px tall** (`size="lg"` + `class="full-width"`), exceeding the 44px WCAG/Apple touch-target minimum. `[ASSUMPTION]` — D-01 says "botones grandes"; 56px is the standard PoS comfortable tap height.
- Primary **Confirmar** button: **min 56px tall, full-width**, sticky to the bottom of the viewport so it is reachable one-handed on a phone.

| Role            | Value                         | Quasar token    | Usage                                                                                      |

**Accent (terracotta `$primary`) reserved for:** the Confirmar CTA, the currently-selected payment-method button, the active mode toggle (Renovar / Cobro suelto), and tappable member names. NOT applied to every button.

**Payment-method button colors `[ASSUMPTION]`:** unselected = `outline` (terracotta border, cream fill); selected = solid `$primary` fill. This avoids the blue `transfer` / purple `card` chips used in `CajaPage` (those are list-badge semantics, not PoS selection state) and keeps the warm-only constraint clean.

**Pending framing (no alarm):** the pending state uses **dark gold `$warning`** with copy "Queda pendiente de validación", never red. Red is reserved strictly for genuine errors. This satisfies the CONTEXT requirement: "make clear it stays pending without alarming."

## Interaction Flows

### Flow A — Renovar plan (D-02)

1. Coach opens `/cargar` → **Renovar plan** mode is selected by default.
2. Taps **Socio** field → types name or DNI → `q-select` debounced `@filter` calls `searchMembers`. Options render name + status badge.
3. Selects a socio → UI calls the autocomplete endpoint → **Plan vigente** (read-only) and **Monto** (editable, pre-filled) populate. Confirmar bar updates its amount label.
4. Coach optionally edits **Monto** (discount/partial — D-02 says editable).
5. Taps one **medio de pago** big button → it becomes solid terracotta (selected). Caja resolves server-side, invisible.
6. Taps **Confirmar** → button shows `:loading`, disables → on success: success notify, form resets, the new ticket prepends to "Mis cargas" with a **Pendiente** badge.

**Confirmar enabled only when:** socio selected AND monto > 0 AND payment method selected.

### Flow B — Cobro suelto (D-03)

1. Coach switches to **Cobro suelto** mode (btn-toggle). The plan-vigente field disappears; **Concepto** textarea appears.
2. Selects socio (same typeahead). **No plan is touched, no autocomplete fires** beyond resolving the member.
3. Enters **Monto** (free) + **Concepto** (free text, required).
4. Selects medio de pago → **Confirmar**.

**Confirmar enabled only when:** socio selected AND monto > 0 AND concepto non-empty AND payment method selected.

### Mode switch behavior `[ASSUMPTION]`

Switching modes **preserves the selected socio and payment method** but clears amount/concept/plan, so an accidental tap is cheap to recover from. Planner may simplify to a full reset if preferred.

## States

| State                                          | Trigger                                                                    | UI                                                                                                                                                                                                                                                                                                             |
| ---------------------------------------------- | -------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Initial / empty form**                       | Page load                                                                  | Renovar mode, empty fields, Confirmar disabled. "Mis cargas" shows today's tickets or empty state                                                                                                                                                                                                              |
| **Typeahead searching**                        | Typing in socio field                                                      | `q-select :loading` spinner; `#no-option` slot shows "Escribe para buscar" / "Sin resultados" (copy from `SlotAttendancePanel`)                                                                                                                                                                                |
| **Autocomplete loading** (Mode A)              | Socio selected                                                             | Plan + Monto fields show `q-skeleton type="text"` until the plan endpoint returns (skeleton pattern from `CajaPage.vue:35-37`)                                                                                                                                                                                 |
| **Autocomplete: no active plan**               | Member has no current subscription                                         | Inline `text-caption text-warning`: "Este socio no tiene un plan vigente para renovar. Usá Cobro suelto." Confirmar stays disabled in Mode A                                                                                                                                                                   |
| **Submitting**                                 | Confirmar tapped                                                           | Confirmar shows `:loading="true"` AND `:disable="true"`. **Disabled for the entire request** — primary double-submit guard                                                                                                                                                                                     |
| **Success**                                    | 2xx response                                                               | `$q.notify({type:'positive', message:'Pago cargado — pendiente de validación'})`. Form resets (socio cleared). New ticket prepends to "Mis cargas" with Pendiente badge                                                                                                                                        |
| **Duplicate submit (idempotent no-op)** (D-09) | Same idempotency key resent (retry / double-tap that slipped past disable) | Server returns the **existing** ticket, not an error. UI treats it as success but does **NOT** create a second list row — de-dupe the prepend by ticket id. Same positive notify. **No error shown** — a retry is safe by design                                                                               |
| **Validation error** (client)                  | Confirmar pressed with missing field                                       | Button stays disabled; offending field shows Quasar `:error` / `error-message`. No network call                                                                                                                                                                                                                |
| **Network / server error**                     | non-2xx                                                                    | `$q.notify({type:'negative', message:'No se pudo cargar el pago. Reintentá.'})`. **Confirmar re-enables** so the coach can retry — and the retry **reuses the same idempotency key** (generated once per confirmation attempt), so a retry after a timeout that actually succeeded server-side is a safe no-op |
| **Mis cargas empty**                           | No loads today                                                             | Empty-state: icon + "Todavía no cargaste pagos hoy." (see Copywriting)                                                                                                                                                                                                                                         |
| **Mis cargas loading**                         | List fetch in flight                                                       | `q-skeleton` rows (3)                                                                                                                                                                                                                                                                                          |

### Idempotency key lifecycle (D-09) — UI contract

- Generate **one** client-side idempotency key (`crypto.randomUUID()`) when a confirmation **attempt begins** (first tap of Confirmar for the current form state).
- Send it on every retry of _that same_ confirmation. Only generate a **new** key after a successful, acknowledged load (i.e., when the form resets for the next deliberate charge).
- The disabled-button guard prevents the common double-tap; the idempotency key is the robust backstop for slow-connection / network-retry cases. Both layers are required by the contract.

## Accessibility

- **Touch targets:** all interactive elements ≥ 44px; PoS payment buttons and Confirmar ≥ 56px (declared in Spacing exceptions).
- **Single-column, no horizontal scroll** at 320px width (smallest common phone).
- **Numeric input:** `inputmode="numeric"` on Monto so phones surface the number pad.
- **Contrast:** all palette tokens are WCAG-AA verified on cream `#f2ede5` (documented in `quasar.variables.scss`: primary 4.75:1, warning 4.79:1, positive 4.88:1, negative 4.51:1).
- **Color is never the sole signal:** the Pendiente badge carries the text "Pendiente", not just gold; payment selection shows solid-fill + label, not color alone.
- **Sticky Confirmar** stays clear of the iOS/Android bottom bar via `q-pb-xl` safe-area padding on the scroll container.
- **Loading feedback:** every async action (typeahead, autocomplete, submit, list) has a visible spinner or skeleton — no silent waits.
- **Focus order:** socio → (plan/monto/concepto) → payment buttons → Confirmar, top to bottom matching visual order.
