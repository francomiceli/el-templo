<objective>
Expose the coach PoS backend as a dedicated thin plugin (`coach-load-routes.ts`) mounted at `/api/admin/finance/coach-load`, gated by `FINANCE_LOAD_ROLES`. Four endpoints: renovar-plan load (reuses renewSubscription), cobro-suelto load (advance_payment, empty links), autocompletar (member current plan + amount), and mis-cargas (own loads only). Implements idempotency dedup at the endpoint layer (catch ER_DUP_ENTRY → return existing). Ships the integration test file proving auth boundaries, idempotency, renew, autocompletar, and cobro-suelto.

Purpose: A SEPARATE plugin is required because `finance/routes.ts` has a module-level `onRequest` guard using `FINANCE_READ_ROLES` (coach excluded) — mounting coach endpoints there would be blocked before the per-handler check runs (Open Question Q1). The new plugin carries its own auth + FINANCE_LOAD_ROLES + country-scope hook.
Output: coach-load-routes.ts plugin + registration, mis-cargas recordedBy filter, endpoint idempotency catch, coach-load.test.ts.
</objective>
