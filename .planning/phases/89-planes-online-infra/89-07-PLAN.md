**Analysis methodology:**

1. Query approved general session blocks from the database:
   - Timeframe: sessions created since 2026-02-16 (per D-11)
   - Filter: `status = 'approved'` AND `goalPlanType IS NULL` (general sessions only, not goal-plan sessions)
   - Include: session blocks with prescriptions, joined to exercises for difficulty/category metadata
   - Expected dataset: ~585 blocks across ~6.5 weeks x 6 days x 3 level groups x 5 blocks

   Write a temporary analysis script (can be inline in the task, or a standalone `.ts` file that connects to DB):

   ```typescript
   // Connect to local DB using existing drizzle config
   // Query: sessions JOIN session_blocks JOIN session_prescriptions JOIN exercises
   // WHERE sessions.created_at >= '2026-02-16' AND sessions.status = 'approved'
   // AND sessions.goal_plan_type IS NULL
   ```

2. For each route/level combination, analyze:

   **Difficulty distribution:**
   - Count exercises by difficulty level (1-5 or whatever the scale is)
   - Compute mean, median, std deviation per route/level
   - Compare against what the pipeline currently generates (run pipeline for same route/level, compare distributions)

   **Prescription patterns (reps/sets):**
   - For each exercise format (e.g., reps_sets, time_hold, AMRAP), compute:
     - Typical set count (mean, range)
     - Typical rep range (mean, range)
     - Typical rest time patterns
   - Identify where pipeline prescriptions deviate

   **Format preferences:**
   - Which exercise formats are most common per route/level in approved data
   - Does the pipeline over/under-use certain formats

   **Exercise variety:**
   - How many unique exercises per route/level in approved data
   - Does the pipeline tend to repeat same exercises too often

3. Cross-reference with known issues from REP_COUNT_DIAGNOSIS.md:
   - ISO phantom weight issue: does the data confirm this?
   - Multi-round format reps: what's the approved pattern?
   - INITIUM reps too low: what's the approved range?

4. Generate the calibration report documenting:
   - Statistical findings per route/level
   - Specific deviations identified (with numbers)
   - Recommended fixes (which pipeline stage, what change)
   - Priority ranking of fixes (high impact first)

Write the report to: `el-templo-api/src/modules/sessions/pipeline/calibration-report.md`

This is an ANALYSIS task — the executor should spend most time querying and analyzing data, not writing code. The report informs Task 2.
