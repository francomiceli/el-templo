**1. Update subscription constraint (per D-35):**

Find the existing active subscription uniqueness check in `assignPlan()`. Currently it checks: "does this member already have an active subscription?" and rejects if yes.

Change to: "does this member already have an active subscription IN THE SAME CATEGORY GROUP?" where:

- Presencial group: `planCategory === 'presencial'`
- Online group: `planCategory !== 'presencial'` (online_regular, online_goal, online_coach)

A member CAN have one presencial AND one online subscription simultaneously.
A member CANNOT have two presencial or two online subscriptions simultaneously.

Implementation: Before the existing uniqueness query, determine if the new plan is presencial or online using `isOnlinePlan(plan.planCategory)`. Then query for active subscriptions of the SAME category group:

```typescript
const existingInSameGroup = await this.db
  .select()
  .from(schema.subscriptions)
  .innerJoin(
    schema.subscriptionPlans,
    eq(schema.subscriptions.planId, schema.subscriptionPlans.id),
  )
  .where(
    and(
      eq(schema.subscriptions.userId, userId),
      eq(schema.subscriptions.status, "active"),
      isOnlinePlan(plan.planCategory)
        ? ne(schema.subscriptionPlans.planCategory, "presencial")
        : eq(schema.subscriptionPlans.planCategory, "presencial"),
    ),
  );
```

If `existingInSameGroup.length > 0`, throw the existing error about active subscription.

The error message should be updated:

- For presencial: "El miembro ya tiene una suscripcion presencial activa"
- For online: "El miembro ya tiene una suscripcion online activa"

NOTE on race conditions: This application-level check is sufficient for the current use case (admin-only operation, single admin at a time per member). A DB-level unique constraint is not practical here because the constraint depends on a JOIN (subscription -> plan -> planCategory). If concurrency becomes a concern in the future, consider SELECT FOR UPDATE on the subscriptions query.

// Auto-create program enrollment if plan has linked program (D-34/D-39)
if (plan.linkedProgramId) {
  // Cancel any existing active enrollment for this user in this program
  await this.db
    .update(schema.programEnrollments)
    .set({ status: "cancelled", cancelledAt: new Date() })
    .where(
      and(
        eq(schema.programEnrollments.userId, userId),
        eq(schema.programEnrollments.programId, plan.linkedProgramId),
