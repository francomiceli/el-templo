## Interaction Contracts

### 1. PlanesPage Tab Restructure (Admin)

**Before:** 3 tabs -- "Planes de Suscripcion" | "Planes Personalizados" | "Promos"
**After:** 2 tabs -- "Planes" | "Promos"

The "Planes" tab contains two visual sections, each with its own section header and table:

```
[Planes] [Promos]

Presenciales                          [+ Nuevo Plan]
+--------------------------------------------------+
| Nombre | Tier | Precio | Duracion | ... | Accion |
+--------------------------------------------------+

Online                                [+ Nuevo Plan Online]
+-----------------------------------------------------------+
| Nombre | Categoria | Precio | $/Semana | Duracion | Accion |
+-----------------------------------------------------------+
```

- Section headers use `text-h6` (Montserrat 600, 18px) with `q-mb-md` spacing below
- Each section has its own "Nuevo Plan" / "Nuevo Plan Online" button aligned right
- Presenciales table columns: Nombre, Tier (badge), Precio, Duracion, Clases/Sem, Estado, Acciones -- unchanged from current
- Online table columns: Nombre, Categoria (badge per category colors above), Precio Mensual, Precio Semanal (computed), Programa Vinculado, Duracion, Estado, Acciones
- Weekly price column: `${ Math.round(priceRegular / 4.33).toLocaleString() }/sem` in grey-7 caption text below monthly price, or as a separate column
- `q-mb-xl` (32px) gap between Presenciales and Online sections

### 2. PlanFormDialog Category Selector (Admin)

**Before:** Two toggles (`isPersonalizada`, `isOnline`) in Options section
**After:** Single `planCategory` QSelect at top of form, immediately after Name/Description

```
General
  [Nombre *        ]
  [Descripcion     ]
  [Categoria *     ] <-- QSelect: Presencial / Online Regular / Online Por Objetivos / Online Personalizado

--- Conditional sections based on category ---

Precios
  [Regular *] [Zero *] [Tarjeta]
  Precio semanal: $X/sem  <-- computed display, read-only, shown only for online categories

Duracion y Clases
  [Duracion *     ]  [Clases por semana]  <-- classesPerWeek hidden when online
  [Tier *] [Modo de Reserva *]           <-- hidden when online (defaults: 'other', 'flexible')

Programa Vinculado                       <-- shown only when online_*
  [Programa *     ] <-- QSelect of active programs from API

Opciones
  [ ] Multi-sucursal
  [ ] Plan de prueba
  [ ] Plan grupal
  [Max miembros grupo] <-- only when isGroup
```

- `planCategory` QSelect options: `[{ label: 'Presencial', value: 'presencial' }, { label: 'Online Regular', value: 'online_regular' }, { label: 'Online Por Objetivos', value: 'online_goal' }, { label: 'Online Personalizado', value: 'online_coach' }]`
- `linkedProgramId` QSelect: populated from `GET /admin/programs` endpoint, shows program name + duration
- When switching category to `presencial`, clear `linkedProgramId`
- When switching to any `online_*`, auto-hide `classesPerWeek`, `planTier`, `bookingMode`
- Weekly price display: `text-caption text-grey-7` below the pricing row. Format: `Precio semanal: $XX.XXX/sem`

### 3. AssignPlanDialog Online Skip (Admin)

When selected plan has `planCategory !== 'presencial'`:

- Skip schedule step entirely (stepper goes 1 -> confirmStep directly)
- Uses existing `confirmStep` computed pattern from Phase 60
- No new UI elements -- same stepper, one fewer step

### 4. ProgramasPage (Admin, New)

Layout matches existing PlanesPage pattern:

```
Programas                              [+ Nuevo Programa]
+-------------------------------------------------------------------+
| Nombre | Tipo | Duracion | Sesiones/Sem | Estado | Acciones       |
+-------------------------------------------------------------------+
```

- Page heading: `text-h5` "Programas"
- "Tipo" column: shows goalPlanType as badge when present, or "Contenido" in grey badge when null
- goalPlanType badge colors: `{ front_lever: 'deep-purple', tren_inferior: 'amber-8', tren_superior: 'blue', empuje: 'teal', traccion: 'orange', planche: 'pink' }`
- Same QTable config as PlanesPage: `flat bordered`, pagination 50 rows, same action button pattern (edit + deactivate)
- Opens existing `ProgramWizardDialog` for create/edit

### 5. Sidebar "Programas" Entry (Admin)

Insert after "Planes" item in the "Gestion" section:

```html
<q-item v-if="isAdminRole" clickable v-ripple to="/programas">
  <q-item-section avatar>
    <q-icon name="school" />
  </q-item-section>
  <q-item-section>Programas</q-item-section>
</q-item>
```

- Same visibility guard as "Planes": `v-if="isAdminRole"` (admin + owner)
- Icon: `school` (Material Icons) -- distinguishes from Planes (`card_membership`)

### 6. Member App Plan Section Rename

- Section title: "Planes Personalizados" -> "Planes Por Objetivos"
- Badge label: "PERSONALIZADO" -> "POR OBJETIVOS" (keep `amber-8` color)
- WhatsApp CTA message template update:
  - Before: `Hola, me interesa el plan personalizado "${exp.name}"`
  - After: `Hola! Me interesa el plan ${plan.name} ($${weeklyPrice}/semana). Quiero mas info.`
- Weekly price computed as: `Math.round(plan.price / 4.33)` for programs, `Math.round(plan.priceRegular / 4.33)` for regular plans
- Regular plan WhatsApp CTA also gets weekly price: `Hola! Me interesa el plan ${plan.name} ($${weeklyPrice}/semana). Quiero mas info.`

## State & Data Flow Contracts

### Admin PlanesPage Data

- `plans` ref splits into two computed lists:
  - `presencialPlans`: `plans.filter(p => p.planCategory === 'presencial')`
  - `onlinePlans`: `plans.filter(p => p.planCategory !== 'presencial')`
- Both filtered from the same `GET /admin/subscriptions/plans` API call (existing endpoint, now returns `planCategory` instead of `isPersonalizada`/`isOnline`)
- Programs loaded via existing `useProgramsApi.getPrograms()` -- moved to ProgramasPage, removed from PlanesPage

### PlanFormDialog State

- `form.planCategory` replaces `form.isPersonalizada` + `form.isOnline`
- `form.linkedProgramId` new nullable number field
- `form.personalizadaType` removed (goalPlanType set on program, not plan per D-07)
- `form.planTier` defaults to `'other'` when online, hidden from form
- `form.bookingMode` defaults to `'flexible'` when online, hidden from form
- `form.classesPerWeek` cleared and hidden when online
- `weeklyPrice` computed: `computed(() => form.priceRegular ? Math.round(form.priceRegular / 4.33) : null)`

### AssignPlanDialog State

- `confirmStep` computed already exists (Phase 60 pattern)
- Update: when `selectedPlan.planCategory !== 'presencial'`, skip step 2 (schedule picker)
- On confirm for online plan with `linkedProgramId`: backend auto-creates `program_enrollment` (D-39) -- no frontend enrollment UI
