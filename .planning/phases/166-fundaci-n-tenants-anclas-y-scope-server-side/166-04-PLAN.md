<interfaces>
Contrato que este plan publica (lo consumen el plan 166-05 y todo el milestone v6.0):

De `el-templo-api/src/modules/shared/country-scope.ts`:

- `interface CountryScope` gana `tenantId: number | null`, con docblock del mismo estilo que el de
  `country`.
- `export type Scope = CountryScope;` — alias de tipo para la migracion gradual de nombres (CD-03).
- `export async function attachScope(request, db): Promise<void>` — **misma firma de 2 parametros
  que hoy**. NO se agrega un parametro `reply` y NO se toca ninguno de los 19 call sites (CD-03:
  el rename migra modulo a modulo en las fases 172-175).
- `export const attachCountryScope = attachScope;` con JSDoc `@deprecated` apuntando a `attachScope`.
- `export const TENANT_SUSPENDED = "TENANT_SUSPENDED";` — codigo estable del 403 (CD-02), mismo
  patron que `BRANCH_OUT_OF_SCOPE` en `branch-access.ts`.

**Como llega `code` al body sin tocar call sites (hallazgo verificado en el codigo instalado):**
`node_modules/fastify/lib/error-handler.js` lineas 111-113 serializa el error por default como
`{ statusCode, code: error.code, error, message }`. Es decir: si el hook LANZA un `AppError`
(`src/modules/shared/errors.ts`, que acepta `code` como tercer argumento) el body del 403 sale con
`code` incluido, sin pasar `reply` al hook. El caso que el PATTERNS marcaba como perdedor
(`handleServiceError` descarta `code`) aplica a los catch DENTRO de rutas, no al camino de error
por default de un hook `onRequest`, que es el que corre aca. El plan 166-05 lo verifica extremo a
extremo sobre rutas reales.

Forma exacta del 403: `statusCode: 403`, `code: "TENANT_SUSPENDED"`, `error: "Forbidden"`,
`message: "Acceso suspendido para este gimnasio"`. Un unico codigo para `suspended` y `archived`
(el cliente HTTP ve lo mismo; el status real viaja en el log estructurado, no en el body).

## Trust Boundaries

| Boundary                                            | Description                                                                                             |
| --------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| cliente (query/body/headers/JWT) -> `attachScope`   | Entrada no confiable que NUNCA debe poder influir en `scope.tenantId`                                   |
| `tenants.status` -> superficie autenticada completa | La suspension es la palanca comercial: si una superficie no la respeta, un tenant impago sigue operando |
| DB (fila de `users`) -> scope del request           | Unica fuente de verdad del tenant; su indisponibilidad no puede degradar en acceso amplio               |
