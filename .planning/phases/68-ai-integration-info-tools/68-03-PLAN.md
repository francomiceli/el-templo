**Fix 4 — Anthropic mapMessages (anthropic.ts):**

In `mapMessages()`, update the `case "assistant"` block (lines 121-128). When `msg.toolCalls` is present and non-empty, build proper Anthropic content blocks:

```typescript
case "assistant": {
  const contentBlocks: (Anthropic.TextBlock | Anthropic.ToolUseBlock)[] = [];

  if (msg.content) {
    contentBlocks.push({ type: "text", text: msg.content });
  }

  if (msg.toolCalls && msg.toolCalls.length > 0) {
    for (const tc of msg.toolCalls) {
      contentBlocks.push({
        type: "tool_use",
        id: tc.id,
        name: tc.name,
        input: tc.arguments,
      });
    }
  }

  if (contentBlocks.length > 0) {
    result.push({ role: "assistant", content: contentBlocks });
  } else {
    result.push({ role: "assistant", content: msg.content });
  }
  break;
}
```

Import `ToolUseBlockParam` or `ContentBlockParam` from the Anthropic SDK types if needed for type safety. Check the exact Anthropic SDK types available — use `ContentBlock` types from `@anthropic-ai/sdk/resources/messages` or cast appropriately.

Also update the `case "tool"` block: when consecutive tool result messages appear, they should be merged into a single user message with multiple `tool_result` blocks (Anthropic requires alternating user/assistant, so consecutive tool results cannot each be separate user messages). Look at how tool results are appended in the handler — if there are multiple tool calls in one iteration, there will be multiple consecutive tool messages. Merge them:

After the main loop in mapMessages(), do a post-processing pass: merge consecutive `role: "user"` messages that contain `tool_result` blocks into a single user message with an array of all their content blocks.
