## Las 4 salidas de rojo provocado + la prueba de la trampa members (Task 2)

Cada mutación se aplicó sobre el archivo del gate ya commiteado (Task 1) o sobre un
archivo de batería, se corrió el gate, se transcribió la salida, y se revirtió con
`git checkout --` antes de la siguiente (verificado `git status --porcelain` limpio
entre cada una).

### 1. Faltantes — rename de un `describe` real

Mutación: en `iso-03-auth.test.ts`, `describe("perfil propio — GET /api/auth/me", ...)`
→ `describe("perfil propio — GET /api/auth/me-XXTYPO", ...)`.

Salida (recorte del assertion message del it de `faltantes`):

```
Rutas de analytics/campaigns/notifications/referrals/improvement-proposals/auth del
manifiesto que NO tienen caso en la batería ISO-03: GET /api/auth/me.
```

(El mismo rename también disparó `fantasmas` con `GET /api/auth/me-XXTYPO` y el conteo
de baseline a 50 — un rename real siempre pega a los tres, es la firma esperada de este
modo).

### 2. Fantasmas — `describe` con clave inexistente (aislado, sin tocar rutas reales)

Mutación: agregado en `iso-03-campaigns.test.ts` un bloque nuevo al final:
`describe("FANTASMA TEMPORAL 175.1-06 Task 2 — GET /api/campaigns/inventado", ...)`.

Salida:

```
Casos de la batería cuyo describe nombra una ruta que NO existe entre las rutas de
analytics/campaigns/notifications/referrals/improvement-proposals/auth del manifiesto:
GET /api/campaigns/inventado.
```

`faltantes` se mantuvo en `[]` — mutación aislada al lado correcto del gate.

### 3. Barra final — criterio incorrecto (`startsWith` a secas, sin la rama `===`)

Mutación: en el propio archivo del gate, `esRutaDelModulo` pasó de
`url === prefijo || url.startsWith(prefijo + "/")` a solo `url.startsWith(prefijo + "/")`.

Salida:

```
El manifiesto tiene 47 rutas de analytics/campaigns/notifications/referrals/
improvement-proposals/auth "tenant-scoped" y el baseline dice 51.
```

51 → 47 (pierde exactamente las 4 rutas que son el prefijo pelado, verificado con tsx:
`GET /api/admin/analytics`, `GET /api/admin/improvement-proposals`,
`POST /api/members/improvement-proposals`, `GET /api/members/referrals`). A diferencia
del molde 174.1-09 (donde el criterio incorrecto no perdía nada hoy, 62→62), acá el
criterio corregido es necesario en el presente, no solo defensivo hacia adelante.

### 4a. Excepción tramposa — motivo vacío

Mutación: agregada una tercera entrada a `EXCEPCIONES_NOMBRADAS`:
`"GET /health": ""` (clave real del manifiesto, fuera de los 8 prefijos, para aislar
el modo de falla sin interferir con las otras 3 aserciones del it de excepciones).

Salida:

```
Excepciones sin motivo utilizable: GET /health.
```

Los otros 3 checks del it de excepciones (inexistentes, conPrefijoDelModulo, y las 2
excepciones reales) se mantuvieron en verde — mutación aislada.

### 4b. La trampa específica: prefijo de referrals vs `/api/admin/members`

**Hallazgo antes de mutar:** la cadena literal del enunciado
(`/api/admin/members/referrals`) NO colisiona con la clave real del manifiesto
(`/api/admin/members/:userId/referrals`) — verificado con tsx:
`"/api/admin/members/:userId/referrals".startsWith("/api/admin/members/referrals/")` es
`false` (el segmento después de `/members/` es `:userId` literal, no `referrals`). Para
demostrar la trampa real —la que el prefijo actual (`/api/admin/referrals`) evita— se
mutó `PREFIJO_ADMIN_REFERRALS` al prefijo que sí colisiona: `/api/admin/members`.

Salida (los 3 its que se pusieron rojos a la vez, transcritos):

```
# it "faltantes": aparecen ~20 rutas nuevas de /api/admin/members/* como "faltantes"
#   (el prefijo ensanchado ahora exige casos para TODO el módulo members, que este
#   gate no cubre — incluye .../:userId/referrals entre las nuevas exigencias)

# it "cubre exactamente las 51 rutas del baseline":
El manifiesto tiene 74 rutas de analytics/campaigns/notifications/referrals/
improvement-proposals/auth "tenant-scoped" y el baseline dice 51.
  (51 → 74: +23 rutas de members capturadas de más por el prefijo ensanchado)

# it "todo caso de la batería apunta a una ruta que existe":
Casos de la batería cuyo describe nombra una ruta que NO existe...:
GET /api/admin/referrals/ab-results.
  (la ÚNICA ruta real del prefijo viejo deja de matchear el prefijo nuevo y su
  propio caso pasa a "fantasma" — el prefijo ensanchado se comió el ancla original)

# it "las excepciones nombradas... siguen fuera de los 8 prefijos" — EL CATCH MÁS DIRECTO:
Excepciones que SÍ matchean alguno de los 8 prefijos del módulo
(.../api/admin/members, ...): GET /api/admin/members/:userId/referrals,
POST /api/admin/members/:userId/referrals.
```

Este último it es el catch más preciso de la trampa: detecta la CONTRADICCIÓN directa
(una ruta no puede ser excepción Y estar dentro de un prefijo del propio módulo a la
vez), independiente del ruido de las +23 rutas de members capturadas de más. El gate
tiene entonces DOS líneas de defensa contra esta trampa específica — la explosión del
baseline (51→74, ruidosa pero honesta) y la contradicción de excepciones (precisa,
nombra las 2 rutas exactas) — no solo una.
