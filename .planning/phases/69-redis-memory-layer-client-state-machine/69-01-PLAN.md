<objective>
Redis connection with graceful degradation and session context memory that stores the last 20 messages per conversation in Redis with 6-hour TTL.

Purpose: The bot currently re-reads message history from MySQL on every message (limited to 10). This plan adds Redis-backed session context so the AI sees the last 20 messages within an active session, and the bot degrades gracefully (no memory, still responds) when Redis is unavailable.

Output: Working Redis singleton, session context module, handler wired to use Redis session for AI context, unit tests.
</objective>

**redis.ts** -- Replace the stub with a working ioredis singleton:

- Create Redis instance from `REDIS_URL` env var (default `redis://localhost:6379`).
- Use `lazyConnect: true` so the bot starts even if Redis is down.
- Call `redis.connect()` at module load wrapped in try/catch. On error, log via Pino and capture with Sentry if `@sentry/node` is available (use dynamic import or guard with try). Set a module-level `let available = false` flag.
- Listen to `redis.on('error')` -- log errors via Pino, set `available = false`. Do NOT let errors propagate (ioredis reconnects automatically).
- Listen to `redis.on('connect')` -- set `available = true`, log info.
- Export: `redis` (the ioredis instance), `isRedisAvailable()` function returning the boolean flag.
- Export `disconnectRedis()` async function for graceful shutdown.

**memory/session.ts** -- Replace the stub with session context storage:

- Define `SessionContext` interface:
  ```ts
  interface SessionMessage {
    role: "user" | "assistant";
    content: string;
    timestamp: number; // epoch ms
  }
  interface SessionContext {
    messages: SessionMessage[];
    updatedAt: number;
  }
  ```
- Redis key pattern: `wa:session:{phone}` with 6-hour TTL (21600 seconds).
- `getSession(phone: string): Promise<SessionContext | null>` -- GET from Redis, JSON.parse. If Redis unavailable (check `isRedisAvailable()`) or key missing, return null. Wrap in try/catch -- on error log and return null (silent degradation).
- `updateSession(phone: string, role: 'user' | 'assistant', content: string): Promise<void>` -- GET existing session (or create new), push new message, trim to last 20 messages (per CONTEXT.md decision), SET with 6h TTL. If Redis unavailable, silently return. Wrap in try/catch.
- `deleteSession(phone: string): Promise<void>` -- DEL the key. For session expiry cleanup if needed.
- All functions use the `redis` import from `../redis.js` and check `isRedisAvailable()` before any operation.
- Use module-level Pino logger (not Fastify request logger) per project pattern.

Constants: `SESSION_TTL = 21600` (6 hours), `MAX_SESSION_MESSAGES = 20`.
