    Replace the contents of `el-templo-app/src-capacitor/android/app/proguard-rules.pro` with:
    ```proguard
    # Capacitor WebView bridge -- keep JavaScript interface classes
    -keepclassmembers class * {
        @android.webkit.JavascriptInterface <methods>;
    }

    # Keep source file names and line numbers for Sentry stack traces
    -keepattributes SourceFile,LineNumberTable
    -renamesourcefileattribute SourceFile

    # Note: Capacitor's @capacitor/android ships its own consumer ProGuard rules
    # that keep plugin classes, annotations, and PluginMethod-annotated methods.
    # No need to duplicate those here.
    ```

    **Step 6: Enable ProGuard for production release builds only.**

    Per user decision: "ProGuard only on production flavor -- staging stays unminified for readable stack traces."

    In `el-templo-app/src-capacitor/android/app/build.gradle`, keep `minifyEnabled = false` in the `buildTypes.release` block (do NOT change it to `true`). This ensures staging release builds stay unminified by default.

    Instead, add an `androidComponents` block AFTER the `android { }` block (before `repositories`). This uses AGP 8.x's Component API to enable minification only for the `productionRelease` variant:

    ```groovy
    // Enable ProGuard/R8 only for production release builds.
    // Per user decision: staging stays unminified for readable stack traces.
    androidComponents {
        onVariants(selector().withBuildType("release").withFlavor(new kotlin.Pair("environment", "production"))) { variant ->
            variant.optimization.minification.set(true)
        }
    }
    ```

    Place this block between the closing `}` of the `android { }` block and the `repositories { }` block.

    **Why this approach:** Setting `minifyEnabled = true` in `buildTypes.release` would apply to ALL flavors' release builds, including a hypothetical `stagingRelease`. The `androidComponents` API (available since AGP 7.0, stable in AGP 8.x) allows per-variant overrides without the shared-BuildType-object problem that `applicationVariants.all` has.

    **Fallback if `androidComponents` doesn't work with this Groovy syntax:** If the executor encounters a build error with the `kotlin.Pair` syntax in Groovy, use this alternative that achieves the same result:

    ```groovy
    // Alternative: enable minification only for productionRelease variant
    androidComponents {
        onVariants(selector().withName("productionRelease")) { variant ->
            variant.optimization.minification.set(true)
        }
    }
    ```

    The `withName("productionRelease")` selector matches the exact variant name (flavor + build type), which is equivalent but avoids the `kotlin.Pair` interop.
