# Phase 141 — UI Design Contract

> Visual and interaction contract for reorganizing `/caja` (CajaPage) into a tabbed cash-control hub for `isCajaRole` (gestion/admin/owner). Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Scope note:** This is a Quasar 2 + Vue 3 admin app. shadcn does NOT apply (no React/Vite-shadcn stack). The shadcn initialization gate is not applicable. The design system is the established El Templo warm palette + existing Quasar component set — **no new UI kit** (locked by STACK.md and CONTEXT D-01).

## Spacing Scale

Quasar `q-*` spacing utilities map to a 4px base. Declared values used in this phase:

| Token | Value | Quasar class                              | Usage                                                                    |
| ----- | ----- | ----------------------------------------- | ------------------------------------------------------------------------ |
| xs    | 4px   | `q-pa-xs` / `q-gutter-xs`                 | Icon-to-label gaps, badge inset, moneda badge offset                     |
| sm    | 8px   | `q-pa-sm` / `q-mb-sm` / `q-col-gutter-sm` | Compact card padding, filter-bar gutters, row chip spacing               |
| md    | 16px  | `q-pa-md` / `q-mb-md` / `q-col-gutter-md` | **Default**: page padding, card gutters, tab-panel padding, section gaps |
| lg    | 24px  | `q-mt-lg` / `q-pa-lg`                     | Section breaks (e.g. saldo group separation, egresos block)              |
| xl    | 32px  | `q-mt-xl`                                 | Major vertical breaks between saldo type groups                          |

Exceptions:

- **Vencido counter banner** uses `q-pa-sm` (compact, sticky-feeling) intentionally — it is an alert strip, not a section.
- **Touch target** for the prominent "Validar" button: minimum 36px height (`dense` q-btn default ≈ 36px). The "⋮" overflow menu trigger keeps the standard 40px round hit area (`q-btn flat dense round`, matching the existing actions column).

## Color

The warm palette is the source of truth (`quasar.variables.scss`, Phase 39 — **NO blue anywhere**). 60/30/10 maps to Quasar tokens as follows.

| Role                    | Token / Hex                                                                  | Usage                                                                                                               |
| ----------------------- | ---------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| Dominant (60%)          | Marble Cream `#F2EDE5` (page bg)                                             | Page background, q-table surface, default card body                                                                 |
| Secondary (30%)         | white / `bg-grey-1` cards, `$accent` Deep Charcoal `#3D3732` text            | Cards, q-table header, sidebar/nav, body text                                                                       |
| Accent (10%)            | `$primary` Terracotta `#96593a`                                              | Primary links (clickable member name), active q-tab indicator, "Exportar" outline btn, **"Validar" primary button** |
| Pending / gold          | `$warning` Dark Gold `#7d6520` + `amber` for badges                          | Pendiente state, "Observado" amber badge, pendiente sub-value on saldo cards                                        |
| Vencido (stronger warm) | `$negative` Warm Red `#b34a4a` (text/badge) on `bg-orange-1`-style warm tint | Rows >3 días: "vencido" badge + row tint + counter banner                                                           |
| Destructive             | `$negative` Warm Red `#b34a4a`                                               | Anular action, void confirmation, error notify                                                                      |
| Success                 | `$positive` Warm Green `#3b7249`                                             | Validate-success notify, saldo firme positive emphasis (existing)                                                   |

**Accent (Terracotta) reserved for:** active tab indicator · clickable member name link · the prominent "Validar" primary button · "Exportar Excel/PDF" outline buttons · primary dialog confirm buttons (non-destructive). NOT applied to every interactive element — secondary actions (Observar/Corregir, menu items, filter chips) stay neutral/charcoal.

**Pending = gold, NOT red (LOCKED D-09 framing).** A pending payment is normal/expected, not an alarm — gold/amber. Only **vencido** (>3 días) escalates to the stronger warm-red tone. This two-tier warmth is the core color contract of the bandeja.

**Currency isolation (LOCKED, 137/138):** moneda always shown as a badge **beside** the amount; never a cross-currency total. Subtotals are per-currency only.

## Tab Hub Structure (D-01)

`/caja` becomes a `q-tabs` + `q-tab-panels` hub. **Pendientes is the landing tab** (default active).

```
q-page (q-pa-md, bg cream)
├─ Header row: text-h5 "Caja"  +  [owner-only País q-select, unchanged]
├─ q-tabs (align="left", active-color="primary", indicator-color="primary", dense)
│   ├─ q-tab name="pendientes"  label="Pendientes"  icon="inbox"
│   │     └─ q-badge floating (vencido count, color="negative") when N>0
│   ├─ q-tab name="saldos"      label="Saldos"      icon="account_balance_wallet"
│   ├─ q-tab name="movimientos" label="Movimientos" icon="receipt_long"
│   └─ q-tab name="movEgresos"  label="Mov. y egresos" icon="swap_horiz"
├─ q-separator
└─ q-tab-panels v-model="activeTab" (keep-alive, swipeable=false)
    ├─ panel pendientes  → BandejaPendientesTab
    ├─ panel saldos      → SaldosPorCajaTab
    ├─ panel movimientos → MovimientosTab  (= current CajaPage body)
    └─ panel movEgresos  → MovEgresosTab
```

**Tab persistence (assumption):** active tab synced to a query param `?tab=pendientes|saldos|movimientos|movEgresos` so refresh/back preserves context. Default (no param) = `pendientes`. _Marked assumption — D-01 only locks "Pendientes is landing"._

**Component split (Claude's discretion, D-01/STACK §3):** extract each panel into its own SFC under `el-templo-admin/src/components/caja/` (`BandejaPendientesTab.vue`, `SaldosPorCajaTab.vue`, `MovimientosTab.vue`, `MovEgresosTab.vue`). `CajaPage.vue` becomes the thin hub shell (tabs + country selector + panel routing). This keeps each tab independently lazy-loadable and matches the Pinia-composition + composable-with-`cleanup()` pattern. The owner-only `selectedCountry` lives in the hub and is passed down as a prop / shared composable so all tabs scope to the same country.

## Tab 1 — Bandeja de Pendientes (landing, D-02..D-05, D-08/D-09)

The daily control surface that replaces el cierre de caja diario.

### Layout

```
panel pendientes (q-pa-md)
├─ Vencido counter banner  (q-banner, warm-red tint) — only when vencidoCount > 0
│     "⚠ {N} pendientes superan los 3 días"   [no action button]
├─ Filter row (q-btn-toggle OR q-tabs-style segmented):  Pendientes | Observados | Todos
│     + q-space + [Exportar Excel] [Exportar PDF] outline btns (right-aligned)
└─ Bandeja list  (q-list separator, OR q-table — see "List vs Table" below)
      one row per pending/observed transaction, ordered antigüedad DESC (oldest first)
```

### Row anatomy (D-02)

Each row, left→right:

| Field       | Source                                     | Rendering                                                                       |
| ----------- | ------------------------------------------ | ------------------------------------------------------------------------------- |
| Socio       | `memberName`                               | `text-weight-medium`, clickable → `/alumnos/:id` (Terracotta link)              |
| Monto       | `amount` + `currency`                      | bold + **moneda badge beside** (currency isolation)                             |
| Medio       | `paymentMethod`                            | `q-badge` reusing `methodColor`/`methodLabel` from CajaPage                     |
| Caja        | `cashRegisterName`                         | `text-body2` neutral                                                            |
| Cargado por | `recorderName`                             | `text-caption` Olive Stone (who loaded it — coach/admin)                        |
| Antigüedad  | derived from `createdAt`/`transactionDate` | `text-caption` "hace N días" — gold if 1–3, **warm-red if >3**                  |
| Estado      | `validationStatus`                         | badge: Pendiente=gold/amber, Observado=amber "Observado" badge                  |
| Acciones    | —                                          | **[Validar] prominent primary btn** + "⋮" q-menu (Observar / Corregir / Anular) |

**Antigüedad computation (Claude's discretion, D-08):** compute server-side in the bandeja endpoint as `daysPending = DATEDIFF(NOW(), createdAt)` and return it alongside the row, so the threshold comparison and sort happen in one place. Front renders "hace N días" from the integer. The threshold is read from a **shared constant** `PENDING_THRESHOLD_DAYS = 3` (see Threshold section).

### Vencido alert (D-08/D-09)

- Rows where `daysPending > PENDING_THRESHOLD_DAYS`: row gets a warm tint (`bg-orange-1` equivalent warm tone, not pure red) + a `q-badge color="negative" label="vencido"` appended to the estado cell.
- Because the list is sorted oldest-first, vencidos naturally cluster at the top.
- Counter banner at the top: `⚠ {vencidoCount} pendientes superan los {threshold} días`. The vencido count also drives the **floating badge on the Pendientes tab** so it's visible from other tabs.
- Banner uses warm-red tint background (`$negative` text on a soft warm surface), `q-icon name="warning"`. No action button (it's informational — the rows below are the action).

### Filter (D-04)

Segmented control (recommend `q-btn-toggle` with 3 options, `toggle-color="primary"`, `flat`): **Pendientes** (default) / **Observados** / **Todos**. Observados live in the SAME list with the amber "Observado" badge — not a separate view. Filter maps to the `validationStatus` query param on the bandeja endpoint.

### List vs Table (Claude's discretion)

Recommend **`q-table`** (not raw q-list) for the bandeja: it gives free pagination, the existing `@request` server-side pattern, column alignment, and a `body-cell-acciones` slot identical to CajaPage. Use custom body-cell slots to render the badges, "hace N días", and the Validar+menu action cell. Row tint via `:class` on `q-td`/row (same pattern CajaPage uses for `isVoided` strikethrough). Default sort is fixed to antigüedad (server-enforced); column sorting disabled to preserve the "oldest first" contract.

### Actions (D-03, D-05)

Reuse the Phase 137 endpoints (validate / observe / correct / void). UI contract per action:

| Action       | Trigger                                                           | UI flow                                                                                                                                                                                                                                                                         |
| ------------ | ----------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Validar**  | prominent primary `q-btn` (label "Validar", color primary, dense) | Confirm dialog (`$q.dialog`, lightweight): "¿Validar el pago de {monto} de {socio}?" → on OK call validate → success notify "Pago validado" → refresh bandeja + saldos badge. Single tap is the happy path.                                                                     |
| **Observar** | "⋮" menu item (icon `flag`, amber)                                | Dialog with required textarea "Motivo de observación \*" (isValid: non-empty) → call observe → row stays in bandeja, flips to "Observado" amber badge → notify "Pago observado".                                                                                                |
| **Corregir** | "⋮" menu item (icon `edit`)                                       | Opens **Corrección dialog** (form: amount, paymentMethod, cashRegister, notes — pre-filled with current values). Submitting = void+recreate (137 D-05): voids the original (with reason "corrección") and creates the corrected transaction PENDIENTE. Notify "Pago corregido". |
| **Anular**   | "⋮" menu item (icon `block`, negative)                            | Opens the **membership 1-a-1 popup** (D-05 / 137 D-10) — see below.                                                                                                                                                                                                             |

### Membership-decision popup on Anular (D-05, 137 D-10)

`q-dialog` (width ~480px, matching detail dialog). Anulando un cobro de plan puede afectar la membresía 1-a-1:

```
q-card
├─ title: "Anular pago de {socio}"
├─ message: "Anular el pago de {monto} de {socio}. Esta acción deja rastro y no se puede deshacer."
├─ Membership decision (only when the void touches an active membership link):
│     q-option-group / q-toggle "Mantener la membresía activa"
│        default = ACTIVA (keepMembershipActive: true)  ← LOCKED default
│        helper caption: "Si la desactivás, el socio pierde el beneficio de este pago."
├─ textarea "Motivo de anulación *"  (required, isValid non-empty)
└─ actions: [Cancelar (flat grey)]  [Anular (color negative)]
```

On OK → call void endpoint with `{ reason, keepMembershipActive }`. Success notify "Pago anulado". Refresh bandeja + saldos. If the transaction has no active membership link, hide the toggle (plain void with reason only — same as the current CajaPage `confirmVoid`).

## Tab 2 — Saldos por Caja (D-06, D-07)

### Layout

```
panel saldos (q-pa-md)
├─ (right) [Exportar Excel] [Exportar PDF] outline btns
├─ Group: "Efectivo sucursales"   (text-subtitle1, q-mb-sm)
│    └─ row q-col-gutter-md  → caja cards
│    └─ per-currency subtotal chips (ARS / EUR), NEVER combined
├─ Group: "Efectivo central"
│    └─ cards + per-currency subtotals
└─ Group: "Banco"
     └─ cards + per-currency subtotals
```

Groups separated by `q-mt-xl`. Group order fixed: Efectivo sucursales → Efectivo central → Banco (D-06).

### Caja card anatomy (D-06)

```
q-card flat bordered (col-6 col-sm-4 col-md-3)
└─ q-card-section
     ├─ row: caja name (text-subtitle2)  + moneda badge (q-badge, beside)
     ├─ saldo firme    → text-h5 text-weight-bold  (large, dominant)  [Σ validados]
     └─ pendiente      → text-caption gold "Pendiente: {monto}" (small, below)  [Σ pendientes, separate]
```

**Critical contracts:**

- Saldo firme = Σ VALIDADO only (large). Pendiente shown small below, **never added to firme** (138 derived-balance rule).
- Moneda badge always beside the amount; **per-currency subtotal only** — there is NEVER a card or chip that sums ARS+EUR. If a group has both currencies, render two subtotal chips side by side ("Subtotal ARS: …", "Subtotal EUR: …").
- Pendiente value uses gold (`$warning`); firme uses neutral charcoal (or `$positive` if the existing Total card emphasis is kept).

### Endpoint (D-07, Claude's discretion)

New REST `GET /admin/finance/cash-registers/balances` (`isCajaRole`) that iterates active cajas and returns `getBalance` (firme + pendiente) per caja, grouped/tagged by `type` (efectivo_sucursal / efectivo_central / banco) and `currency`. The front groups by `type`, computes per-currency subtotals client-side (or server returns them). _Endpoint shape is Claude's discretion per CONTEXT — follow finance module conventions._

### Empty state

If a group has no cajas: show a muted `text-caption text-grey-5` "Sin cajas de este tipo." rather than an empty group with a header floating.

## Tab 4 — Movimientos y Egresos (D-/REP-03)

Historial de `cash_transfer` (inter-caja, double-entry) + `expense` (egresos), filterable.

### Layout

```
panel movEgresos (q-pa-md)
├─ Filter bar (q-col-gutter-sm, items-end):
│    [Caja q-select]  [Período q-input type=month OR date range]  [Tipo: Movimientos/Egresos/Todos]
│    + q-space + [Exportar Excel] [Exportar PDF]
└─ q-table (server-side pagination, @request)
     columns: Fecha · Tipo (badge: Movimiento/Egreso) · Origen → Destino (mov) / Concepto (egreso)
              · Monto (+ moneda badge) · Caja · Registrado por · [⋮ Detalles]
```

### Critical: LEFT JOIN users (flag 139)

⚠️ **LOCKED data contract.** Rows for `cash_transfer` / `expense` / `adjustment` have `member_id = NULL`. The list/export MUST use **LEFT JOIN users** (not INNER JOIN) or these NULL-member rows are silently dropped. The "Registrado por" / member-less rows render with `recorderName` (or "—" where no member). This is a known bug flag from 139 the executor must honor.

### Tipo rendering

- **Movimiento (inter-caja):** badge neutral/charcoal "Movimiento", shows Origen → Destino caja. Double-entry: render as a single logical row (one transfer), not two ledger entries.
- **Egreso:** badge `$negative`-toned "Egreso", shows the concepto/category. Amount debits (display with a leading "−" sign, warm-red text, but **no cross-currency totals**).

### Detail dialog

Reuse the same `q-dialog` detail pattern from CajaPage (q-list of label/value rows) adapted for transfer/egreso fields (origen, destino, concepto, motivo, registrado por, fecha).

## Accessibility

- **Color is never the sole signal.** Vencido rows carry a "vencido" text badge + the counter banner text, not just the warm tint. Estados always have a text label badge (Pendiente/Observado), not color alone. (Required because the warm palette's pending-gold vs vencido-red distinction must survive for color-blind users.)
- **Contrast:** all tokens are the AA-verified Phase-39 values (Terracotta 4.75:1, warning gold 4.79:1, negative 4.51:1 on cream). Do not lighten badge text below these.
- **Hit targets:** Validar btn ≥36px; "⋮" trigger keeps the 40px round area. Filter toggle buttons full label, not icon-only.
- **Keyboard:** tabs reachable via `q-tabs` native keyboard nav; dialogs trap focus (Quasar default); required textareas block OK until valid (`isValid`).
- **Member links** keep `cursor-pointer` + accent color + are real navigations (`router.push`), not just styled spans for click — preserve the existing pattern.
- **Tab badge** (vencido count) is decorative-with-text — ensure the bandeja banner is the authoritative count for screen readers.
