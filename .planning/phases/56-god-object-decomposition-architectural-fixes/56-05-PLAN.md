Add the following test cases to the existing analytics test file. Use the existing helper functions (createMember, createPlan, assignSubscription, recordPayment, cleanupAll).

**Retention rate tests (in "GET /api/admin/analytics/members" describe block):**

1. "should compute retentionRate = 50% when 1 of 2 members renews":
   - Create Plan A (30 days)
   - Create Member 1 and Member 2
   - Assign sub to Member 1 starting 35 days ago (ended 5 days ago) — this is an "ending" sub
   - Assign a NEW active sub to Member 1 starting today — this means Member 1 "renewed"
   - Assign sub to Member 2 starting 35 days ago (ended 5 days ago) — ended, no renewal
   - Query /members with dateFrom = 10 days ago, dateTo = today
   - Expect `retentionRate` to be 50 (1 renewed out of 2 ending)

2. "should compute retentionRate = 100% when no subs end in period":
   - Create Plan A (30 days), Member 1
   - Assign sub starting today (ends in 30 days — not in past)
   - Query /members with dateFrom = 10 days ago, dateTo = today
   - Expect `retentionRate` to be 100

**Morosos tests (in "GET /api/admin/analytics (KPIs)" describe block):**

3. "should count morosos when member has expired sub with insufficient payment":
   - Create Plan (30 days, price 15000), Member
   - Assign sub starting 35 days ago (expired 5 days ago, pricePaid = 15000)
   - Record payment of 5000 (insufficient — 10000 still owed)
   - Query /api/admin/analytics
   - Expect `morososCount.value` to be >= 1

4. "should not count fully-paid expired sub as moroso":
   - Create Plan (30 days, price 15000), Member
   - Assign sub starting 35 days ago (expired 5 days ago)
   - Record payment of 15000 (fully paid)
   - Query /api/admin/analytics
   - Expect `morososCount.value` to be 0

**Financial tests (in "GET /api/admin/analytics/financial" describe block):**

5. "should compute totalOutstanding as sum of unpaid balances on expired subs":
   - Create Plan (price 15000, 30 days), Member
   - Assign sub starting 35 days ago (expired)
   - Record payment of 5000
   - Query /financial
   - Expect `totalOutstanding` to be 10000

6. "should compute collectionRate from total owed vs total collected":
   - Create Plan (price 10000, 30 days), 2 Members
   - Assign subs starting 35 days ago (both expired, pricePaid 10000 each)
   - Member 1 pays 10000 (full), Member 2 pays 5000 (partial)
   - Total owed = 20000, total collected = 15000
   - Query /financial
   - Expect `collectionRate` to be 75
