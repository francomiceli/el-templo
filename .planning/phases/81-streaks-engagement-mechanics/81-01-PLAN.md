**4. Create StreakService** at `el-templo-api/src/modules/streaks/service.ts`:

Constructor DI: `constructor(private db: DbInstance, private auraService: AuraService, private log: FastifyBaseLogger)`

Methods:

a) `async getExpectedTrainingDays(userId: number): Promise<number[]>` — Returns ISO day-of-week numbers (1=Mon..6=Sat) when the member is expected to train. Query: join active subscription -> subscription_schedules -> schedules to get `dayOfWeek` values. If no subscription_schedules exist, fall back to subscription plan's `classesPerWeek` (distribute evenly Mon-Sat). If no active subscription at all, return `[1,2,3,4,5,6]` (assume daily except Sunday).

b) `async updateStreak(userId: number): Promise<{ currentStreak: number; longestStreak: number; milestoneReached: number | null }>` — Core logic (per D-01, D-03, D-04, D-05):

1. Get the member's expected training days via `getExpectedTrainingDays(userId)`.
2. Read `currentStreak` and `longestStreak` from `member_profiles` WHERE userId matches.
3. Determine if the member had a missed planned training day since `streakUpdatedAt` (or since "yesterday" if null). Walk backwards from today: for each date between `streakUpdatedAt` and yesterday, check if `dayOfWeek` was an expected training day. If it was, check if `completed_sessions` has a record for that user+date. If a planned day was missed, reset `currentStreak = 0`.
4. Increment `currentStreak` by 1 (today's session just happened).
5. If `currentStreak > longestStreak`, set `longestStreak = currentStreak` (per D-05).
6. Update `member_profiles` with new values + `streakUpdatedAt = NOW()`.
7. Check if `currentStreak` exactly equals a milestone (7, 14, 30, 60, 100). If so, award AURA bonus via `getStreakMilestoneConfig()` and `auraService.award()` with `sourceType: "streak_bonus"`, `referenceType: "streak_milestone"`, `referenceId: currentStreak` (the milestone number). Wrap in try/catch — log on failure but don't fail the update (per graceful degradation pattern from Phase 69/78).
8. Return `{ currentStreak, longestStreak, milestoneReached }`.

IMPORTANT: If the member has no `member_profiles` row (hasn't completed onboarding), skip silently — log a debug message and return `{ currentStreak: 0, longestStreak: 0, milestoneReached: null }`.

c) `async getStreakMilestoneConfig(): Promise<StreakMilestoneConfig>` — Follow exact same pattern as `SettingsService.getSegmentThresholds()`: query system_settings by keys in STREAK_SETTINGS_KEYS, parse with defaults from STREAK_DEFAULTS.
