Implement fixed schedule slot reservations with bulk booking generation, holiday-aware skip, subscription cancellation cleanup, and schedule slot attendance visibility API.

Purpose: Replace the old day-checkbox fixed schedule system with specific schedule slot references. When a fixed-plan subscription is created, the system auto-generates all bookings for the subscription period, skipping holidays. Provide APIs for the admin UI to show attendance per schedule slot and for coaches to manually check in / remove check-ins.

Output: Updated SubscriptionService with schedule slot storage, BookingService with bulk generation, new admin API endpoints for slot attendance and coach check-in/removal.
</objective>

    1. New method `generateFixedBookings(subscriptionId, scheduleIds, startDate, endDate, branchId)`:
       - For each scheduleId, get the schedule's dayOfWeek
       - Generate all dates from startDate to endDate that match each schedule's dayOfWeek
       - For each date, check if it's a holiday (query holidays table for the branch's country). If holiday: skip and increment holidaysSkipped counter.
       - For each non-holiday date, insert a booking (memberId from subscription, scheduleId, bookingDate, status 'reservado')
       - Handle capacity: if a slot is full for a date, put on waitlist (same logic as existing reserve)
       - Return `{ totalGenerated: number, holidaysSkipped: number }`
       - NOTE: This method needs the memberId. Get it from the subscription record, or accept it as a param.

    2. New method `cancelFutureBookings(subscriptionId)`:
       - Get all schedule IDs from subscription_schedules for this subscriptionId
       - Get the memberId from the subscription
       - Cancel all bookings where: memberId matches, scheduleId in scheduleIds, bookingDate > CURDATE(), status IN ('reservado', 'lista_espera')
       - Do NOT cancel qr_escaneado or confirmado bookings (those are past/current-day attendance records)
       - Trigger waitlist promotion for each affected scheduleId+date

    **New endpoint: GET /admin/attendance/slot/:scheduleId/:date**
    Returns the list of members who have a booking for this schedule+date, enriched with attendance status:
    - For each booking: memberId, memberName, bookingStatus, attendanceId (if checked in), checkedInAt (if checked in)
    - Also include "unbooked check-ins" -- members who checked in via QR to this schedule+date but didn't have a booking
    - Response shape:
      ```typescript
      interface SlotAttendanceItem {
        memberId: number;
        memberName: string;
        bookingId: number | null;     // null if no booking (walk-in QR)
        bookingStatus: string | null;
        attendanceId: number | null;   // null if not checked in
        checkedInAt: string | null;
        source: 'qr' | 'manual' | null;
      }
      ```

    **New endpoint: POST /admin/attendance/slot/:scheduleId/:date/check-in**
    Coach manual check-in from the Horarios attendance view. This IS the force check-in (unified mechanism per CONTEXT.md).
    - Body: `{ memberId: number, reason?: string }`
    - This endpoint searches ALL members (not just booked ones) -- the admin UI sends any memberId. The API validates membership and returns subscription status warnings (expired, no classes remaining, overdue) alongside the created attendance record.
    - Creates attendance record with status "confirmado", source "manual", scheduleId, branchId (from schedule)
    - Awards 10 AURA immediately
    - Decrements classesRemaining if tracked
    - If member has a booking for this slot+date, update booking status to "confirmado"
    - Returns the attendance record + subscription status warnings (expired, no classes remaining, etc.)
    - This replaces the old POST /admin/attendance/force endpoint. Remove the old force endpoint OR keep it as an alias.

    **New endpoint: DELETE /admin/attendance/:attendanceId**
    Coach undo: remove a check-in if someone scanned but didn't actually attend.
    - Deletes the attendance record
    - If the attendance was linked to a booking (via scheduleId+date match), revert booking status from "qr_escaneado"/"confirmado" back to "reservado"
    - Restore classesRemaining +1 on the member's subscription (if tracked)
    - Reverse the 10 AURA award (call auraService with negative amount or a "reversal" transaction)

    - `removeCheckIn(attendanceId, adminId)`: delete attendance, restore budget, reverse AURA, revert booking
