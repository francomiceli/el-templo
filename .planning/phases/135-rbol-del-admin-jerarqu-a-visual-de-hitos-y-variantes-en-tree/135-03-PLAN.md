<objective>
Block B backend (D-11). Extend `GET /admin/tree-editor/tree` so each hito node carries its `variants[]` (the exercises whose `milestone_exercise_id` points at it). This is done with a SEPARATE batched query — `loadVariantsByMilestone()` — that selects all variants (`isNotNull(milestoneExerciseId)`) and groups them in JS, added to `buildEditableTree`'s existing `Promise.all`. **`backboneNodeConditions()` is NEVER modified** (B-NOREGRESION): the backbone (member-tree/getNeighbor/rebuild) keeps seeing only hitos. The contract (`editableNodeSchema`) and the DTO (`EditableNode`) gain `variants[]`; the route handler does not change.

Purpose: today variants only exist in the side-panel via on-demand `getVariants(id)`. To draw the collapsible hierarchy without N round-trips, the canvas needs variants embedded per hito in the `/tree` payload.
Output: extended service + schema + a regression-guarded integration test.
</objective>
