Create three reference table schemas:

**routes.ts:**
- `id` INT PK autoincrement
- `code` VARCHAR(20) NOT NULL UNIQUE - stores route codes like 'PL', 'FL', 'MN/RP'
- `displayName` VARCHAR(100) - human-readable name
- `createdAt` TIMESTAMP default now

**intensity-rules.ts:**
- `id` INT PK autoincrement
- `intensity` INT NOT NULL UNIQUE - percentage (55, 60, 65, 70, 75, 80, 85, 90, 95)
- `repsBudget` INT NOT NULL - total reps per block (from "Repeticiones por Bloque" column)
- `difficulty` VARCHAR(20) NOT NULL - '1', '2', '3', or 'Nivel Superior 1' (store as string)
- `exerciseCountMin` INT NOT NULL - lower bound (extract from "4 a 5" -> 4)
- `exerciseCountMax` INT NOT NULL - upper bound (extract from "4 a 5" -> 5)

**contraction-rules.ts:**
- `id` INT PK autoincrement
- `intensity` INT NOT NULL - references intensity value
- `totalExercises` INT NOT NULL - 2, 3, 4, or 5
- `concentrico` INT NOT NULL - CON count
- `excentrico` INT NOT NULL - EXC count
- `isometrico` INT NOT NULL - ISO count
- Composite unique constraint on (intensity, totalExercises)
- Index on (intensity, totalExercises) for lookups

Follow existing patterns from users.ts for imports and table structure.

  <action>
Create two core periodization table schemas:

**spom-rules.ts:**
- `id` INT PK autoincrement
- `week` INT NOT NULL (1-52)
- `routeId` INT NOT NULL FK -> routes.id
- `intensity` INT NOT NULL (55-95)
- `wave` VARCHAR(50) NOT NULL - wave emoji and name (e.g., "Senoidal", "Shockwave")
- `pattern` VARCHAR(150) NOT NULL - active pattern description
- `pattern2` VARCHAR(100) - secondary pattern (nullable)
- `category` VARCHAR(100) NOT NULL - category name
- Composite index on (week, routeId) for primary lookup pattern
- Index on routeId for FK lookups
- Unique constraint on (week, routeId) to enforce SPOM-09 (no duplicates)

**weekly-rotator.ts:**
- `id` INT PK autoincrement
- `week` INT NOT NULL (1-52)
- `day` mysqlEnum('lunes', 'martes', 'miercoles', 'jueves', 'viernes', 'sabado')
- `levelGroup` mysqlEnum('alfa_delta', 'sigma', 'omega')
- `nucleusRouteId` INT NOT NULL FK -> routes.id
- `deuteros1RouteId` INT NOT NULL FK -> routes.id
- `deuteros2RouteId` INT FK -> routes.id (nullable - some days may not have)
- `athlosRouteId` INT NOT NULL FK -> routes.id
- Composite index on (week, day, levelGroup) for primary lookup
- Indexes on each route FK column

Note: Use mysqlEnum for day and levelGroup to enforce valid values.

Create remaining schemas and update index:

**formats.ts:**
- `id` INT PK autoincrement
- `name` VARCHAR(100) NOT NULL UNIQUE - format name from CSV
- `type` VARCHAR(50) - 'Volume-based', 'Intensity-based', 'Time-based' (nullable)
- Index on name for lookups

**format-compatibility.ts:**
- `id` INT PK autoincrement
- `formatId` INT NOT NULL FK -> formats.id
- `block` mysqlEnum('nucleus', 'deuteros', 'plethora') - Deuteros covers both 1 and 2
- `level` mysqlEnum('alfa', 'delta', 'sigma', 'omega') - individual level, not group
- `intensity` INT NOT NULL - 55, 60, 65, 70, 75, 80, 85, 90, 95
- `compatibility` INT NOT NULL - 0 or 1
- Composite index on (formatId, block, level, intensity) for lookups
- Composite unique constraint to prevent duplicates

**exercises.ts:**
- `id` INT PK autoincrement
- `pattern` VARCHAR(100) NOT NULL - PATRON PRINCIPAL
- `category` VARCHAR(100) NOT NULL - CATEGORIA PRINCIPAL
- `categorySecondary` VARCHAR(100) - CATEGORIA SECUNDARIA (nullable)
- `exercise` VARCHAR(150) NOT NULL - Ejercicio name
- `exercise2` VARCHAR(150) - Ejercicio 2 (nullable)
- `position` VARCHAR(100) - Posicion (nullable)
- `effort` VARCHAR(10) NOT NULL - 'CON.', 'EXC.', 'ISO.' (contraction type)
- `level` mysqlEnum('alfa', 'delta', 'sigma', 'omega', 'spartan')
- `codeNumber` INT - Codigo Numerico
- `difficulty` INT NOT NULL DEFAULT 1 - Dificultad Relativa (1-3+)
- `route` VARCHAR(20) NOT NULL - Route code (e.g., 'FL', 'PL')
- `mobilityRelated` VARCHAR(100) - related mobility (nullable)
- Composite index on (route, effort, level, difficulty) for exercise queries (SPOM-09)
- Index on level for filtering

**spom-config.ts:**
- `id` INT PK default 1
- `currentWeek` INT NOT NULL default 1 - must be 1-52
- `updatedAt` TIMESTAMP default now, onUpdateNow
- CHECK constraint: id = 1 (enforce single row)
- Note: CHECK syntax is `check('name', sql\`condition\`)`
