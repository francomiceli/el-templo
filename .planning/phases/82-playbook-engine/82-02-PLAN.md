1. `el-templo-bot/src/memory/playbook-state.ts` — Mirror the shape of `memory/session.ts` (same Pino logger, same `isRedisAvailable` guard, same silent-degrade pattern) but store a separate key namespace:

```ts
import pino from "pino";
import { redis, isRedisAvailable } from "../redis.js";
import type { PlaybookSessionState } from "../playbooks/types.js";

const log = pino({ name: "el-templo-bot:playbook-state" });

/** 6 hours, matches SESSION_TTL */
export const PLAYBOOK_STATE_TTL = 21_600;

const KEY_PREFIX = "wa:playbook:";

function key(phone: string): string { return `${KEY_PREFIX}${phone}`; }

export async function getPlaybookState(phone: string): Promise<PlaybookSessionState | null> { ... }
export async function setPlaybookState(phone: string, state: PlaybookSessionState): Promise<void> { ... }
export async function deletePlaybookState(phone: string): Promise<void> { ... }
```

Rules:

- Separate key prefix (`wa:playbook:`) — do NOT stuff playbook state inside the existing `wa:session:` value. Reason: the session context is trimmed to the last 20 messages and rewritten on every turn; playbook state should not ride that write cycle.
- Use `redis.set(key, JSON.stringify(state), "EX", PLAYBOOK_STATE_TTL)` — exact same TTL as SESSION_TTL so both expire together. Use the `PLAYBOOK_STATE_TTL` constant (not the literal) so grep checks are readable.
- All error paths: log with Pino (no `console.*`), return `null` or no-op. Do NOT throw to the handler — engine degradation must be silent (bot must keep working even if Redis is down).
- `catch (err: unknown)` with `instanceof Error` narrowing (project standard).
