<objective>
Extend the 5 per-subscription / funnel analytics endpoints (ticket, churn, renewal, ltv, trial-funnel) so the admin panel can filter by plan as an INPUT param (D-10), and the trial-funnel additionally by turno (mañana/tarde, D-10). This is what lets "plan" and "turno" act as global panel filters and what makes the turno×sucursal funnel cross work via filter+breakdown (D-11) with zero 2D-aggregation code.

Purpose: The 6 frontend metrics need plan/turno to be real input filters; today the endpoints only accept from/to, branchId, country (+window). The plan join already exists in every breakdown — this plan threads planId/turno end-to-end the same way `/retention` already threads planId.
Output: 5 services accept planId (turno on trial-funnel), routes/schemas widened, integration tests proving filtering + scope isolation.

NOTE: frequency-service is handled in plan 132-02 (it gets BOTH turno input AND the D-12 name/phone enrichment). This plan does NOT touch frequency-service.
</objective>
