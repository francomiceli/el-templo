<objective>
Make Mica's tone genuinely adapt to the detected avatar (4 distinct voices) AND skip already-answered discovery questions when a returning lead has a profile in Redis. This is the user-facing payoff of phase 83's profile detection and phase 84's enriched playbook prompts.

Purpose: Closes AVAT-01 (per-avatar tone), AVAT-02 (skip already-answered), AVAT-05 (tone keyword tests). The phase 83 detection + 6h Redis TTL pipeline already feeds `currentAvatar` into `getSystemPrompt` — today that only injects a 1-line "Perfil detectado" stub. This plan replaces the stub with real per-avatar tone guidance, AND wires the resolver-level skip so a returning lead in the same 6h window goes straight to the recommendation stage instead of being asked questions Mica already knows the answer to.

Output: AVATAR_TONE_GUIDES const in system-prompt.ts (4 distinct Spanish tone blocks), resolver-level skip rule (lead + known avatar + no in-flight session → PB1.E4), new test file `avatar-tone-guide.test.ts` covering all 4 avatars + the skip rule.
</objective>
